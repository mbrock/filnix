Fil‑C NixOS: a memory‑safe NixOS and finix

filnix builds Nixpkgs packages with Fil-C, so a memory error in them stops the program instead of corrupting its memory. Its NixOS is a whole system built that way: pkgs is the Fil-C package set, so systemd, PAM, D-Bus, OpenSSH and every service you enable are Fil-C builds, from the same Nixpkgs sources and NixOS modules you already know. Only the kernel, the bootloader and a short, written-down list of exceptions stay native, and the machine checks that.

The whole system

A process is either all Fil-C or all native. A Fil-C program can't load a native library, and a native program can't load a Fil-C one. So rather than swap programs one at a time, filnix swaps the package set: NixOS modules take their programs from pkgs, and pkgs is Fil-C. The exceptions are whole packages from a native Nixpkgs.

Fil-Cnative

One module

One small module does it for both systems: lib/filc-system.nix, exported as nixosModules.default and finixModules.default through two thin wrappers. It has no per-service switches and no lists of names. The only knob is the exceptions, written as Nix values, so a typo fails evaluation:

# NixOS, with the NixOS modules of filnix's pinned Nixpkgs
nixosConfigurations.host = filnix.lib.nixosSystem {
  modules = [
    { filc.native = native: { inherit (native) tailscale; }; }
    ./configuration.nix
  ];
};

# finix
finixConfigurations.host = finix.lib.finixSystem {
  inherit (nixpkgs) lib;
  modules = [
    filnix.finixModules.default
    { filc.enable = true; filc.native = native: { inherit (native) tailscale; }; }
    ./configuration.nix
  ];
};
# nix.conf: substitute instead of compiling the Fil-C world
extra-substituters = https://filc.cachix.org
extra-trusted-public-keys = filc.cachix.org-1:8rA7kXyu1HaJuMTsAKfA9fU/+r8YtLv5KiZ5hfDNZMk=

If a service needs a fix to run as Fil-C, the fix goes in its port, where every system gets it. Every option is in the options reference.

What stays native

The built-in exceptions are data, lib/native-exceptions.nix, each with the systems that need it and why; the table in the NixOS notes is generated from it. In short: the kernel and the bootloader, Nix (whose Fil-C build can't sandbox), the static setuid wrappers, and the Rust tools that NixOS 26.05 boots and activates with. The module asserts that each exists in the native Nixpkgs, so a rename there fails evaluation instead of quietly building a Fil-C package.

Rust and Go have no Fil-C target, and nothing written in them gets in unnoticed. Evaluation stops, and says what to write instead:

error: Refusing to evaluate package 'ripgrep-15.1.0' … because it has problems:
- filc (kind "broken"): Rust has no Fil-C target. Take the native build instead, with filc.native = native: { inherit (native) ripgrep; }; in your system's configuration, or leave it out.

This only changes meta, so derivations hash the same as in the plain Fil-C set. Haskell and Zig aren't detected yet.

What it took

The systemd port is Nixpkgs' own 260.4, not upstream Fil-C's 256.4, because NixOS's modules expect 260. Getting it to run as PID 1 took plain posix_spawn instead of pidfd_spawn, ENOSYS from raw syscall wrappers so systemd's fallbacks run, no SIGBUS handler, and restoring the .note.dlopen notes the compiler drops, without which the initrd lacked libkmod and loaded no modules. Fil-C's glibc and runtime needed a reviewed batch of fixes too: directory walks, brk, settimeofday and a few other calls used raw syscall instructions, which Fil-C stops a program on rather than run machine code it hasn't checked, and the runtime refused the prctl calls that set a service's capabilities. On finix, keventd stopped on a real bug that Fil-C caught: it NUL-terminated what recv returned, so a uevent that filled its 1024-byte buffer wrote one byte past the end. The NixOS userland notes list it all, with what is still open.

Because PAM, its modules and every program that loads them are Fil-C together, a login gets a real PAM session, and sshd keeps PAM: no special cases for locked passwords or missing pam_limits.

And a trap is still a crash. Fil-C turns an out-of-bounds write or a use after free into a stopped process, so an attacker who can trigger one can still restart your daemon in a loop. They just can't take it over.

One Fil-C daemon on a stock NixOS

There is no module support for mixing, but a service's package option can still point at a Fil-C build:

services.tor.package = filnix.legacyPackages.x86_64-linux.pkgsFilc.tor;

That suits daemons that load nothing from the rest of the system. A Fil-C program can't load the native PAM or NSS modules, so it is not for sshd or anything that authenticates users, and nothing checks it for you.

Read the modules

The modules are short, and the wiki draws them as structure rather than text: lib/filc-system.nix, lib/native-exceptions.nix, the wrappers nixos/default.nix and finix/default.nix, and the options reference. The NixOS notes, the NixOS userland notes and the finix notes have the rest.

A research project. Fil-C stops memory corruption in C and C++; it doesn't help with logic bugs, misconfiguration or the kernel. A whole Fil-C system now boots on both NixOS and finix, but it is new: expect packages that still need porting. The build recipes are in mbrock/filnix.
