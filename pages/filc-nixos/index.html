Fil‑C NixOS: a memory‑safe flavor of NixOS and finix

filnix builds Nixpkgs packages with Fil-C, so a memory error in them stops the program instead of corrupting its memory. Its NixOS support lets you choose how much of a machine runs those builds: a few daemons, then the shell and the tools, then the whole userland. Each step uses the same Nixpkgs sources and NixOS modules you already have, Nixpkgs' own tests check it, and the machine can tell you which of its programs are Fil-C.

One scale, four steps

A process is either all Fil-C or all native. A Fil-C program can't load a native library, and a native program can't load a Fil-C one. So the unit of choice is a whole program, and a system moves along this scale one program at a time. Pick a step to see what changes:

Fil-Cnative
Steps 1 and 2 add Fil-C programs to a native NixOS. At step 3 everything starts as Fil-C and you list what stays native.

Steps 1 and 2 are one module, nixosModules.filc (nixos/filc.nix), on your own NixOS. pkgs stays your Nixpkgs, and the Fil-C packages come from filnix's pinned Nixpkgs and its binary cache, so most of a rebuild is downloads. Step 3 is a second pair of modules with the same options: nixosModules.filc-userland (nixos/userland.nix) on NixOS, and finixModules.filc-userland (finix/userland.nix) on finix. Every option is in the options reference.

# flake.nix
inputs.filnix.url = "github:mbrock/filnix";

nixosConfigurations.host = nixpkgs.lib.nixosSystem {
  system = "x86_64-linux";
  modules = [ filnix.nixosModules.filc ./configuration.nix ];
};
# nix.conf: skip most of the build
extra-substituters = https://filc.cachix.org
extra-trusted-public-keys = filc.cachix.org-1:8rA7kXyu1HaJuMTsAKfA9fU/+r8YtLv5KiZ5hfDNZMk=

Step 1: services

A switch sets one service's package option to the Fil-C build. Enable the service as usual: the switch only chooses the package. It sets the package at normal priority, so if your configuration also sets it, you get a conflict, not a silent choice.

SwitchSets
filc.openssh.enableservices.openssh.package, with UsePAM = false
filc.tor.enable, filc.unbound.enable, filc.lighttpd.enable, filc.redis.enablethat service's package
filc.bind.enableservices.bind.package: see Fil-BIND
filc.phpfpm.enableservices.phpfpm.phpPackage, and the PHP of MediaWiki, DokuWiki and Nextcloud: see PHP on Fil-C

The switches are the services filnix tests on every change, not the only ones you can use. Any NixOS service with a package option can run a Fil-C build. Set the option yourself, and list the unit in filc.units so it gets checked:

{ config, ... }: {
  services.mosquitto.enable = true;
  services.mosquitto.package = config.filc.packages.mosquitto;
  filc.units = [ "mosquitto" ];
}

Whether a package builds with Fil-C and passes its own tests is on the campaign dashboard.

Tested with Nixpkgs' own tests. The VM tests (tests/nixos) take Nixpkgs' test of each service, unchanged, and add the module to every node. Then, after the test's own script passes, they check that every unit in filc.units that is still running maps the Fil-C runtime, libpizlo.so, into its memory. A test therefore can't pass on a native build by accident. The log ends with a table of what it found. These are from today's runs of Nixpkgs' lighttpd and mosquitto tests on swa (store hashes shortened here). Mosquitto has no switch; it is the general pattern above:

Getting there found two things worth knowing. Fil-C Tor stopped in every ntor v3 handshake: its constant-time key lookup picks between two pointers by masking their integer values, and an integer made that way has no capability, so the first read through it trapped and the relays never bootstrapped. Its port now puts both pointers in a two-element array and indexes it with the comparison's 0 or 1, which keeps the capability and still takes the same time whichever key matches. And without PAM, sshd treats every account whose password starts with ! as locked, which NixOS sets for every user without a password, so key-only users couldn't log in. The switch's sshd leaves that check out, as NixOS's own sshd does by using PAM.

Step 2: the shell and the tools

filc.enable = true turns on every switch. It also makes Bash the login shell of root and normal users (filc.shell), and uses the Fil-C Nix for the daemon and the CLI (filc.nix). filc.tools puts Fil-C programs on PATH, ahead of native programs with the same name. Any switch can be turned off again.

The demo machine, nixosConfigurations.filc-demo (nixos/demo.nix), is this step: the Fil-C sshd, Unbound, lighttpd and Bash, and nineteen tools from coreutils to Python. It ships filc-status, which lists each unit in filc.units with the program it runs, then the login shell, Nix and each tool. The Nix daemon starts on its socket's first connection, and the test's builds run as root, which uses the store directly, so it shows -, "not running". The nix row is the Fil-C Nix that built a derivation in the same test. A unit counts as Fil-C if its running process maps libpizlo. A program counts as Fil-C if its ELF headers name the Fil-C loader as its interpreter or libpizlo as a needed library, the same rule the finix audit applies to a whole closure. A normal user can't read the memory maps of root's services, so for demo the three daemons come out as ?, which means "run as root to check", not "native":

Step 3: the whole userland

At step 3, pkgs itself is the Fil-C package set. NixOS modules take their packages from pkgs, so init, the shell, OpenSSH, sudo, PAM, D-Bus, Python and the rest become Fil-C without an override each. The options switch from "what becomes Fil-C" to "what stays native".

There is a module for each: nixosModules.filc-userland (nixos/userland.nix) for NixOS, and finixModules.filc-userland for finix, a small NixOS-like distribution with finit as init and no systemd. Both take the same filc.userland options. Both machines boot to a login and pass their VM tests. That took a batch of fixes to Fil-C's glibc and runtime: directory walks, brk, settimeofday and a few other calls used raw syscall instructions, which Fil-C stops a program on rather than run machine code it hasn't checked, and the runtime refused the prctl calls that set a service's capabilities.

# NixOS
nixosConfigurations.host = nixpkgs.lib.nixosSystem {
  system = "x86_64-linux";
  modules = [
    filnix.nixosModules.filc-userland
    { filc.userland.enable = true;
      filc.userland.native = [ "tailscale" ]; }
    ./configuration.nix
  ];
};

# finix
nixosConfigurations.host = finix.lib.finixSystem {
  inherit (nixpkgs) lib;
  modules = [
    filnix.finixModules.filc-userland
    { filc.userland = { enable = true; system = "x86_64-linux";
                        native = [ "tailscale" ]; }; }
    ./configuration.nix
  ];
};

What always stays native, and why:

PackageWhy
the kernel and its modulesFil-C can't build the kernel
grub2, kexec-tools (NixOS); limine, sbctl, efibootmgr (finix)the bootloader and its install hook run before any userland, and kexec loads freestanding code
pkgsStatic, glibcsetuid wrappers are static, and Fil-C doesn't link statically; glibc only for a header they use
nixunless nativeNix = false: the Fil-C Nix can't sandbox builds
nixos-init, makeInitrdNGTool, switch-to-configuration-ng, fish (NixOS); userborn (finix)Rust: NixOS 26.05 boots and activates with these, and finix creates users with userborn

Rust and Go have no Fil-C target, and nothing written in them gets in unnoticed: evaluation stops with

error: Refusing to evaluate package 'ripgrep-15.1.0' … because it has problems:
- filc (kind "broken"): Rust has no Fil-C target. Use the native build instead (filc.userland.native in finix), or leave it out.

and you add the package to native or leave it out. This only changes meta, so derivations hash the same as in the plain Fil-C set. Haskell and Zig aren't detected yet.

On the way there, finit's keventd stopped on a real bug that Fil-C caught: it NUL-terminates what recv returned, so a uevent that filled its 1024-byte buffer, which is common during coldplug, wrote one byte past the end. Its port now leaves room for the terminator.

The audit. A whole system has too many programs to list, so the test also audits the closure: finix/filc-audit.sh reads each ELF file's program headers and dynamic section, and classifies it by whether it uses the Fil-C loader and needs libpizlo. The 304 runtime files are libpizlo, the loader and the glibc beneath them: native code that only Fil-C programs load. The 486 native files are the exception list. They are almost all native Nix and its dependencies (that's where the native glibc, Bash and Boost come from), plus userborn and 13 static setuid wrappers.

Each line means the process maps libpizlo. PAM works again here: the programs that load PAM modules are Fil-C, like the modules, so a login gets a real PAM session, which a Fil-C sshd on a native NixOS gives up. The systemd port is Nixpkgs' own 260.4, not upstream Fil-C's 256.4, because NixOS's modules expect 260. Getting it to run as PID 1 took a list of changes, among them plain posix_spawn instead of pidfd_spawn, ENOSYS from raw syscall wrappers so systemd's fallbacks run, no SIGBUS handler, and restoring the .note.dlopen notes the compiler drops, without which the initrd lacked libkmod and loaded no modules. The NixOS userland notes list them all, with what is still open.

How you know it's Fil-C

Three checks, from cheap to thorough. Each looks at what the machine actually runs, not at what the configuration says:

CheckLooks atWhere
filc-statuseach listed unit's running process (does it map libpizlo?), the login shell, Nix and each tool on PATHinstalled by nixosModules.filc on any machine it changes
VM teststhe same check on every listed unit, after Nixpkgs' own test of the service passes; the test fails if any is nativenix build .#nixosTests.lighttpd, needs KVM
filc-auditevery ELF file in the system closure: Fil-C, runtime, kernel, or native and allowedfinix/filc-audit.sh

What it costs

WhereCostWhy
everywhere1.5–4× the CPU time of the native build, and more memorybounds checks and the garbage collector
sshd, steps 1 and 2no PAM: sshd checks passwords and keys itself, so a login gets no logind session (no XDG_RUNTIME_DIR) and no PAM module such as limits or two-factora Fil-C sshd can't load the native PAM modules
sshd without OpenSSLno Fil-C build (openssh.override { linkOpenssl = false; })the Fil-C OpenSSH patches do the ML-KEM key exchange through OpenSSL
Nixno build sandboxFil-C has no namespaces or seccomp
PHP-FPMeach worker grows to about 150–250 MB, so a pool needs several GBthe garbage collector keeps more memory alive
nginxno Fil-C build: use lighttpd, or a native nginx in frontnginx's processes share pointers through shared memory, which capabilities don't survive
updatessecurity fixes to Fil-C packages arrive when filnix updates its Nixpkgs pin, not with your channelthey are built and cached against that pin
step 3no Rust, Go, Haskell or Zig unless native; anything not yet ported needs building or an exceptionFil-C compiles C and C++ only
step 3 on NixOSno nscd, so names resolve from /etc files only (no nss-systemd or myhostname); dbus-daemon instead of dbus-broker; no QEMU guest agentthe Fil-C glibc has no nscd and nsncd is Rust; dbus-broker's Fil-C build fails its tests on real findings; the agent's dependencies don't build yet

And a trap is still a crash. Fil-C turns an out-of-bounds write or a use after free into a stopped process, so an attacker who can trigger one can still restart your daemon in a loop. They just can't take it over.

Read the modules

The modules are short, and the wiki draws them as structure rather than text: nixos/filc.nix with its table of services, nixos/userland.nix and finix/userland.nix with their exception lists, and the options reference for both. The NixOS notes, the NixOS userland notes and the finix notes have the rest: the example machines, how to run the VM tests without KVM, and how to add a service.

A research project. Fil-C stops memory corruption in C and C++; it doesn't help with logic bugs, misconfiguration or the kernel. Steps 1 and 2 are the practical ones today: a few internet-facing daemons on Fil-C, for 1.5–4× their CPU, with Nixpkgs' tests behind them. Step 3 now boots on both NixOS and finix, but it is new: expect packages that still need porting. The build recipes are in mbrock/filnix.
