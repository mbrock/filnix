mbrock/filnix

What is Filnix?

Filnix is an experimental repository for building Linux software with Fil-C, Filip Pizlo's memory-safe implementation of C and C++. It also holds nanofil, a small compiler for Fil-C, and a Rocq development that proves properties of nanofil's output and of real C programs.

Everything is in one repository, mbrock/filnix, and has three parts.

Nixpkgs and NixOS on Fil-C

A Nix overlay and stdenv compile ordinary C and C++ packages from Nixpkgs with Fil-C, including Fil-C's userland glibc, OpenSSH, PHP, BIND, SQLite and Lua. A NixOS module builds a whole bootable system the same way. In these programs an out-of-bounds access or a use after free stops the program with a Fil-C panic instead of corrupting memory.

  • Fil-C NixOS and finix describes the module, what stays native and what it costs.
  • Fil-BIND and PHP on Fil-C describe two ported servers and their performance.
  • The documentation covers installing the results, maintaining the toolchain, individual ports and the build campaigns.

nanofil

nanofil is a C compiler written in SWI-Prolog. It emits x86-64 code for the Fil-C runtime, and its objects link with those of filcc, the clang-based Fil-C compiler. nanofil writes each of Fil-C's capability checks as an explicit instruction in a small intermediate representation, so check elimination and register allocation can be inspected, tested and checked by a validator. Its back end is being rewritten in Rocq and extracted, and a second design compiles extracted Rocq programs themselves to Fil-C.

  • A guide to nanofil follows one C function through every stage of the compiler.
  • How Fil-C works explains capabilities, the garbage collector and safepoints, the parts of Fil-C that nanofil reproduces.
  • λANF on nanofil IR is the design for compiling extracted Rocq programs.
  • The playground runs nanofil in the browser and shows the IR and assembly it produces for C you type.

Proofs in Rocq

The Rocq development defines a small-step semantics for nanofil's IR, a validator proved sound (a module it accepts never makes an unchecked memory access), and an Iris separation logic over the same machine. It is used to prove that particular programs never panic. Small loops over arrays and heap buffers are proved outright. Programs that call libc are proved against a contract for each libc function, and Fil-C's own glibc functions, such as strlen and strcmp, are being proved to meet those contracts. The current target is GNU Hello.

  • The formal campaign states each claim and records what has been proved.
  • How Iris works introduces separation logic and Iris, and how nanofil's machine is an Iris language.
  • Contracts at the zsys_ boundary explores compiling Fil-C's glibc to nanofil IR, so that only the runtime's system-call entry points need trusted contracts.
  • Proving GNU Hello over userland glibc collects sixteen concrete surprises in glibc and Fil-C that turned up while verifying the real C library code.

This site

This site is built from the repository. It renders the documentation, the Nix, Prolog and Rocq sources (drawn from their syntax trees, with each name linked to its definition), and the explainers, which each describe one change or one system. The stream is a dated list of short entries in which mbrock and the Amp threads working in the repository record what they found and finished. Each document shows when it was written and last changed, taken from the git history.
