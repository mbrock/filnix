# Prolog hosts

nanofil runs on SWI-Prolog (the default, through `src/swi/`) and supports
Trealla for the IR backend. Full Trealla frontend/interpreter testing
remains paused. This file records the compatibility work and measurements.

## Trealla backend restored (November 2026)

The pinned native Trealla (`nix/trealla.nix`, revision `12f4cbd7`) runs
`optimize/3`, `pizlonate_module/2` and `filc_module_emit/3`. Run the CLI
from `nanofil/src`, with stdin closed:

```sh
NANOFIL_HOST=trealla TPL=/path/to/tpl ../bin/nanofil -O compile input.ir </dev/null
```

`tests/backend-hosts.sh` compares optimized IR, checked IR and assembly
in stack, temps and pointers modes on both hosts, plus plain and `-O`
CLI compilation. Its eight ABI fixtures cover floats, phi shadows,
local storage, variadics, setjmp, globals and copies. A forty-parameter
function exercises liveness masks beyond 64 bits: reverting the bitset
fix makes the comparison fail even when compilation succeeds. The small
parity step runs in the default Nix check; the full Trealla suite is
still opt-in and currently stops parsing a multiline test literal in
`tests/unit.pl` ("unterminated quoted atom").

### What worked, and what broke

The parent of the October 24 pause, [`8a5f5fa8`](https://github.com/mbrock/filnix/commit/8a5f5fa8),
still passes all 57 of its unit tests on the pinned Trealla when rerun.
The pause, [`d31875b3`](https://github.com/mbrock/filnix/commit/d31875b3),
was a decision to stop spending time on Trealla's memory and runtime
cost, not a known backend correctness failure. Later SWI-only development
introduced several independent incompatibilities:

- Register allocation (`bbc0f97f`, October 27) classified assembly labels
  with `atom_number/2`. On Trealla, a symbolic label throws through
  `number_codes/2` instead of failing. Test explicitly for decimal digits.
- Its wide liveness masks also exposed a pinned-host arithmetic defect:
  `(1<<64) /\ \1` evaluates to zero. Use the equivalent nonnegative
  set difference `xor(A, A /\ B)` instead of `A /\ \B` in both
  allocator and checker. No validation is disabled or weakened.
- Phi-shadow reuse (`04c7e7cb`, October 28) used missing `select/4`;
  replace it with indexed removal/insertion. Promotion (`2ce8b0f3`) and
  later slot/register selection used missing `partition/4`; share a
  portable, stable implementation.
- K&R parsing (`a2ee3145`) used DCG negation, and C23 booleans
  (`36039eb5`) used an if-then without a final else inside a DCG.
  Equivalent grammar rewrites let the CLI load. Trealla supplies
  `read_line_to_codes/2` itself, not through SWI's `library(readutil)`.
- Wide inlining (`c0f190b3`, November 5) used SWI's generative
  `arg(_, Term, Arg)`. Enumerate argument indices explicitly.
- Trealla considers `[]` an atom; serialize it before testing `atom/1`
  so printed IR agrees. On the nine-regex module, the branch-use scan
  via recursive `=../2` also produced malformed temporary-name lists
  and a duplicate-key exception. Indexed `arg/3` traversal avoids that
  failure; its underlying host defect has not been reduced further.

### Remaining cost

On the nine patterns (tag, email, word, alt, entity, shortcode, key,
date, lit) generated by `experiments/regex-nanofil/rx.pl`, CLI
`-O compile` produced byte-identical 8,233-line assembly on SWI and
Trealla. The frontend-free parity driver also matched optimized IR,
checked IR and all three emission modes (36,882 lines including the
wide-mask fixture). A separate driver isolates the stages below. These are
CPU seconds on an orb, SWI 9.2.9 versus pinned native Trealla, with
`optimize(o1(wide,full), ...)`, validation and
`filc_module_emit(..., emit(pointers,selected,inline), print_asm)`:

| Stage | SWI | Trealla |
| --- | ---: | ---: |
| read IR | 0.004 | 0.045 |
| validate input | 0.037 | 0.310 |
| optimize | 0.195 | 1.692 |
| pizlonate | 0.004 | 0.020 |
| validate checked IR | 0.043 | 0.395 |
| emit | 1.124 | 7.089 |
| whole process, wall seconds | 1.95 | 10.78 |
| peak RSS, MiB | 37 | 2,035 |

Emission, especially allocating registers, dominates absolute time.
With stack emission the emit stage takes 0.112/0.637 CPU seconds and
the whole process 0.83/4.24 wall seconds (SWI/Trealla); outputs still
match between hosts. This is an existing cheaper compilation mode, not
a substitute for testing the allocating modes. There is no measured
speedup from this compatibility repair, and no host/runtime tuning is
claimed. An embedded Trealla build and full frontend/interpreter
coverage are not established by these native-host measurements.

## Scryer Prolog: not worth supporting yet (October 2026)

Scryer 0.10.0 (nixpkgs `scryer-prolog`) ran a scratch copy of `src/` on
Lua 5.4.7's files. The output was identical to SWI's: `cc-ir` and `-O cc`
of `lvm.c` (76,757 lines of assembly) and `lapi.c`, and the
preprocessor's tokens of `lvm.c` matched `filcc -E`'s. It was slower and
larger everywhere:

| `lvm.c` | SWI 9.2.9 | Scryer 0.10.0 |
| --- | --- | --- |
| startup (empty file) | 0.3 s | 2.0–2.4 s |
| `tokens` of the `.i` | 0.8 s | 4.5 s |
| preprocess + `tokens` | 3.0 s, 314 MB | 12.5 s, 536 MB |
| `cc-ir` | 1.7 s, 133 MB | 7.6 s, 367 MB |
| `-O cc` | 3.5 s, 216 MB | 14.5 s, 737 MB |

Scryer's packed strings did not make the character-list preprocessor
cheaper: text it builds (spliced lines, spellings) is ordinary list
cells again. Scryer also compiles all of `src/` on every run.

Running there took, besides one real fix (an operator atom as an operand
must be bracketed, `Op == (=)`, not `Op == '='`; now in `c_lower.pl`):

- no `:- if/else/endif`: choose the non-SWI branches by script;
- argv from `os:argv/1`; `forall/2` from `library(iso_ext)`;
- missing: `msort/2`, `sort/4`, `atomic_list_concat/2,3`, `atom_number/2`,
  `is_list/1`, `include/3`, `exclude/3`, `foldl/6`, `last/2`,
  `max_list/2`, `min_list/2`, `numlist/3`, `subtract/3`;
- char lists, not atoms, for `format/2,3` and `format_//2` format
  strings (and no `format(atom(A), ...)`), `getenv/2`,
  `process_create/3`, and file names (`path_canonical/2`,
  `file_exists/1` stand in for `absolute_file_name/2`, `exists_file/1`);
- `write_canonical/1` prints lists as `'.'(H, T)`, so `tokens` output
  differs in form.

So "Trealla's dialect" also leans on Trealla's SWI-like extras. A
`src/scryer/` layer would be about 60 lines plus a `format` wrapper, but
at 4x SWI's time it buys only a strictness check. Revisit when Scryer
is faster or caches compiled code.

## SWI-Prolog: what the preprocessor's time was (October 2026)

Preprocessing Lua 5.4.7's `lvm.c` (65,628 tokens) took 3.2 s, against
0.06 s for `filcc -E`. Measured on SWI 9.2.9:

- Reading headers was 63% of it, and lvm.c reads 124 files 272 times
  (`bits/types.h` 19 times): guarded headers are included again and
  again. `read_source/2` now keeps each file's tokens for the run,
  3.2 s to 2.3 s.
- `punctuator/1` and `digraph/1` were `member/2` over a list, tried with
  every punctuation character; as facts they are indexed, 2.3 s to 2.1 s.
  All of Lua, preprocessing and lexing, went from 56.8 s to 35.6 s.
- What remains is flat: hide-set `memberchk`, macro lookups, and
  re-lexing each token (0.36 s).
- `swipl -O` gave nothing on `tokens` and 4% on `-O cc`. Turning GC off
  gave nothing and 4x the memory; the profiler's 12% in GC is not cost.
- Startup is 0.26 s, SWI compiling `src/` on every run, about 9 s of
  Lua's 35. A saved state (`swipl -o nanofil.state -c swi/compat.pl
  main.pl`, run with `swipl -x nanofil.state -- ARGS`) starts in 0.05 s
  with identical output, interpreter commands included. `bin/nanofil
  --save-state FILE` builds one and `NANOFIL_STATE=FILE` uses it; the
  Nix check and `nix/nanofil-cc.nix` (hello, zlib, Lua) do. A state does
  not rerun directives, so `swi/compat.pl` sets the UTF-8 streams again
  on restore (without that, stderr printed `\u00E9` for `é` under
  `LANG=C`).
- Not tried: skipping a re-included header whose guard macro is defined
  (clang's multiple-include optimization), and SWI strings instead of
  char lists, which would leave the shared dialect.
