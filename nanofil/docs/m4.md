# M4: C frontend

The plan and decisions are in [PLAN.md](../PLAN.md#m4-c-frontend-subset).
This file records what exists. M4a (lexer, parser, types), M4b
(lowering of functions), M4c (globals, string literals, function
pointers, libc calls, `main`), M4d (structs and unions as values), and M4e
(preprocessor) are done. M4f's pinned corpus and complete failure triage
are in [corpus.md](corpus.md).

```sh
cd nanofil/src
export FILCC=/path/to/filcc/bin/clang     # target profile and linking only
../bin/nanofil cc-ir prog.c            # the IR, as ir_text.pl clauses
../bin/nanofil cc prog.c > prog.s      # Fil-C assembly; .i still works
```

## Pipeline

```diagram
 C ──▶ c_pp ──▶ c_lex ──▶ c_parse ──▶ c_lower ──▶ IR (Fil-C module)
                     tokens     syntax      │  ▲
                                trees       ▼  │
                                          c_types
                                 specifiers, declarators, layouts,
                                 conversions, constant expressions
```

- [src/c_lex.pl](../src/c_lex.pl): tokens `tok(T, File:Line)`, following
  `# N "file"` markers, so errors point into the original source. GNU
  spellings fold into keywords (`__restrict__` is `restrict`). Integer
  constants keep their radix, because C types `4294967295` as `long` but
  `0xFFFFFFFF` as `unsigned int`.
- [src/c_parse.pl](../src/c_parse.pl): a C11 parser whose only state is
  the set of typedef names in scope, enough to tell declarations from
  expressions (a local `int node;` hides a typedef `node`). Declarator
  types are built outermost first around the atom `base`, so
  `int (*c)[5]` is `ptr(array(base, 5))`. Attributes after declarators are
  kept as `attr(Tokens)` specifiers; asm labels are kept as renames.
- [src/c_types.pl](../src/c_types.pl): type terms, SysV sizes and struct
  layout, integer promotions, the usual arithmetic conversions, and
  integer constant expressions (`sizeof`, `offsetof`, casts, enum
  constants). A type nanofil cannot handle yet is `bad(Reason)`, an error
  only when a declaration uses it, so whole glibc headers still parse.
- [src/c_lower.pl](../src/c_lower.pl): cproc-style lowering.

The real glibc headers from filcc's sysroot parse: stdio, stdlib, string,
stdint, ctype, limits, errno, unistd, signal, math, pthread, time,
sys/stat, dirent, wchar, inttypes, fcntl, sys/mman, getopt and setjmp.
`stdatomic.h` is rejected. Struct layouts were compared with clang's
`sizeof`, `_Alignof` and `offsetof` for `stat`, `tm`, `timespec`, `dirent`,
`pthread_mutex_t`, `pthread_attr_t`, `sigset_t`, `fpos_t`, `div_t` and
`ldiv_t`, and match.

## GNU hello frontend additions

`_Generic` parses an unevaluated controlling expression and an association
list. Selection applies lvalue/array/function conversion, but not integer
promotion; typedefs and compatible pointer/array/function types match,
and `default` is used only when no type matches. A scoped `qtype(Name)`
entry preserves qualification for reflection without changing ABI types.
Only the selected expression is lowered and it retains its value category.
Duplicate compatible associations, duplicate defaults, incomplete object
associations and missing matches are errors.

`sizeof` of an expression is available to integer constant evaluation as
well as function lowering. Array names already decay to relocation-bearing
address constants in static initializers. Block-scope static initializers
are now resolved while their local names (including enums and typedefs)
are still in scope, rather than after restoring the enclosing scope.

`__builtin_unreachable()` ends a block with `unreachable`.
`__builtin_alloca(n)` emits a bounded, 16-byte-aligned `alloc` at the call
site; see [the ABI findings](abi-findings.md#dynamic-alloca-and-unreachable).
GNU hello's same header expansions also need `__builtin_constant_p`, which
queries integer constant evaluation without evaluating its argument and
returns 0 when it cannot establish a constant.

## Preprocessor (M4e)

[src/c_pp.pl](../src/c_pp.pl) preprocesses the source and headers itself;
none of their contents is sent to clang. The DCG scanner retains token
spellings, preceding whitespace, original file/line and a macro hide set.
Only after replacement and rescanning does `c_lex` classify each spelling
into the parser's existing `tok(T, File:Line)` terms. `.i` input still goes
straight to `c_lex`, including its line-marker support.

- Object and function macros, empty arguments, variadic `__VA_ARGS__`
  (also GNU named variadics), argument prescan, `#`, `##`, placemarkers and
  rescanning. Hide sets prevent direct and indirect recursion, including
  when a replacement consumes a call from the remaining input. Arguments
  used only by `#` or `##` are not prescanned.
- Quoted includes search the including file's directory first; angle
  includes use the target search list. Literal header names are not macro
  expanded (`linux` is a predefined macro!), but macro operands are.
  `#include_next` and `__has_include_next` search after the current system
  directory. `__has_include` tests the same search path.
- Nested conditionals, `defined`, `#undef`, `#error` and ignored pragmas;
  `#pragma once` remembers a canonical file name, and nested
  `push_macro`/`pop_macro` save and restore definitions (including undefined
  macros). Integer conditions use
  64-bit intmax/uintmax conversions and exact integer division. `&&`, `||`
  and `?:` do not evaluate unselected arms.
- `__FILE__` and `__LINE__` refer to original sources. A parallel location
  vector survives line splicing, including splices inside tokens. Macro
  replacement tokens point to their invocation, not to the definition in
  a system header. Macro-expanded `#line` changes logical locations without
  changing the physical directory used for includes and `__has_include`.

**Target profile decision:** discover predefined macros with
`$FILCC -dM -E -x c /dev/null` and include directories with
`$FILCC -E -v -x c /dev/null` once per invocation (`FILCC` defaults to
`filcc`). Embedding either would duplicate the toolchain pin and bake Nix
store paths into Prolog. Clang's feature operators are absent from `-dM`:
the adapter batches glibc's `__has_attribute`, `__has_builtin`,
`__has_extension`, `__has_feature` and `__building_module` queries, and
queries other single feature names on demand. Only target-property probes
go through clang; nanofil performs all source preprocessing. Keeping this
profile discovery requires the selected Fil-C executable, which is also
needed for linking. No replacement headers or per-header output patches
are used. Header-driven additions were wide character constants in `#if`
(`bits/wchar.h`), the feature operators (`sys/cdefs.h`), and the next-include
operators in Clang's resource headers.

**Acceptance:** [tests/pptest.sh](../tests/pptest.sh), part of the Nix check,
compares location-free `c_lex` terms against `filcc -E` for each of the 20
headers listed above and every `.c` recursively under `tests/c` (including
rejections). Generated probes cover the macro rules, the C standard's
recursive rescanning example, once-only includes, integer conversions,
short-circuiting, `#error`, original-file/line assertions, spliced `#line`,
multiline comments in directives, and nested macro save/restore. `#line`
and macro save/restore also preserve M4f's existing passing cases
`c-testsuite/00152.c` and `c-testsuite/00206.c`. The existing
differential, whole-program and rejection scripts now compile `.c`
directly through nanofil. To prove the comparator detects a regression,
object macros were temporarily changed to expand to nothing: a
`#define VALUE 42` probe failed with `PREPROCESSOR MISMATCH` and a missing
`int(42,-(none,dec))` token (exit 1). Restoring expansion made the same
command pass (exit 0).

## Lowering

- **Locals.** Every local and parameter is an `alloc` in the entry block,
  and each use is a load or store, as in cproc before QBE's `promote`. An
  initializer zeroes the whole object first, because a hoisted alloc is
  reused across loop iterations. Initializer lists support designators
  and brace elision.
- **Narrow integers** are always held sign- or zero-extended to 32 bits in
  a `w` value. A conversion emits an `ext` only if some value of the source
  type does not fit the target (`int` to `unsigned char` does, `unsigned
  char` to `short` does not). `int` to `long` is `extsw`/`extuw`, and
  `long` to `int` needs no instruction, since a `w` use of an `l` value
  reads its low half. Narrow call results are re-extended, because
  nothing guarantees the callee did it.
- **Pointers** are `p`: `p + i` scales `i` to a `long` and adds it with
  `add` at `p`, which keeps the capability; differences and comparisons go
  through `ptoi`. A constant integer used as a pointer is a capability-free
  `p` constant, so `*(int *)0` traps.
- **`&&`, `||` and `?:`** produce phis. `?:` lowers each arm once against
  a throwaway copy of the lowering state to find the result type, then
  again with the conversion; `sizeof expr` uses the same trick.
- **`switch`** jumps to a dispatch block after the body, a chain of
  compares filled in once all `case` labels are known.

## Globals, literals, function pointers and libc (M4c)

The ABI facts are in [abi-findings.md](abi-findings.md#globals-getters-and-indirect-calls-for-m4c),
read from the runtime and pass at the pin.

**IR.** A Fil-C module may now have `data`. `item(p, sym(Sym, Off))` is
a pointer data item, and linkage `ro(Lk)` marks read-only data (in
`.rodata`). A symbol appears in code only as
`let(tmp(T), p, copy, [global(Sym)])`, which is a call to its getter, and
`call(Res, tmp(T), Args)` calls through a `p` value. A module
that calls a function it does not define is a Fil-C module.

**Interpreter.** Globals are 16-aligned objects with sizes rounded up to
8, as Fil-C lays them out; read-only data has capability `ro(Base)` and
traps on writes. Each function has an address with capability `fn(F)`, a
zero-size object, so loads through it trap. An indirect call traps
unless the pointer is exactly a function's; a call whose classes differ
from the callee's goes through the generic convention, so too few
arguments or using a void result traps, as the generic entry's size
checks do.

**Backend.**

- `DO_g`, `GP_g`, `DA_g` (only if the payload holds pointers), a
  relocation table, and a getter whose slow path is
  `filc_global_initialization_start`, `filc_execute_constant_relocations`,
  `filc_global_initialization_end`, with the flags clang uses (0x1, 0x11,
  0x3, 0x13). Pointer slots are 0 in the static data and filled in by the
  relocations; a pointer with an offset uses a constexpr node.
- `copy $s` sets the frame's call-site origin and calls the getter, so a
  getter is a safepoint like any call.
- Every function now has a getter, generic entry and function object, so
  local functions can have their address taken.
- Indirect calls check for a function object (lower ≠ 0, ptr = its aux
  pointer, special type function, else `filc_check_function_call_fail`),
  then use the fast entry if the signature word matches and the generic
  entry otherwise, checking the returned size.
- Each external callee gets a hidden weak thunk `pizlonatedFI<sig>_f`, as
  clang emits: getter, function-object check, fast or generic entry. A
  clang definition in the same link wins. This is how libc is reached.
- `main` needs nothing special: the runtime calls `pizlonated_main`.

**Frontend.** Globals with constant initializers (integers, address
constants such as `&a[2]`, `"str"`, function names, `&s.f`, with
designators and brace elision), tentative definitions, `static` locals
(renamed `fn.name.N`), string literals as read-only `str.N` data,
function designators and pointers, and `__func__`. `static inline`
functions are lowered only when something refers to them, as clang does;
headers are full of ones nanofil cannot lower.

Non-static inline definitions follow C99: any file-scope declaration
with `extern` or without `inline`, even after the body, makes the body
an external definition. Otherwise it emits no definition. GNU
`gnu_inline`/`__gnu_inline__` attributes retain the GNU89 rule instead:
`extern inline` emits no definition, plain `inline` does. The attributes
are already retained by the parser in specifiers and declarator suffixes.
[tests/c/prog/extern-inline.c](../tests/c/prog/extern-inline.c) tests both
rules across translation units against clang, including declarations
before and after the body and the unchanged `static inline` behavior.

## Structs and unions as values (M4d)

The ABI facts are in [abi-findings.md](abi-findings.md#structs-as-values-for-m4d).

**IR.** One addition, a two-word result, for structs of 9 to 16 bytes:
`function {l, p} $f(...)`, `ret {%a, %b}` and `{%a, %b} ={l, p} call
...` (terms `tuple([K1, K2])`, `rets([V1, V2])` and `call(tuple([to(D1,
K1), to(D2, K2)]), ...)`). Each word is `l` or `p`. A tuple makes the
module a Fil-C module. Everything else a struct needs is lowered by the
frontend into existing IR: struct arguments are their words, one-word
structs return as `l` or `p`, and larger returns take an sret pointer as
the first argument.

**Interpreter.** `rets` gives the outcome `rets([X1, X2])` and a tuple
call binds both temporaries. The generic convention of indirect calls
now works word by word for results too: the call site may read fewer
words than the callee returns, not more.

**Backend.** Results with at most two slots (a `p` word is two) come
back in RDX:RCX; `{l, p}`, `{p, l}` and `{p, p}` use the caller's buffer,
with all registers shifted by one. Functions, direct and indirect calls,
generic entries and thunks all handle both forms. A buffered call keeps
its buffer on the native stack for the moment between the return and
copying the slots into the frame; there is no safepoint in between.

**Frontend.** A struct rvalue is the address of storage holding it (a
variable, or a temporary local for a call result), so `a = b`, `return
s`, `f(s)`, `c ? s1 : s2` and `f().x` need no struct temporaries in the
IR. Copies and conversions to words go an eightbyte at a time: `load(p)`
and `store(p, ...)` where a pointer starts, so capabilities copy exactly
(decision 6), else `load(l)`/`store(l, ...)`, with a short last eightbyte moved
in 4-, 2- and 1-byte pieces (`struct {char a, b, c}` is a halfword and a
byte). A struct expression initializes a struct member or array element
whole rather than by brace elision. Struct arguments over 16 bytes (and
misaligned packed ones) are byval: passed as their eightbytes, and a
function taking one is generic-only, promoting its argument packet to
the heap as a variadic function does (decision 7, abi-findings.md
*Byval arguments*). Such a struct's float members do not matter, since
it never travels in SSE registers. Smaller structs with float members
travel in SSE eightbytes as SysV classifies them (abi-findings.md,
*Structs with float members*), and `va_arg` of a struct or union reads
it a cell per eightbyte.
[tests/c/prog/fstructs.c](../tests/c/prog/fstructs.c) checks them and
clang's signatures across the boundary.
[tests/c/prog/byval.c](../tests/c/prog/byval.c) passes them across the
clang boundary both ways, directly, indirectly, past a prototype's
`...` and through wrong prototypes, and traps through a pointer field
that made the round trip.

**Initializers.** An array of unknown size counts the entries each
element takes with brace elision (`struct {int a, b;} s[] = {1, 2, 3,
4}` has 2 elements, not 4), and an elided aggregate stops at the next
designator, which belongs to the enclosing list. Both were found by the
M4f corpus (c-testsuite `00205`).

## Bit-fields

A bit-field is a member `m(some(F), Type, Off, bits(Pos, W))`: W bits
from bit Pos of the Type-sized storage unit at byte Off. Layout follows
the SysV psABI (and clang): a bit-field takes the next bits unless it
would cross a boundary of its type's size, where it starts instead; a
zero-width one moves to that boundary; an unnamed one takes space but
does not align the struct, and a named one aligns it as its type. The
unit is aligned to its own size inside a struct aligned at least as
much, so every unit access stays inside the object, and a unit never
shares an eightbyte with a pointer, so the Fil-C capabilities are
untouched.

The elaborator marks a bit-field lvalue `obj(T, bitfield(member(XS, F),
W))`. Its value has the promoted type of `bitfield_promotion/3`: int
when an int holds every value, else unsigned int when that does, else
its own type (C11 6.3.1.1p2, and clang's rule for `long` bit-fields).
`&` and `sizeof` of a bit-field are refused. Lowering reads the unit
and shifts the field to the bottom, extended by the type's sign; a store
loads the unit, masks the field in and stores it back, and the value of
an assignment, `++` or `--` is the field read back from what was stored.
Static initializers merge each bit-field into the bytes it covers.
[tests/c/bitfields.c](../tests/c/bitfields.c) compares the interpreter,
nanofil and clang on layouts, signs, neighbours kept by stores,
promotion, assignment values, initializers, copies and struct arguments.
Packed bit-fields, which GCC places differently, are rejected.

## Packed structs and unions

GNU's `packed` attribute (`__attribute__((packed))` before the tag or
after the body, or `[[gnu::packed]]`) gives every member alignment 1,
and the struct too (`su_layout/5`). Non-pointer accesses already check
no alignment, so misaligned members load and store like any other;
copies and static initializers are bytewise as before. nanofil refuses
a packed pointer (Fil-C keeps a capability only at an 8-aligned
address) unless the struct is also aligned to 8 and the pointer is at a
multiple of 8 in it (parted's `packed, aligned(8)` GPTDiskData). A
packed enum has the smallest integer type that holds its constants,
unsigned unless one is negative, as GCC and clang give it (svt-av1,
libepoxy, elfutils).
A packed bit-field follows the bits before it across any boundary, as
in GCC and clang (parted's GPT attributes); one that no access of its
type within the struct covers is refused. `#pragma pack(N)`, with
push and pop, caps member alignment at N for the definitions after it
(tpm2-tss's command headers): c_lex marks each struct or union keyword
under it with an internal attribute, so `.c` and preprocessed `.i`
input agree; a pointer, bit-field or explicitly aligned member it
would underalign is refused, as is a named push or pop. Until this,
nanofil ignored the pragma. A struct with a misaligned member, perhaps
nested, has SysV class MEMORY (`unaligned_type/2`): it is returned
through a hidden pointer as clang does, and passed by value byval. `aligned` stays unsupported.
[tests/c/packed.c](../tests/c/packed.c) compares layouts and accesses
three ways; [tests/c/prog/packed.c](../tests/c/prog/packed.c) returns a
misaligned packed struct across the clang boundary in both directions.

## Small C99 and GNU additions

GNU statement expressions `({ ... })` open a block scope and yield the
last expression statement's value (including a labelled expression), or
void otherwise. Nested expressions, shadowing and header macros such as
glibc's `assert` work. Labels remain function-scoped: gotos may stay within
or leave an expression, but entering one (also from a sibling expression)
is rejected, as is switch dispatch from outside to a case/default inside.
Computed gotos are described under "Linux userland additions" below.
Break/continue retain the enclosing
statement context; in loop conditions/init/increment they target an outer
loop, as GCC documents, not the loop being constructed. The pinned clang
differs for condition-expression break/continue, so those cases must be
checked against GCC instead. Evaluation is not interleaved with sibling
operands. [tests/c/stmtexpr.c](../tests/c/stmtexpr.c) compares values, void,
nesting, scope, assert, labels and outward jumps against clang.

Compound literals (a block-scope one is an unnamed local initialized
where it appears; a file-scope one is unnamed static data), wide
character and string literals (`L` is `int`, `u` is `unsigned short`, `U`
is `unsigned int`; elements are code points), `u8` strings, GNU `c ?: b`
with `c` evaluated once, and `__builtin_expect`. In initializers: GNU
range designators `[a ... b] = v`, each element initialized as if
designated alone (so `v` may not have side effects, which GCC would
evaluate once); a designator naming a member of an anonymous member
(C11 6.7.2.1p13); and GNU constant compound literals of the slot's own
struct type in static initializers, read as their initializer lists.
[tests/c/c99.c](../tests/c/c99.c) covers them three ways.

## SQLite additions

SQLite 3.51.2's amalgamation and shell (`SQLITE_THREADSAFE=0`,
`SQLITE_OMIT_LOAD_EXTENSION`, FTS5 and the math functions) build with
nanofil alone; [nix/sqlite.nix](../nix/sqlite.nix) compares them with a
filcc build. They needed:

- **Integer address constants.** An integer constant cast to a pointer
  is an address constant in a static initializer (C11 6.6p9), as in
  SQLite's `SQLITE_INT_TO_PTR(1)`. It becomes an address with no
  capability, as clang emits it, and 0 the null pointer. Dereferencing
  one traps in both builds.
- **`__builtin_nan("")`, `__builtin_nanf("")`** (glibc's `NAN`) are
  constants: the quiet NaN with a zero payload. A non-empty payload
  string is refused.
- **`__builtin_ceil`, `__builtin_floor`** call libm's `ceil` and
  `floor`, which compute the same exact result as clang's inline
  `roundsd`.
- **Large translation units.** sqlite3.c is 260,000 lines. The pipeline
  commits to each statement, function, item and block, so finished work
  leaves no choicepoints that keep it alive. Frame-slot liveness shares
  the per-block live sets instead of copying a point per temporary, and
  the assembly prints one item at a time from atomic parts, not
  character lists. Whole-module lookups (a function by name, a
  function's provenance context, whether a callee is variadic) go
  through indexes built once per pass, never a scan of the items per
  use, and each full expression is elaborated once. The output is
  unchanged. With FTS5 the amalgamation compiles in about 65 s within
  SWI's default 1 GB stack, and with `-O` in about 3 minutes, also within
  it, since main.pl's `release_stacks/0` collects and trims SWI's stacks
  between stages (its limit counts allocated, not live, memory).
  `NANOFIL_STACK_LIMIT=BYTES` raises the limit, from source or a saved
  state, as a fallback. nanofil-cc (the package builds and the survey)
  compiles every file within the default 1 GB first, and only a compile
  that overflows it (`resource_error(stack)`) is compiled once more with
  `NANOFIL_STACK_LIMIT=4000000000`, saying so on stderr: gettext's 34 MB
  tree-sitter OCaml parser is about 11M tokens, a token list that alone
  fills 1 GB, and compiles in about 155 s at 7.9 GB RSS. So parallel
  builds meet the larger limit only where a file needs it.

  With the port's flags (nixpkgs' NIX_CFLAGS_COMPILE: FTS3 and FTS4,
  R-Tree, Geopoly, sessions, RBU) more of sqlite3.c is compiled. Without
  `-O`, as the survey builds it, it fits since release_stacks also runs
  between the frontend and the validator (nanofil-sqlite's `port`
  configuration, 90 s). With `-O` it is at the limit, a known limit:
  one run passed in 259 s, another overflowed, and `-O --checks=reuse`
  overflowed in copy and provenance. Live global stack after a
  collection, by stage: tokens 71 MB, parse 100 MB, c_module 320 MB,
  valid_module 220 MB, optimize 364 MB, pizlonation 484 MB, and emission
  holds the whole pizlonated module. Fitting it would need per-function
  pizlonation and emission (M7's area); the plain, O and reuse
  configurations keep the check's smaller flag set.

  SWI collects the global stack only once it holds three times what the
  last collection left (`set_prolog_stack/2`'s factor), and grows it
  otherwise; at the limit it raises an overflow without collecting.
  sqlite-interactive's sqlite3 (the port's flags and the shell's, a
  4.2 MB `.i`) then needed between 800 and 950 MB, and overflowed in
  the survey's busier builds, which collect at other moments. swi/compat.pl
  sets the factor to 2: it fits between 650 and 800 MB, in the same
  84 s. gtk3's and gtk4's 11 MB resource blobs, 256 MB live while
  lexing, needed more than 850 MB and now fit in 750 MB.

[tests/c/prog/sqlite-idioms.c](../tests/c/prog/sqlite-idioms.c) and
[tests/c/prog/gnu-math.c](../tests/c/prog/gnu-math.c) compare these with
clang.

### Atomic builtins

`__atomic_load_n(P, Order)` and `__atomic_store_n(P, V, Order)` take a
pointer to an integer or a pointer and a constant `Order`: relaxed,
consume, acquire or seq_cst for a load, and relaxed, release or seq_cst
for a store. Other orders and the other `__atomic` builtins are refused
with a message.

- **Integers.** A load is `*P` and a relaxed or release store is
  `(void)(*P = V)`: on x86-64 an aligned integer access is already
  atomic, and none of those orders needs a fence. A seq_cst store is the
  store, then IR `fence` (`mfence`). Clang emits `xchg`; both are
  trailing-fence seq_cst stores, so they combine with each other and
  with plain-`mov` seq_cst loads.
- **Pointers**, at every order, use IR `atomic_load(p)` and
  `atomic_store(p, V, A)`. Pizlonation gives them the ordinary inline
  check and the effect lists `[atomic_read]` and `[atomic_write]`, which
  call Fil-C's helpers as clang does: `filc_load_ptr_atomic_with_manual_tracking_outline`
  and `filc_store_ptr_atomic_outline` ([abi-findings.md](abi-findings.md#pointer-atomics)).
  They keep the address and capability one unit (an atomic box in the
  slot's aux) and are sequentially consistent. Escape analysis makes an
  atomically accessed object escape, so it stays a heap object; stack
  aux has no boxes. The interpreter, single-threaded, treats them as
  plain pointer accesses and `fence` as nothing.

[tests/c/prog/atomic-ptr.c](../tests/c/prog/atomic-ptr.c) runs a writer
and a reader thread on one slot, nanofil against clang in each direction,
with two objects of different sizes: a torn pair traps. It also runs a
store-buffer litmus of nanofil's seq_cst store against clang's.

## Linux userland additions

GNU sed 4.10, jq 1.8.2 (with its bundled oniguruma and decNumber) and
dash 0.5.13.3 build with nanofil alone, each with filnix's port patch;
[nix/sed.nix](../nix/sed.nix), [nix/jq.nix](../nix/jq.nix) and
[nix/dash.nix](../nix/dash.nix) compare them with filcc builds on
workloads in [nix/workloads](../nix/workloads) and run their test suites.
They needed:

- **C23 keywords.** configure gives sed `-std=gnu23`, and gnulib's
  headers then spell `bool`, `true`, `false`, `nullptr`,
  `static_assert`, `alignas`, `alignof` and `thread_local` as keywords.
  nanofil-cc sets `NANOFIL_STD=c23` for `-std=c23`, `gnu23`, `c2x` or
  `gnu2x`, and c_lex's `c23_tokens/2` then reads those spellings as
  keywords; C17 stays the default. `true` and `false` are `(bool)1` and
  `(bool)0`; `nullptr` is `(void *)0`, so `nullptr_t` is `void *` (only
  `_Generic` tells them apart). progtest's `// cflags:` line builds a
  test with such flags.
- **`_FORTIFY_SOURCE`.** gnulib's config.h turns it on when optimizing,
  and glibc's headers then call `__builtin_object_size` and the
  `__builtin___*_chk` builtins. nanofil answers that an object's size is
  unknown (`(size_t)-1` for types 0 and 1, 0 for 2 and 3), which GCC
  documents as correct for any pointer. A `__builtin___X_chk` call is a
  call of the library's `__X_chk` when it is declared (glibc's printf
  family), else of `X` when the size is `(size_t)-1`. Clang computes
  real sizes, so `__builtin_object_size` can answer differently; Fil-C
  checks every access either way.
- **clang's `overloadable`.** glibc's fortify headers overload `open`,
  `open64` and `openat` by arity. A declaration or definition marked
  overloadable whose type is not compatible with the visible one is
  skipped, and calls reach the original function; glibc's overloads only
  check the flags before calling it.
- **Alignment requests that change nothing.** An `_Alignas` or
  `aligned(N)` no stronger than the member's own alignment is dropped
  (C11 6.7.5p4), as in glibc's and clang's `max_align_t`. A stronger one
  is still refused, except on a struct or union definition (*xz
  additions* below).
- **`transparent_union`.** glibc's socket functions take
  `__SOCKADDR_ARG` under `_GNU_SOURCE`. A parameter of a transparent
  union whose members are all pointers has its first member's type, so
  any member's pointer passes, as GCC passes it.
- **`cleanup`.** GLib's `g_autoptr`, `g_autofree` and `g_auto`, and
  systemd's `_cleanup_`, attach `cleanup(F)` to an automatic variable
  v: `F(&v)` runs on every way out of v's scope (the end of its block,
  `return` after its value is taken, `break`, `continue`, `goto`), in
  reverse order of declaration. A jump into such a scope and F of the
  wrong type are refused as clang refuses them; so is a `goto *` inside
  one, which clang compiles.
  On a variable that is not automatic it is ignored, as clang ignores it
  with a warning. One difference remains: a function that returns a
  struct copies it before the cleanups run, where clang, returning a
  named local in place, lets the cleanup change the returned value
  (docs/abi-findings.md, *Cleanup and a returned struct*).
  Before this was supported, nanofil ignored the attribute, and dconf's
  leak tests leaked a GDBusConnection reference.
- **Labels as values.** `&&L` is `(void *)N`, N the label's number in
  its function, an address constant with no capability (so static
  tables of labels work). Every `goto *E` of a function stores E and
  jumps to one dispatch block, a search among the function's
  address-taken labels; any other value reaches `unreachable`, a Fil-C
  panic. oniguruma's bytecode interpreter dispatches so. A label value
  is meaningful only in its own function.
- **The `alias` attribute** (dash's `bgcmd`; fontconfig's, gettext's and
  gtk2's object aliases) binds the name to the target's symbol. An
  external or weak alias is also the IR item `alias(Name, Linkage,
  Target)`, which filc_amd64 emits as filcc does: a getter
  `pizlonated_<Name>` that calls the target's getter, so another
  translation unit reaches the target's function or data object, at the
  target's address. The validator requires the target to be a function
  or object the module defines, and a data alias never to be called.
  Functions of any type (variadic and unprototyped included) and
  objects alike; a function alias of an object, an alias of
  thread-local data and several declarators are refused.
- **Source bytes.** Files are read as bytes. A narrow string keeps the
  bytes as written, valid UTF-8 or not (oniguruma's tests are EUC-JP),
  and a wide string decodes UTF-8, as clang does. c_pp keeps `u8"..."`
  one preprocessing token.
- **Smaller pieces.** `typeof` (C23 6.7.2.5) of an expression or a type,
  not of a variably modified type; the empty compiler barrier
  `asm volatile("" ::: "memory")`, which emits nothing; GNU `void *`
  arithmetic (steps of 1); `sizeof` and `_Alignof` of a type name that
  defines a tag; `sizeof (T[]){...}`; static assertions among struct
  members (C11 6.7.10, gnulib's `verify_expr`); `__builtin_isnan`,
  `__builtin_flt_rounds`, the classification builtins of glibc's
  math.h (`isinf_sign`, `isfinite`, `isnormal`, `signbit`, `signbitf`,
  `signbitl`, `fpclassify`) and long double `huge_vall`, `infl` and
  `nanl`.
- **Thread-local variables.** jq's libjq keeps three `static __thread`
  objects. `_Thread_local`, C23 `thread_local` and `__thread` with
  `static`, `extern` or at file scope give the object thread storage
  duration (C11 6.2.4p4): its data has linkage `tls(L)` (ir.pl), and
  filc_amd64 emits clang's per-thread getter and slow path
  ([abi-findings.md](abi-findings.md#thread-local-variables)). Refused,
  as clang refuses them: a block-scope thread-local that is neither
  `static` nor `extern` and a thread-local function (6.7.1p3-4), and
  `&x` of one in a static initializer (6.6p9).
  [tests/c/prog/thread-local.c](../tests/c/prog/thread-local.c) runs
  eight threads against clang's side; before this, the storage class
  was dropped and every thread shared one object (a block-scope one
  even became automatic).
- **Nested `?:` cost.** A conditional checks whether an arm is a null
  pointer constant only when the other arm is a pointer; folding every
  arm refolded each subexpression once per enclosing `?:` (gnulib's
  intprops tests went from minutes to seconds in the frontend).

Refused, with a message: inline asm other than the empty barrier
(gnulib's x87 control-word tests); a stronger alignment request; a
pointer converted to `bool` in a static initializer (`bool b = &s;`, a
GNU extension); classifying a long double other than by its sign. dash's
`vfork` is `fork`, as filnix's port has it, since a vforked child would
share the collector's heap. gnulib's test-intprops.c, whose `main` has
87,000 blocks (constant conditions are still lowered as branches),
compiles with `-O` in about 150 s within the default 1 GB stack: CFG
liveness found unreachable blocks quadratically until 3d3d251, and
main.pl's `release_stacks/0` now returns SWI's grown stacks between
stages, since its stack limit counts allocated, not live, memory.

## xz additions

xz-utils 5.8.4 builds with nanofil alone, with the C changes of
filnix's port patch; [nix/xz.nix](../nix/xz.nix) compares it with a
filcc build on [nix/workloads/xz.sh](../nix/workloads/xz.sh), which
runs liblzma's threaded encoder and decoder at 1 to 8 threads, and runs
xz's test suite. It needed:

- **`aligned(N)` on a struct or union definition** (xz's `io_buf`):
  the alignment is the larger of N and the members', the size rounds up
  to it, packed or not; bare `aligned` is 16, clang's
  `__BIGGEST_ALIGNMENT__` (c_types `definition_alignment/3`). nanofil's
  globals and allocations are 16-aligned, so N above 16 is refused, as
  are `aligned` on a typedef, an object or a member, and `_Alignas`
  stronger than natural.
- **Eightbytes with no data.** A struct of at most 16 bytes passes only
  the eightbytes that hold a member (SysV NO_CLASS,
  [abi-findings.md](abi-findings.md#eightbytes-without-data)).
- **Header intrinsics that are never called.** xz includes
  `<immintrin.h>`, which declares vector types, `_Float16` and `__bf16`
  vectors, and inline functions with asm bodies. Inline asm other than
  the empty barrier parses as `unsupported_asm` and is refused where a
  function containing it is lowered, so an unused `static inline` one is
  never refused, as clang never emits it. `vector_size` (and clang's
  `ext_vector_type`) makes a bad type, refused where it is used; it was
  silently ignored before, which gave a vector the size of its element.
  `_Float16` and `__bf16` are refused types. A `static` function that
  nanofil cannot lower is deferred as a `static inline` one is, and its
  error is raised only if something refers to it
  (amxcomplexintrin.h's `__tile_cmmimfp16ps` takes a struct with a
  vector member by value); clang emits an unreferenced static function
  not at all, and the output of every function that lowers is
  unchanged.
- **`__builtin_bit_cast(T, E)`**, of two complete object types of one
  size, T not an array: E's value is stored and loaded as T, so a
  pointer's bytes keep its address and lose its capability, as through
  memcpy (c_types `bit_castable/3`). **`__builtin_assume_aligned(p, a[,
  o])`** is p as a `void *`.
- **Constructors and destructors.** `__attribute__((constructor))` and
  `destructor`, with an optional priority from 0 to 65535, were
  ignored, so the functions never ran (xz sets its CRC function
  pointers in one when its CLMUL CRC is built, which the check
  configures out; no xz object has one). Each is now data of linkage
  `init(ctor|dtor, Priority)` holding the function (ir.pl), which
  filc_amd64 emits as clang's Fil-C does
  ([abi-findings.md](abi-findings.md#constructors-and-destructors)). The
  entry refers to the function, so a deferred static one is lowered; a
  constructor not defined in the translation unit is refused.
- **Weak thunks are per signature, not per call site**
  ([abi-findings.md](abi-findings.md#weak-thunks-are-shared-by-signature)).

Refused, and configured out of both builds: vector types and the SIMD
intrinsics, which xz uses for its CLMUL CRC (`--disable-clmul-crc`)
and its LZ decoder's SSE2 copy (`LZMA_LZ_DECODER_CONFIG=1`, the memcpy
variant, which lz_decoder.h lets the build choose).

## coreutils additions

GNU coreutils 9.11 (107 programs, gnulib at scale) needed three changes:

- **Asm with a memory operand.** gnulib's fpucw.h reads and sets the
  x87 control word with `fnstcw %0` / `fldcw %0` on an `"m"` operand,
  under vasnprintf's long double formats (seq, printf). clang's Fil-C
  compiles such an asm to a run-time safety error, which a program
  reaches only if it runs it; nanofil now does the same (a call of
  `zsafety_error` with clang's message), instead of refusing the
  function at compile time
  ([abi-findings.md](abi-findings.md#inline-asm)). Any other asm is
  still refused. [asm-memory.c](../tests/c/prog/asm-memory.c).
- **Attributes on a label** (gnulib's `_GL_UNUSED_LABEL`,
  `fail: __attribute__((__unused__));`) are ignored, as GCC and clang
  do. [userland-idioms.c](../tests/c/prog/userland-idioms.c).
- **No `__SIZEOF_INT128__`.** nanofil refuses `__int128`, so its
  preprocessor profile, and nanofil-cc's clang preprocessing, no longer
  define the macro clang advertises it with: factor.c's `umul_ppmm`
  takes its portable path. [int128-portable.c](../tests/c/prog/int128-portable.c).

Refused, and configured out of both builds: vector types (the AVX2,
AVX-512 and PCLMUL paths of wc and cksum), `_Float16` and `__bf16` (od),
and factor's longlong.h asm (`USE_LONGLONG_H=0`). Some commands stop
with a Fil-C safety error in both builds alike: seq and printf on
floating formats (the fpucw asm above), and `yes` into a pipe, which
reaches glibc's vmsplice syscall asm.

## CPython additions

CPython 3.12.5 with filnix's port (the version the port pins; nixpkgs'
3.13 is marked broken there), its interpreter, test modules and 62
extension modules, needed:

- **`_Atomic`** (pycore_atomic.h's `void *_Atomic` and `atomic_int`
  members, through `<stdatomic.h>`). `_Atomic(T)` and the `_Atomic`
  qualifier apply to an integer, a pointer, `float` or `double`, whose
  atomic version has T's size and alignment on x86-64; a struct, union
  or `long double` is refused (`atomic_object_type/1`). Reading an
  `_Atomic` object is a seq_cst atomic load and simple assignment a
  seq_cst atomic store, mapped as the builtins below are: a pointer
  through Fil-C's atomic helpers, anything else a plain load, or a store
  and then `mfence`. Initialization is not atomic (C11 7.17.2.1). A
  compound assignment or `++`/`--` of one is an atomic read-modify-write
  (see Atomic read-modify-write below). `<stdatomic.h>`'s
  `atomic_load_explicit`, `atomic_store_explicit`, `atomic_init` and the
  fences are clang's `__c11_atomic_*` builtins: load and store map to
  the `__atomic` builtins, init is a plain store, and a thread fence is
  `mfence` when seq_cst and nothing otherwise (as on x86-64 clang);
  `__atomic_thread_fence` and the signal fences too. An `_Atomic`
  bit-field is refused (clang refuses one too). An `_Atomic` parameter
  loses its qualifier and is assigned plainly, which only matters if its
  address reaches another thread. Before, the
  `_Atomic` qualifier was silently ignored: a `struct obj *_Atomic`
  slot stored by one thread and read by another tore and trapped.
  [c11-atomics.c](../tests/c/prog/c11-atomics.c).
- **Alignment of objects.** `_Alignas` and GNU `aligned(N)` on an object
  declaration (socketmodule's `char buf[16384] Py_ALIGNED(8)`) align the
  object, local, VLA, static or global, up to 16 bytes, the most an
  `alloc` or data item aligns to; the type, and so `sizeof` and
  `_Alignof` of it, is unchanged (`object_alignment/5`). A stricter
  request, or one on a function or typedef, is still refused.
  [object-alignment.c](../tests/c/prog/object-alignment.c).
- **Pointer-as-int laundering.** Fil-C gives an `inttoptr` the
  capability of the one `ptrtoint` its integer came from
  (gimso_semantics.md, *Inttoptr*); _elementtree tags pointers with
  `(PyObject *)((uintptr_t)p & ~1)` and the string search aligns them
  with `_Py_ALIGN_DOWN`. nanofil finds the source in the cast's own
  expression: through integer conversions, unary `-`, `+` and `~`, and
  the arithmetic and bitwise operators, one cast of a pointer to an
  integer gives the result that pointer's capability at the integer's
  address (`laundered/4`). The same side-effect-free pointer cast twice
  (`(uintptr_t)p - ((uintptr_t)p & 7)`) is one source, as Fil-C's SSA
  identity makes it. No source, two different ones, or a pointer
  conversion or pointer difference inside a `?:`, comma, assignment or
  statement expression gives no capability, as Fil-C's TOP does; so does
  a source behind a conversion to `_Bool`. Fil-C infers on SSA after the
  optimizer has made locals values, so it also follows a pointer through
  a local `uintptr_t` variable, and through a `?:` whose arms agree;
  nanofil does not. [launder.c](../tests/c/prog/launder.c).
- **Large tables.** unicodedata's 26,000-entry tables and deepfreeze.c
  (6.6 MB preprocessed, string literals of up to a few hundred kilobytes)
  overflowed SWI's 1 GB stack. A choicepoint per declaration
  (`reflect_type/4`) and per static-initializer leaf kept every
  declaration's and leaf's terms alive; the lexer's narrow string
  literals recursed per character without last-call optimization; and
  the stacks grown by lexing and parsing stayed allocated into
  lowering (`release_stacks/0` now also runs after each). Both fit in
  about 600 MB and 800 MB, and the output is byte-identical to the old
  compiler's with a raised limit.

`__uint128_t` is configured out of both builds (libmpdec takes its
portable path): nanofil refuses `__int128`. Frames are larger than
clang's: `_PyEval_EvalFrameDefault`'s is 24,880 bytes plain and 9,872
with `-O`, against 3,640 for clang `-O3`, so Python's recursion tests
overflow an 8 MB stack before Python's recursion guard stops them
(Fil-C reports the overflow); the check runs both interpreters on a
fiber with a 256 MB stack (nix/python-main-stack.patch; Fil-C sizes a
thread's stack by RLIMIT_STACK, whatever its attributes ask), so it does not
depend on the builder letting it raise RLIMIT_STACK
(test_isinstance's `test_infinitely_many_bases` recurses about 2,400
levels of about 27 KB each in the plain build, past 64 MB).

## Atomic read-modify-write

## Variable length arrays

C11 6.7.6.2 as c_types states it. An array size that is not an integer
constant expression gives the type `array(T, vla(E))`, keeping the
size expression E (`[*]` is `vla(star)`); `vm_type/1` (6.7.6p3) and
`vla_type/1` (6.7.6.2p4) say which types are variably modified and
which are VLAs. A variable length is compatible with any length
(6.7.6.2p6). Parameter names are in scope for the later parameters'
sizes. A comma operator folds only when its left operand does, so the
length of `int[(c++, 5)]` is not a constant and `c++` happens. A
struct member may not be variably modified (6.7.2.1p9).

Lowering evaluates each `vla(E)` once, where C does (`realized//3`):
at a declaration when it is reached (including typedefs and `static`
pointers to VLAs), in a cast, `va_arg` or compound literal's type name,
in `sizeof` of a VLA type, and for each variably modified parameter on
entry, after all parameters are bound (6.9.1p10). The length, converted
to `long`, becomes the type's `dyn(V)`, V an IR temporary; outermost
lengths are evaluated first. `extent//3` computes a size from those
lengths, so `sizeof`, pointer arithmetic and pointer differences scale
at run time. `sizeof` evaluates its operand only when it has a VLA type
(6.5.3.4p2): `sizeof(c++, p)` for a pointer to one does not.

A VLA object is an `alloc` of its run-time size at the declaration, not
hoisted to the entry block, as `__builtin_alloca` is
([abi-findings](abi-findings.md#dynamic-alloca-and-unreachable)): a
fresh Fil-C object each time, whose capability bounds are the actual
size (rounded up to 16 bytes by the runtime, as clang's are), so an
access past the length traps. No IR term changed. Lowering
uses the evaluated type a tree node's lowered pointer carries
(`vm_typed/3`) where the elaborator's type still holds an unevaluated
type name's `vla(E)`.

The temporaries holding lengths and VLA addresses are defined where the
declaration is, so lowering enforces the constraints that keep them
dominating every use: no `goto` into the scope of a variably modified
identifier (6.8.6.1p1), no `switch` case inside one the switch is
outside (6.8.4.2p2). Also refused: `static` VLAs, variably modified
objects at file scope or with linkage (6.7.6.2p2), initialized VLAs
(6.7.9p3), VLA compound literals (6.5.2.5p1), and `[*]` outside a
prototype. [tests/c/vla.c](../tests/c/vla.c) compares interpreter,
nanofil and clang on storage, bounds traps, multidimensional indexing,
evaluation counts, `sizeof`, casts, parameters, loops and backward
jumps; `tests/c/reject/vla-*.c` hold the refusals.

## Known gaps

- **Bounds of locals are rounded up to 16 bytes.** M3's `alloc` is
  `filc_allocate`, which rounds every size up to `FILC_MINALIGN` (16) and
  sets `upper` to match (`prepare_allocate_object` in `filc_runtime.c`).
  This is Fil-C's own heap granularity, not a hole. clang-built `malloc(8)`
  and escaping locals at `-O0` behave the same, and the overrun only
  reaches the object's own zeroed padding, never another object or a
  capability. clang at `-O1` traps exactly on `oobp(2)` because it keeps
  that non-escaping local on the stack and checks its exact size
  statically. nanofil gets that with M5's escape analysis, which keeps
  non-escaping locals on the stack.
- Byval struct arguments always take the generic convention, as
  clang's do.
- Struct copies are inline, one load and store per eightbyte, however
