# M4: C frontend

The plan and decisions are in [PLAN.md](../PLAN.md#m4-c-frontend-subset).
This file records what exists. M4a (lexer, parser, types), M4b
(lowering of functions), M4c (globals, string literals, function
pointers, libc calls, `main`), M4d (structs and unions as values), and M4e
(preprocessor) are done. M4f's pinned corpus and complete failure triage
are in [corpus.md](corpus.md).

```sh
cd nanofil/src
export FILCC=/path/to/filcc/bin/clang     # target profile and linking only
../bin/nanofil cc-ir prog.c            # the IR, as ir_text.pl clauses
../bin/nanofil cc prog.c > prog.s      # Fil-C assembly; .i still works
```

## Pipeline

```diagram
 C ──▶ c_pp ──▶ c_lex ──▶ c_parse ──▶ c_lower ──▶ IR (Fil-C module)
                     tokens     syntax      │  ▲
                                trees       ▼  │
                                          c_types
                                 specifiers, declarators, layouts,
                                 conversions, constant expressions
```

- [src/c_lex.pl](../src/c_lex.pl): tokens `tok(T, File:Line)`, following
  `# N "file"` markers, so errors point into the original source. GNU
  spellings fold into keywords (`__restrict__` is `restrict`). Integer
  constants keep their radix, because C types `4294967295` as `long` but
  `0xFFFFFFFF` as `unsigned int`.
- [src/c_parse.pl](../src/c_parse.pl): a C11 parser whose only state is
  the set of typedef names in scope, enough to tell declarations from
  expressions (a local `int node;` hides a typedef `node`). Declarator
  types are built outermost first around the atom `base`, so
  `int (*c)[5]` is `ptr(array(base, 5))`. Attributes after declarators are
  kept as `attr(Tokens)` specifiers; asm labels are kept as renames.
- [src/c_types.pl](../src/c_types.pl): type terms, SysV sizes and struct
  layout, integer promotions, the usual arithmetic conversions, and
  integer constant expressions (`sizeof`, `offsetof`, casts, enum
  constants). A type nanofil cannot handle yet is `bad(Reason)`, an error
  only when a declaration uses it, so whole glibc headers still parse.
- [src/c_lower.pl](../src/c_lower.pl): cproc-style lowering.

The real glibc headers from filcc's sysroot parse: stdio, stdlib, string,
stdint, ctype, limits, errno, unistd, signal, math, pthread, time,
sys/stat, dirent, wchar, inttypes, fcntl, sys/mman, getopt and setjmp.
`stdatomic.h` is rejected. Struct layouts were compared with clang's
`sizeof`, `_Alignof` and `offsetof` for `stat`, `tm`, `timespec`, `dirent`,
`pthread_mutex_t`, `pthread_attr_t`, `sigset_t`, `fpos_t`, `div_t` and
`ldiv_t`, and match.

## GNU hello frontend additions

`_Generic` parses an unevaluated controlling expression and an association
list. Selection applies lvalue/array/function conversion, but not integer
promotion; typedefs and compatible pointer/array/function types match,
and `default` is used only when no type matches. A scoped `qtype(Name)`
entry preserves qualification for reflection without changing ABI types.
Only the selected expression is lowered and it retains its value category.
Duplicate compatible associations, duplicate defaults, incomplete object
associations and missing matches are errors.

`sizeof` of an expression is available to integer constant evaluation as
well as function lowering. Array names already decay to relocation-bearing
address constants in static initializers. Block-scope static initializers
are now resolved while their local names (including enums and typedefs)
are still in scope, rather than after restoring the enclosing scope.

`__builtin_unreachable()` ends a block with `unreachable`.
`__builtin_alloca(n)` emits a bounded, 16-byte-aligned `alloc` at the call
site; see [the ABI findings](abi-findings.md#dynamic-alloca-and-unreachable).
GNU hello's same header expansions also need `__builtin_constant_p`, which
queries integer constant evaluation without evaluating its argument and
returns 0 when it cannot establish a constant.

## Preprocessor (M4e)

[src/c_pp.pl](../src/c_pp.pl) preprocesses the source and headers itself;
none of their contents is sent to clang. The DCG scanner retains token
spellings, preceding whitespace, original file/line and a macro hide set.
Only after replacement and rescanning does `c_lex` classify each spelling
into the parser's existing `tok(T, File:Line)` terms. `.i` input still goes
straight to `c_lex`, including its line-marker support.

- Object and function macros, empty arguments, variadic `__VA_ARGS__`
  (also GNU named variadics), argument prescan, `#`, `##`, placemarkers and
  rescanning. Hide sets prevent direct and indirect recursion, including
  when a replacement consumes a call from the remaining input. Arguments
  used only by `#` or `##` are not prescanned.
- Quoted includes search the including file's directory first; angle
  includes use the target search list. Literal header names are not macro
  expanded (`linux` is a predefined macro!), but macro operands are.
  `#include_next` and `__has_include_next` search after the current system
  directory. `__has_include` tests the same search path.
- Nested conditionals, `defined`, `#undef`, `#error` and ignored pragmas;
  `#pragma once` remembers a canonical file name, and nested
  `push_macro`/`pop_macro` save and restore definitions (including undefined
  macros). Integer conditions use
  64-bit intmax/uintmax conversions and exact integer division. `&&`, `||`
  and `?:` do not evaluate unselected arms.
- `__FILE__` and `__LINE__` refer to original sources. A parallel location
  vector survives line splicing, including splices inside tokens. Macro
  replacement tokens point to their invocation, not to the definition in
  a system header. Macro-expanded `#line` changes logical locations without
  changing the physical directory used for includes and `__has_include`.

**Target profile decision:** discover predefined macros with
`$FILCC -dM -E -x c /dev/null` and include directories with
`$FILCC -E -v -x c /dev/null` once per invocation (`FILCC` defaults to
`filcc`). Embedding either would duplicate the toolchain pin and bake Nix
store paths into Prolog. Clang's feature operators are absent from `-dM`:
the adapter batches glibc's `__has_attribute`, `__has_builtin`,
`__has_extension`, `__has_feature` and `__building_module` queries, and
queries other single feature names on demand. Only target-property probes
go through clang; nanofil performs all source preprocessing. Keeping this
profile discovery requires the selected Fil-C executable, which is also
needed for linking. No replacement headers or per-header output patches
are used. Header-driven additions were wide character constants in `#if`
(`bits/wchar.h`), the feature operators (`sys/cdefs.h`), and the next-include
operators in Clang's resource headers.

**Acceptance:** [tests/pptest.sh](../tests/pptest.sh), part of the Nix check,
compares location-free `c_lex` terms against `filcc -E` for each of the 20
headers listed above and every `.c` recursively under `tests/c` (including
rejections). Generated probes cover the macro rules, the C standard's
recursive rescanning example, once-only includes, integer conversions,
short-circuiting, `#error`, original-file/line assertions, spliced `#line`,
multiline comments in directives, and nested macro save/restore. `#line`
and macro save/restore also preserve M4f's existing passing cases
`c-testsuite/00152.c` and `c-testsuite/00206.c`. The existing
differential, whole-program and rejection scripts now compile `.c`
directly through nanofil. To prove the comparator detects a regression,
object macros were temporarily changed to expand to nothing: a
`#define VALUE 42` probe failed with `PREPROCESSOR MISMATCH` and a missing
`int(42,-(none,dec))` token (exit 1). Restoring expansion made the same
command pass (exit 0).

## Lowering

- **Locals.** Every local and parameter is an `alloc` in the entry block,
  and each use is a load or store, as in cproc before QBE's `promote`. An
  initializer zeroes the whole object first, because a hoisted alloc is
  reused across loop iterations. Initializer lists support designators
  and brace elision.
- **Narrow integers** are always held sign- or zero-extended to 32 bits in
  a `w` value. A conversion emits an `ext` only if some value of the source
  type does not fit the target (`int` to `unsigned char` does, `unsigned
  char` to `short` does not). `int` to `long` is `extsw`/`extuw`, and
  `long` to `int` needs no instruction, since a `w` use of an `l` value
  reads its low half. Narrow call results are re-extended, because
  nothing guarantees the callee did it.
- **Pointers** are `p`: `p + i` scales `i` to a `long` and adds it with
  `add` at `p`, which keeps the capability; differences and comparisons go
  through `ptoi`. A constant integer used as a pointer is a capability-free
  `p` constant, so `*(int *)0` traps.
- **`&&`, `||` and `?:`** produce phis. `?:` lowers each arm once against
  a throwaway copy of the lowering state to find the result type, then
  again with the conversion; `sizeof expr` uses the same trick.
- **`switch`** jumps to a dispatch block after the body, a chain of
  compares filled in once all `case` labels are known.

## Globals, literals, function pointers and libc (M4c)

The ABI facts are in [abi-findings.md](abi-findings.md#globals-getters-and-indirect-calls-for-m4c),
read from the runtime and pass at the pin.

**IR.** A Fil-C module may now have `data`. `item(p, sym(Sym, Off))` is
a pointer data item, and linkage `ro(Lk)` marks read-only data (in
`.rodata`). A symbol appears in code only as
`let(tmp(T), p, copy, [global(Sym)])`, which is a call to its getter, and
`call(Res, tmp(T), Args)` calls through a `p` value. A module
that calls a function it does not define is a Fil-C module.

**Interpreter.** Globals are 16-aligned objects with sizes rounded up to
8, as Fil-C lays them out; read-only data has capability `ro(Base)` and
traps on writes. Each function has an address with capability `fn(F)`, a
zero-size object, so loads through it trap. An indirect call traps
unless the pointer is exactly a function's; a call whose classes differ
from the callee's goes through the generic convention, so too few
arguments or using a void result traps, as the generic entry's size
checks do.

**Backend.**

- `DO_g`, `GP_g`, `DA_g` (only if the payload holds pointers), a
  relocation table, and a getter whose slow path is
  `filc_global_initialization_start`, `filc_execute_constant_relocations`,
  `filc_global_initialization_end`, with the flags clang uses (0x1, 0x11,
  0x3, 0x13). Pointer slots are 0 in the static data and filled in by the
  relocations; a pointer with an offset uses a constexpr node.
- `copy $s` sets the frame's call-site origin and calls the getter, so a
  getter is a safepoint like any call.
- Every function now has a getter, generic entry and function object, so
  local functions can have their address taken.
- Indirect calls check for a function object (lower ≠ 0, ptr = its aux
  pointer, special type function, else `filc_check_function_call_fail`),
  then use the fast entry if the signature word matches and the generic
  entry otherwise, checking the returned size.
- Each external callee gets a hidden weak thunk `pizlonatedFI<sig>_f`, as
  clang emits: getter, function-object check, fast or generic entry. A
  clang definition in the same link wins. This is how libc is reached.
- `main` needs nothing special: the runtime calls `pizlonated_main`.

**Frontend.** Globals with constant initializers (integers, address
constants such as `&a[2]`, `"str"`, function names, `&s.f`, with
designators and brace elision), tentative definitions, `static` locals
(renamed `fn.name.N`), string literals as read-only `str.N` data,
function designators and pointers, and `__func__`. `static inline`
functions are lowered only when something refers to them, as clang does;
headers are full of ones nanofil cannot lower.

Non-static inline definitions follow C99: any file-scope declaration
with `extern` or without `inline`, even after the body, makes the body
an external definition. Otherwise it emits no definition. GNU
`gnu_inline`/`__gnu_inline__` attributes retain the GNU89 rule instead:
`extern inline` emits no definition, plain `inline` does. The attributes
are already retained by the parser in specifiers and declarator suffixes.
[tests/c/prog/extern-inline.c](../tests/c/prog/extern-inline.c) tests both
rules across translation units against clang, including declarations
before and after the body and the unchanged `static inline` behavior.

## Structs and unions as values (M4d)

The ABI facts are in [abi-findings.md](abi-findings.md#structs-as-values-for-m4d).

**IR.** One addition, a two-word result, for structs of 9 to 16 bytes:
`function {l, p} $f(...)`, `ret {%a, %b}` and `{%a, %b} ={l, p} call
...` (terms `tuple([K1, K2])`, `rets([V1, V2])` and `call(tuple([to(D1,
K1), to(D2, K2)]), ...)`). Each word is `l` or `p`. A tuple makes the
module a Fil-C module. Everything else a struct needs is lowered by the
frontend into existing IR: struct arguments are their words, one-word
structs return as `l` or `p`, and larger returns take an sret pointer as
the first argument.

**Interpreter.** `rets` gives the outcome `rets([X1, X2])` and a tuple
call binds both temporaries. The generic convention of indirect calls
now works word by word for results too: the call site may read fewer
words than the callee returns, not more.

**Backend.** Results with at most two slots (a `p` word is two) come
back in RDX:RCX; `{l, p}`, `{p, l}` and `{p, p}` use the caller's buffer,
with all registers shifted by one. Functions, direct and indirect calls,
generic entries and thunks all handle both forms. A buffered call keeps
its buffer on the native stack for the moment between the return and
copying the slots into the frame; there is no safepoint in between.

**Frontend.** A struct rvalue is the address of storage holding it (a
variable, or a temporary local for a call result), so `a = b`, `return
s`, `f(s)`, `c ? s1 : s2` and `f().x` need no struct temporaries in the
IR. Copies and conversions to words go an eightbyte at a time: `load(p)`
and `store(p, ...)` where a pointer starts, so capabilities copy exactly
(decision 6), else `load(l)`/`store(l, ...)`, with a short last eightbyte moved
in 4-, 2- and 1-byte pieces (`struct {char a, b, c}` is a halfword and a
byte). A struct expression initializes a struct member or array element
whole rather than by brace elision. Struct arguments over 16 bytes (and
misaligned packed ones) are byval: passed as their eightbytes, and a
function taking one is generic-only, promoting its argument packet to
the heap as a variadic function does (decision 7, abi-findings.md
*Byval arguments*). Such a struct's float members do not matter, since
it never travels in SSE registers; a byval struct over 16 words, or an
aggregate `va_arg`, is still refused.
[tests/c/prog/byval.c](../tests/c/prog/byval.c) passes them across the
clang boundary both ways, directly, indirectly, past a prototype's
`...` and through wrong prototypes, and traps through a pointer field
that made the round trip.

**Initializers.** An array of unknown size counts the entries each
element takes with brace elision (`struct {int a, b;} s[] = {1, 2, 3,
4}` has 2 elements, not 4), and an elided aggregate stops at the next
designator, which belongs to the enclosing list. Both were found by the
M4f corpus (c-testsuite `00205`).

## Bit-fields

A bit-field is a member `m(some(F), Type, Off, bits(Pos, W))`: W bits
from bit Pos of the Type-sized storage unit at byte Off. Layout follows
the SysV psABI (and clang): a bit-field takes the next bits unless it
would cross a boundary of its type's size, where it starts instead; a
zero-width one moves to that boundary; an unnamed one takes space but
does not align the struct, and a named one aligns it as its type. The
unit is aligned to its own size inside a struct aligned at least as
much, so every unit access stays inside the object, and a unit never
shares an eightbyte with a pointer, so the Fil-C capabilities are
untouched.

The elaborator marks a bit-field lvalue `obj(T, bitfield(member(XS, F),
W))`. Its value has the promoted type of `bitfield_promotion/3`: int
when an int holds every value, else unsigned int when that does, else
its own type (C11 6.3.1.1p2, and clang's rule for `long` bit-fields).
`&` and `sizeof` of a bit-field are refused. Lowering reads the unit
and shifts the field to the bottom, extended by the type's sign; a store
loads the unit, masks the field in and stores it back, and the value of
an assignment, `++` or `--` is the field read back from what was stored.
Static initializers merge each bit-field into the bytes it covers.
[tests/c/bitfields.c](../tests/c/bitfields.c) compares the interpreter,
nanofil and clang on layouts, signs, neighbours kept by stores,
promotion, assignment values, initializers, copies and struct arguments.
Packed bit-fields, which GCC places differently, are rejected.

## Packed structs and unions

GNU's `packed` attribute (`__attribute__((packed))` before the tag or
after the body, or `[[gnu::packed]]`) gives every member alignment 1,
and the struct too (`su_layout/5`). Non-pointer accesses already check
no alignment, so misaligned members load and store like any other;
copies and static initializers are bytewise as before. nanofil refuses
packed pointers (Fil-C keeps a capability only at an 8-aligned address)
and packed bit-fields. A struct with a misaligned member, perhaps
nested, has SysV class MEMORY (`unaligned_type/2`): it is returned
through a hidden pointer as clang does, and passed by value byval. `aligned` stays unsupported.
[tests/c/packed.c](../tests/c/packed.c) compares layouts and accesses
three ways; [tests/c/prog/packed.c](../tests/c/prog/packed.c) returns a
misaligned packed struct across the clang boundary in both directions.

## Small C99 and GNU additions

GNU statement expressions `({ ... })` open a block scope and yield the
last expression statement's value (including a labelled expression), or
void otherwise. Nested expressions, shadowing and header macros such as
glibc's `assert` work. Labels remain function-scoped: gotos may stay within
or leave an expression, but entering one (also from a sibling expression)
is rejected, as is switch dispatch from outside to a case/default inside.
Computed gotos remain unsupported. Break/continue retain the enclosing
statement context; in loop conditions/init/increment they target an outer
loop, as GCC documents, not the loop being constructed. The pinned clang
differs for condition-expression break/continue, so those cases must be
checked against GCC instead. Evaluation is not interleaved with sibling
operands. [tests/c/stmtexpr.c](../tests/c/stmtexpr.c) compares values, void,
nesting, scope, assert, labels and outward jumps against clang.

Compound literals (a block-scope one is an unnamed local initialized
where it appears; a file-scope one is unnamed static data), wide
character and string literals (`L` is `int`, `u` is `unsigned short`, `U`
is `unsigned int`; elements are code points), `u8` strings, GNU `c ?: b`
with `c` evaluated once, and `__builtin_expect`. In initializers: GNU
range designators `[a ... b] = v`, each element initialized as if
designated alone (so `v` may not have side effects, which GCC would
evaluate once); a designator naming a member of an anonymous member
(C11 6.7.2.1p13); and GNU constant compound literals of the slot's own
struct type in static initializers, read as their initializer lists.
[tests/c/c99.c](../tests/c/c99.c) covers them three ways.

## Variable length arrays

C11 6.7.6.2 as c_types states it. An array size that is not an integer
constant expression gives the type `array(T, vla(E))`, keeping the
size expression E (`[*]` is `vla(star)`); `vm_type/1` (6.7.6p3) and
`vla_type/1` (6.7.6.2p4) say which types are variably modified and
which are VLAs. A variable length is compatible with any length
(6.7.6.2p6). Parameter names are in scope for the later parameters'
sizes. A comma operator folds only when its left operand does, so the
length of `int[(c++, 5)]` is not a constant and `c++` happens. A
struct member may not be variably modified (6.7.2.1p9).

Lowering evaluates each `vla(E)` once, where C does (`realized//3`):
at a declaration when it is reached (including typedefs and `static`
pointers to VLAs), in a cast, `va_arg` or compound literal's type name,
in `sizeof` of a VLA type, and for each variably modified parameter on
entry, after all parameters are bound (6.9.1p10). The length, converted
to `long`, becomes the type's `dyn(V)`, V an IR temporary; outermost
lengths are evaluated first. `extent//3` computes a size from those
lengths, so `sizeof`, pointer arithmetic and pointer differences scale
at run time. `sizeof` evaluates its operand only when it has a VLA type
(6.5.3.4p2): `sizeof(c++, p)` for a pointer to one does not.

A VLA object is an `alloc` of its run-time size at the declaration, not
hoisted to the entry block, as `__builtin_alloca` is
([abi-findings](abi-findings.md#dynamic-alloca-and-unreachable)): a
fresh Fil-C object each time, whose capability bounds are the actual
size (rounded up to 16 bytes by the runtime, as clang's are), so an
access past the length traps. No IR term changed. Lowering
uses the evaluated type a tree node's lowered pointer carries
(`vm_typed/3`) where the elaborator's type still holds an unevaluated
type name's `vla(E)`.

The temporaries holding lengths and VLA addresses are defined where the
declaration is, so lowering enforces the constraints that keep them
dominating every use: no `goto` into the scope of a variably modified
identifier (6.8.6.1p1), no `switch` case inside one the switch is
outside (6.8.4.2p2). Also refused: `static` VLAs, variably modified
objects at file scope or with linkage (6.7.6.2p2), initialized VLAs
(6.7.9p3), VLA compound literals (6.5.2.5p1), and `[*]` outside a
prototype. [tests/c/vla.c](../tests/c/vla.c) compares interpreter,
nanofil and clang on storage, bounds traps, multidimensional indexing,
evaluation counts, `sizeof`, casts, parameters, loops and backward
jumps; `tests/c/reject/vla-*.c` hold the refusals.

## Known gaps

- **Bounds of locals are rounded up to 16 bytes.** M3's `alloc` is
  `filc_allocate`, which rounds every size up to `FILC_MINALIGN` (16) and
  sets `upper` to match (`prepare_allocate_object` in `filc_runtime.c`).
  This is Fil-C's own heap granularity, not a hole. clang-built `malloc(8)`
  and escaping locals at `-O0` behave the same, and the overrun only
  reaches the object's own zeroed padding, never another object or a
  capability. clang at `-O1` traps exactly on `oobp(2)` because it keeps
  that non-escaping local on the stack and checks its exact size
  statically. nanofil gets that with M5's escape analysis, which keeps
  non-escaping locals on the stack.
- Byval struct arguments always take the generic convention, as
  clang's do, and the words of one are limited to 16 in all.
- Struct copies are inline, one load and store per eightbyte, however
  large the struct.
