# M4: C frontend

The plan and decisions are in [PLAN.md](../PLAN.md#m4-c-frontend-subset).
This file records what exists. M4a (lexer, parser, types), M4b
(lowering of functions) and M4c (globals, string literals, function
pointers, libc calls, `main`) are done. M4f's pinned corpus and complete
failure triage are in [corpus.md](corpus.md); M4d and M4e are in progress.

```sh
cd nanofil/src
filcc -E prog.c > prog.i                  # until M4e's preprocessor
tpl -q main.pl -- cc-ir prog.i            # the IR, as QBE text
tpl -q main.pl -- cc prog.i > prog.s      # Fil-C assembly
```

## Pipeline

```diagram
 preprocessed C ──▶ c_lex ──▶ c_parse ──▶ c_lower ──▶ IR (Fil-C module)
                     tokens     syntax      │  ▲
                                trees       ▼  │
                                          c_types
                                 specifiers, declarators, layouts,
                                 conversions, constant expressions
```

- [src/c_lex.pl](../src/c_lex.pl): tokens `tok(T, File:Line)`, following
  `# N "file"` markers, so errors point into the original source. GNU
  spellings fold into keywords (`__restrict__` is `restrict`). Integer
  constants keep their radix, because C types `4294967295` as `long` but
  `0xFFFFFFFF` as `unsigned int`.
- [src/c_parse.pl](../src/c_parse.pl): a C11 parser whose only state is
  the set of typedef names in scope, enough to tell declarations from
  expressions (a local `int node;` hides a typedef `node`). Declarator
  types are built outermost first around the atom `base`, so
  `int (*c)[5]` is `ptr(array(base, 5))`. Attributes after declarators are
  kept as `attr(Tokens)` specifiers; asm labels are kept as renames.
- [src/c_types.pl](../src/c_types.pl): type terms, SysV sizes and struct
  layout, integer promotions, the usual arithmetic conversions, and
  integer constant expressions (`sizeof`, `offsetof`, casts, enum
  constants). A type nanofil cannot handle yet is `bad(Reason)`, an error
  only when a declaration uses it, so whole glibc headers still parse.
- [src/c_lower.pl](../src/c_lower.pl): cproc-style lowering.

The real glibc headers from filcc's sysroot parse: stdio, stdlib, string,
stdint, ctype, limits, errno, unistd, signal, math, pthread, time,
sys/stat, dirent, wchar, inttypes, fcntl, sys/mman, getopt and setjmp.
`stdatomic.h` is rejected. Struct layouts were compared with clang's
`sizeof`, `_Alignof` and `offsetof` for `stat`, `tm`, `timespec`, `dirent`,
`pthread_mutex_t`, `pthread_attr_t`, `sigset_t`, `fpos_t`, `div_t` and
`ldiv_t`, and match.

## Lowering

- **Locals.** Every local and parameter is an `alloc` in the entry block,
  and each use is a load or store, as in cproc before QBE's `promote`. An
  initializer zeroes the whole object first, because a hoisted alloc is
  reused across loop iterations. Initializer lists support designators
  and brace elision.
- **Narrow integers** are always held sign- or zero-extended to 32 bits in
  a `w` value. A conversion emits an `ext` only if some value of the source
  type does not fit the target (`int` to `unsigned char` does, `unsigned
  char` to `short` does not). `int` to `long` is `extsw`/`extuw`, and
  `long` to `int` needs no instruction, since a `w` use of an `l` value
  reads its low half. Narrow call results are re-extended, because
  nothing guarantees the callee did it.
- **Pointers** are `p`: `p + i` scales `i` to a `long` and adds it with
  `add` at `p`, which keeps the capability; differences and comparisons go
  through `ptoi`. A constant integer used as a pointer is a capability-free
  `p` constant, so `*(int *)0` traps.
- **`&&`, `||` and `?:`** produce phis. `?:` lowers each arm once against
  a throwaway copy of the lowering state to find the result type, then
  again with the conversion; `sizeof expr` uses the same trick.
- **`switch`** jumps to a dispatch block after the body, a chain of
  compares filled in once all `case` labels are known.

## Globals, literals, function pointers and libc (M4c)

The ABI facts are in [abi-findings.md](abi-findings.md#globals-getters-and-indirect-calls-for-m4c),
read from the runtime and pass at the pin.

**IR.** A Fil-C module may now have `data`. `p $sym + off` is a pointer
data item, and `section ".rodata"` marks read-only data (linkage
`ro(Lk)`). A symbol appears in code only as `%t =p copy $sym`, which is a
call to its getter, and `call %t(...)` calls through a `p` value. A module
that calls a function it does not define is a Fil-C module.

**Interpreter.** Globals are 16-aligned objects with sizes rounded up to
8, as Fil-C lays them out; read-only data has capability `ro(Base)` and
traps on writes. Each function has an address with capability `fn(F)`, a
zero-size object, so loads through it trap. An indirect call traps
unless the pointer is exactly a function's; a call whose classes differ
from the callee's goes through the generic convention, so too few
arguments or using a void result traps, as the generic entry's size
checks do.

**Backend.**

- `DO_g`, `GP_g`, `DA_g` (only if the payload holds pointers), a
  relocation table, and a getter whose slow path is
  `filc_global_initialization_start`, `filc_execute_constant_relocations`,
  `filc_global_initialization_end`, with the flags clang uses (0x1, 0x11,
  0x3, 0x13). Pointer slots are 0 in the static data and filled in by the
  relocations; a pointer with an offset uses a constexpr node.
- `copy $s` sets the frame's call-site origin and calls the getter, so a
  getter is a safepoint like any call.
- Every function now has a getter, generic entry and function object, so
  local functions can have their address taken.
- Indirect calls check for a function object (lower ≠ 0, ptr = its aux
  pointer, special type function, else `filc_check_function_call_fail`),
  then use the fast entry if the signature word matches and the generic
  entry otherwise, checking the returned size.
- Each external callee gets a hidden weak thunk `pizlonatedFI<sig>_f`, as
  clang emits: getter, function-object check, fast or generic entry. A
  clang definition in the same link wins. This is how libc is reached.
- `main` needs nothing special: the runtime calls `pizlonated_main`.

**Frontend.** Globals with constant initializers (integers, address
constants such as `&a[2]`, `"str"`, function names, `&s.f`, with
designators and brace elision), tentative definitions, `static` locals
(renamed `fn.name.N`), string literals as read-only `str.N` data,
function designators and pointers, and `__func__`. `static inline`
functions are lowered only when something refers to them, as clang does;
headers are full of ones nanofil cannot lower.

## Tests

- [tests/c/basic.c](../tests/c/basic.c) and [tests/c/more.c](../tests/c/more.c):
  52 runs, each run three ways (interpreter on nanofil's IR, nanofil's
  Fil-C code, and clang compiling the same C file), all linked with the
  same harness by [tests/difftest.sh](../tests/difftest.sh), which now
  accepts `.c` files and takes `// run: $fn args` comments as run lines.
  They cover conversions between all integer widths and signs, signed and
  unsigned division and shifts, enums and `switch`, structs, unions,
  nested arrays with brace elision and designators, string initializers,
  pointer walking and comparison, mutual recursion through prototypes,
  short-circuit side effects and out-of-bounds traps. A planted bug
  (unsigned `>>` as `sar`) shows up only as a mismatch against clang,
  because the interpreter and nanofil's code share the frontend. That is
  why the clang variant exists.
- [tests/reject.sh](../tests/reject.sh): 13 programs in
  [tests/c/reject](../tests/c/reject) that must be refused with a given
  message: floating point, bitfields, VLAs, defining a variadic function,
  inline asm, `_Complex`, `_Atomic`, statement expressions, K&R
  parameters, label addresses, packed structs, undeclared identifiers and
  case ranges.

- [tests/progtest.sh](../tests/progtest.sh): whole programs in
  [tests/c/prog](../tests/c/prog), built by nanofil (including `main`) and
  by `filcc -O1`, must agree on stdout, stderr and exit status, a safety
  panic counting as `trap`. They use `printf`, `snprintf`, `puts`,
  `fputs(stderr)`, `malloc`, `strcpy`/`strcat`/`strlen`/`memcpy`, `qsort`
  with nanofil callbacks, function pointers in structs and static tables,
  and an overflow in `strcpy` into a nanofil `malloc` that must trap.
  `gcglobals.c` keeps 20,000-node lists reachable only from globals and a
  static local across forced collections, and the check also runs it with
  `FUGC_SCRIBBLE=1 FUGC_VERIFY=1`. A getter that skips registration (it
  returned the object without `filc_global_initialization_start`) loses
  the list in both modes. A thunk that drops pointer lowers in the generic
  path is caught by `funcs.c`.
- [tests/filc/globals.ssa](../tests/filc/globals.ssa): IR-level globals,
  read-only writes, pointer data with offsets, indirect calls with
  matching and mismatching classes, calls through non-functions and
  offset function pointers, and reads through a function pointer.

## Known gaps

- **Bounds of locals are rounded up to 16 bytes.** M3's `alloc` is
  `filc_allocate`, which rounds every size up to `FILC_MINALIGN` (16) and
  sets `upper` to match (`prepare_allocate_object` in `filc_runtime.c`).
  This is Fil-C's own heap granularity, not a hole. clang-built `malloc(8)`
  and escaping locals at `-O0` behave the same, and the overrun only
  reaches the object's own zeroed padding, never another object or a
  capability. clang at `-O1` traps exactly on `oobp(2)` because it keeps
  that non-escaping local on the stack and checks its exact size
  statically. nanofil gets that with M5's escape analysis, which keeps
  non-escaping locals on the stack.
- Not yet: struct copies, struct arguments and returns (M4d), defining
  variadic functions, and the DCG preprocessor (M4e).
- The generic path of indirect calls and thunks returns only one word,
  enough until struct returns exist.
