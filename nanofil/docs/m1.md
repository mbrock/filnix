# M1: IR, relational interpreter, QBE subset

## What exists

| File | Role |
| --- | --- |
| [src/ir.pl](../src/ir.pl) | IR terms (documented at the top) and a validator that reports the first problem with a function name |
| [src/qbe_parse.pl](../src/qbe_parse.pl) | Lexer and DCG parser for the subset; unsupported input is rejected with a line number |
| [src/qbe_print.pl](../src/qbe_print.pl) | DCG printer back to QBE text |
| [src/interp.pl](../src/interp.pl) | `run(Module, Fn, Args, Fuel, Outcome)`, the semantics in CLP(Z) |
| [src/main.pl](../src/main.pl) | Driver: `check`, `print`, `run`, `difftest` |

The subset is QBE's integer IL: classes `w` and `l`, all integer
arithmetic, comparisons, extensions, loads, stores, `alloc`, `jmp`/`jnz`/
`ret`/`hlt`, phis, direct calls between functions in the module, and data
definitions with integer, string, symbol and zero items. Floats,
aggregate types, variadics, external calls and `blit` are rejected.

```sh
cd nanofil/src
tpl -q main.pl -- run ../tests/fixtures/memory.ssa fibs 15     # ret 610
tpl -q ../tests/unit.pl
TPL=tpl QBE=qbe ../tests/difftest.sh ../tests/fixtures/*.ssa
nix build .#checks.x86_64-linux.nanofil
```

## Semantics decisions

- Values are integers in `0..2^bits-1`. Reading an `l` value at `w` takes
  its low 32 bits, as the IL's subtyping says. `jnz` reads its argument
  at `w`.
- Shift counts are taken modulo the width, matching x86 and qbe.
- Division by zero and `INT_MIN / -1` are outcomes, `ub(...)`, not
  failures. So are accesses outside every live allocation, including use
  of a callee's `alloc` after it returns (addresses are never reused).
- Unwritten bytes are fresh variables in `0..255`. A load of them is an
  unknown value, never a made-up one.
- Memory is an assoc from byte address to byte, plus the list of live
  regions. Addresses and allocation sizes must be known when an access
  runs; otherwise an instantiation error is raised. That is incomplete but
  never wrong, and it was the M1 open question about modelling memory.
  Symbolic addresses can wait until a pass needs them.

Because arithmetic and branches are constraints, `run/5` runs backwards.
The unit tests ask which input makes `3x + 1 = 7` (x = 2), which input
reaches `hlt`, and for an input where signed division by 2 and `sar 1`
differ (−1).

## Testing

- **Differential.** `difftest` writes the interpreter's result for every
  `# run:` line with a known return value, and a C harness calling the same
  functions. `difftest.sh` compiles both the original file and nanofil's
  printed version of it with real `qbe`, runs them and diffs the results.
  This tests the interpreter, the parser and the printer at once.
- **Random.** [tests/gen.py](../tests/gen.py) generates functions mixing
  both classes, edge-value constants, diamonds with phis, counted loops and
  overlapping stack stores and loads. Seeds 1 to 8 (1,600 functions) gave
  8,098 compared runs with no mismatch once the qbe bugs below were
  avoided. About 17% of runs end in `ub` and are not compared.
- **Unit.** [tests/unit.pl](../tests/unit.pl) covers what native runs
  cannot: `ub`, `hlt`, fuel, unknown bytes, backwards queries, diagnostics
  and the printer round trip. The expected values are derived by hand.
- **Mutation check (manual).** Six deliberate interpreter bugs were each
  caught by the fixtures and the random corpus: truncating `sar`,
  sequential phis, `jnz` reading 64 bits, unsigned `extsb`, floored `rem`
  and big-endian loads.

## qbe bugs found

The interpreter disagreed with qbe four ways. The first three reproduce
with nixpkgs qbe 1.2 and upstream `c081897` (May 2026). Each is a fixture in
[tests/qbe-bugs/](../tests/qbe-bugs/), and the unit tests pin the answer
the IL document gives for the first three.

1. **[storew-l.ssa](../tests/qbe-bugs/storew-l.ssa).** Load forwarding
   after a sub-word store of a value with bits beyond the store width
   (an `l` temp, or a constant such as −661) does not mask those bits, so
   an overlapping narrower load sees them.
2. **[jnz-shift-flags.ssa](../tests/qbe-bugs/jnz-shift-flags.ssa).** `jnz`
   reuses the flags of the shift that defines its argument, but an x86
   shift by zero leaves flags unchanged.
3. **[jnz-long-flags.ssa](../tests/qbe-bugs/jnz-long-flags.ssa).** After
   a 64-bit op, `jnz` tests all 64 bits instead of the low 32 the IL
   specifies. With a plain `l` parameter, qbe tests 32 bits.
4. **[jnz-long-const.ssa](../tests/qbe-bugs/jnz-long-const.ssa).** The
   same when the `l` argument folds to a constant (`c081897` only),
   found once the generator stopped avoiding bug 3.

qbe also emits an unmasked constant shift count as an immediate that GNU
`as` rejects outside 8 bits. The check uses qbe `c081897` built by
[nix/qbe.nix](../nix/qbe.nix) with fixes for all five, kept as
`patches/qbe-*.patch` in the filnix tree, so the generator no longer
avoids these patterns.

## Trealla bug found

A clause whose body has a CLP(Z) goal over a ground integer constant of
at least 2^63, such as `Z #= X mod 18446744073709551616`, crashed Trealla
`12f4cbd` and upstream head `ba473a6`. Natively it segfaulted; the Fil-C
build reported `cannot write pointer to free object` in `set_var`.
Goal expansion pasted the expanded goal's cells into the clause and then
destroyed the sub-parser, freeing the bigint. filnix now carries
[patches/trealla-goal-expansion-share-cells.patch](../../patches/trealla-goal-expansion-share-cells.patch)
in both the Fil-C port and nanofil's native Trealla; it has not been
sent upstream yet.

The unit tests also pass under the Fil-C Trealla (`pkgsFilc.trealla`), in
about 5 s against 0.6 s natively.
