# M5: analyses, escape classification and promote

The plan is in [PLAN.md](../PLAN.md#m5-middle-end-and-translation-validation).
This file records what exists: the first middle-end pass, `promote`,
the analyses it needs, the translation validation that checks it, and
the measurement that settles how analyses are written.

```sh
cd nanofil/src
../bin/nanofil -O cc prog.i > prog.s         # with the middle end
../bin/nanofil -O cc-ir prog.i               # the promoted IR
../bin/nanofil -O difftest FILE.ssa OUTDIR   # validate run by run
NANOFIL_OPT=-O ../tests/difftest.sh FILE...     # every suite takes this
NANOFIL_OPT=-O ../tests/progtest.sh
```

Without `-O` nothing changes: the IR goes to the backend as loaded. That
path is the reference every optimization is checked against.

## Modules

```diagram
 IR module ──▶ opt.pl: optimize(o0 | o1)
                 │ o1
                 ▼
              promote.pl ──uses──▶ escape.pl   which allocs can go
                 │         ──uses──▶ cfg.pl     CFG, dominators, frontiers,
                 ▼                              liveness (pure, assocs)
              IR module, fewer allocs, phis
```

- [src/cfg.pl](../src/cfg.pl): pure functions from a function's blocks
  to assocs keyed by label. Reverse postorder, successors and
  predecessors; immediate dominators (Cooper, Harvey and Kennedy);
  dominator-tree children and pre/post intervals for constant-time
  `dominates`; dominance frontiers; and a generic backward liveness over
  any names (gen/kill per block plus uses on edges, which is how phi
  arguments count). Temp liveness is that instance; promote uses it again
  for memory slots.
- [src/escape.pl](../src/escape.pl): QBE's `ALoc`/`AEsc`. An alloc is
  `local(Size, Accesses)` when every use of its address, directly or
  through `add`/`sub` of constants and `copy`, is the address operand of a
  load or store; `Accesses` is the set of `acc(Offset, Width)`. Anything
  else is `escapes(Why)`: stored as a value, passed to a call, returned,
  compared, converted with `ptoi`, offset by a variable, merged in a phi,
  or a derived temp that is defined more than once. Unknown means
  escaping; the analysis never guesses.
- [src/promote.pl](../src/promote.pl): mem2reg. See below.
- [src/opt.pl](../src/opt.pl): `optimize/3` for the driver and
  `refines/2`, the comparison translation validation uses.
- [src/cfg_tabled.pl](../src/cfg_tabled.pl): the same analyses as tabled
  relations over asserted facts, versioned and incremental. They exist
  for the measurement below and as a cross-check; no pass uses them.

## promote

An alloc is promoted, all its slots at once, when:

- escape.pl calls it local;
- it is in the entry block, so it runs once per call and its fresh
  contents are the only initial state (the validator forbids jumps to the
  entry block);
- its size is a constant and every slot lies inside it, so no access
  could trap or be undefined;
- its slots do not overlap and each offset has one width, so every load
  reads exactly the bytes one store wrote;
- in Fil-C mode, `p` slots are 8-aligned, so no `loadp`/`storep` could
  trap as misaligned;
- the function is in strict SSA form (one definition per temp, dominating
  its uses). The C frontend's output always is; a function that is not is
  left alone.

Each slot becomes an SSA variable. Phis go on the iterated dominance
frontier of the blocks that store to it, pruned to blocks where the slot
is live (Cytron et al.). A walk of the dominator tree replaces loads with
the slot's current value and deletes the stores, the alloc and its
derived addresses. A narrow load re-extends the stored value
(`loadsb` → `extsb`, `loadsw` at `l` → `extsw`, at `w` → `copy`), which
is what the bytes would give. Before any store a slot is 0: Fil-C
allocations are zeroed (so a `p` slot is a pointer without a capability,
which traps when used, as before), and in plain mode the bytes are
unknown, so 0 is one value they could have had.

What it removes, alloc count before → after:

| corpus | allocs |
| --- | --- |
| tests/c/basic.c | 23 → 2 (`arr` and `ptrs` pass or store their arrays' addresses) |
| tests/c/more.c | 51 → 10 |
| tests/c/globals.c | 11 → 0 |
| tests/c/structs.c | 70 → 23 |
| tests/fixtures/promote.ssa | 12 → 4 (the four cases it must keep) |
| tests/filc/basic.ssa | 11 → 10 (the rest are arrays indexed by a variable) |
| `bigfn.py 1 300` | 63 → 0 |
| gen.py corpus | 72 → 72 (every alloc is addressed by variable offsets) |

Plain-mode fixtures are also compiled by real qbe before and after
promote. That found a qbe miscompile: qbe's own promote turns `loadsw`
and `loaduw` of a `w` slot read at class `l` into the same copy, so their
difference is 0. The repro is
[tests/qbe-bugs/load-ext-l.ssa](../tests/qbe-bugs/load-ext-l.ssa), with
the other qbe bugs M1 found.

**Bearing on safety.** In Fil-C mode a promoted local is no longer a heap
object, so its loads and stores lose their access checks. That is a
removal of checks, and it is sound only because every condition above is
established, never assumed: escape classification treats any use it does
not understand as an escape, and promote refuses unless every access is
inside the allocation, aligned and non-overlapping, so none of the
removed checks could have failed. A `p` value that was in a slot is now a
`p` temp, which the backend roots in its own frame slot, so rooting is
unchanged; the GC stress tests pass with `-O`, also under
`FUGC_SCRIBBLE=1 FUGC_VERIFY=1`. Keeping non-escaping arrays on the
stack (the `oobp` gap in [m4.md](m4.md#known-gaps)) is not done yet:
arrays indexed by a variable still escape here and stay on the heap.

## Translation validation

`main.pl -O difftest` runs every `# run:` line on both the unoptimized
and the optimized module in the interpreter, in the same `findall` step,
and fails unless the optimized outcome refines the original:

- undefined behaviour in the original allows anything;
- an unknown result (uninitialized bytes in plain mode) allows any value
  its constraints allow;
- otherwise the outcomes are equal. A returned pointer into an alloc
  compares by its offset in the object, since removing allocs moves the
  others.

Promote keeps every block and branch, so a correct result needs exactly
the fuel the original needs. Both run with the same fuel, growing from
1,000 blocks until the original finishes, so a broken pass that loops
ends as `out_of_fuel` cheaply. (The interpreter's memory grows fast with
blocks run: a loop of 10,000 blocks took 10 GB and 3 minutes, so a run to
the full 1,000,000 would exhaust memory before reporting.)

The optimized IR is also checked with `valid_module/1` there and in the
unit tests, not on every `cc -O`, because the validator is quadratic in
the number of blocks (11.7 s for a 1557-block function in the corpus).
That function, c-testsuite/00200, takes 21 s to compile without `-O`,
over the corpus check's 20 s limit, so the check now allows 60 s.
Computing each block's predecessors once in `valid_block` (ir.pl) would
bring `cc-ir` on it from 12.5 s to 5.3 s; ir.pl is shared, so that is
left to its owner.

The Nix check runs every existing suite again with `NANOFIL_OPT=-O`:
fixtures, qbe-bugs, the 200-function gen.py corpus, tests/filc,
tests/c, a 300-statement `bigfn.py` function, interop, GC stress, and
progtest including its scribble/verify run. Each difftest also validates
in the interpreter as above. The M4f corpus (`tests/corpus.py`) was run
with `-O` by hand and gives the recorded outcomes for all 416 sources.
It is not in the check twice because of its run time.

A broken promote that leaves every alloc in place would pass all of that.
`promote_removes_allocs` in [tests/unit.pl](../tests/unit.pl) pins which
allocs must go and which must stay, worked out by hand.

**Planted bugs**, each caught and then restored:

| bug | caught by |
| --- | --- |
| a narrow load does not re-extend (`loadsb` → `copy`) | `VALIDATION FAILED $narrow(128): ret 0 before, ret 256 after` |
| no phis (each block sees its dominator's value) | `$fact(10): ret 3628800 before, out_of_fuel after`, `$sw(3): ret 7 before, ret 3 after` |
| overlapping slots allowed | `$kept(10): ret 30064771105 before, ret 33 after` (the first fixture missed it; the overlap case was added for this) |
| slots start at 1, not 0 | `promote_reads_zero_in_filc` (C code never reads a local before writing it) |
| call arguments do not escape | `in $kept: undefined temporary %e` from `valid_module` |
| promote does nothing | `promote_removes_allocs`; difftest and progtest pass |

## Tabled, versioned or functional analyses

PLAN asked whether analyses should be tabled relations keyed on
versioned IR facts or incrementally tabled facts, at realistic sizes.
[tests/bench-cfg.pl](../tests/bench-cfg.pl) runs all three on the
largest function of each file and throws if they disagree;
[tests/bigfn.py](../tests/bigfn.py) generates structured C (nested
`if`/`for`, early returns, a dozen locals), so the functions have
hundreds of blocks and small live sets. CPU seconds, native Trealla
`12f4cbd`:

| function | scenario | functional | versioned facts | incremental |
| --- | --- | --- | --- | --- |
| 119 blocks, 504 temps | assert as facts | – | 0.021 | 0.014 |
| | dominators + frontiers | **0.025** | 1.46 | – |
| | temp liveness | 0.053 | 0.031 | 0.030 |
| | liveness after promote | 0.098 | 0.040 | 0.033 |
| | liveness after a one-instruction edit | 0.055 | 0.052 | 0.052 |
| 298 blocks, 1300 temps | assert as facts | – | 0.069 | 0.039 |
| | dominators + frontiers | **0.103** | 19.6 | – |
| | temp liveness | 0.208 | 0.185 | 0.185 |
| | liveness after promote | 0.266 | 0.185 | 0.107 |
| | liveness after a one-instruction edit | 0.227 | 0.181 | 0.195 |
| 887 blocks, 4458 temps | assert as facts | – | 0.343 | 0.136 |
| | dominators + frontiers | **0.311** | over 3 min | – |
| | temp liveness | 0.711 | 0.670 | 0.650 |
| | liveness after promote | 0.791 | 0.583 | 0.311 |
| | liveness after a one-instruction edit | 1.003 | 1.255 | 0.958 |

The answer:

- **Liveness: a wash.** The three-rule tabled liveness is never more than
  1.5× faster than an assoc worklist, and asserting the facts costs about
  what the tabled version saves. The first functional version (round-robin
  until nothing changed) was 2.4× slower at 298 blocks; a postorder
  worklist closed the gap.
- **Dominators: functional, by far.** Dominance has no short monotone
  Datalog form. The tabled one needs a reachability-avoiding-D table per
  block, so it grows with the cube of the size: 60× slower at 119 blocks,
  190× at 298, minutes at 887.
- **Incremental tabling buys little.** It wins after promote (fewer facts
  change than a version holds), but after a one-instruction edit it
  re-derives about as much as recomputing, because each of
  `i_live_in(_, _)` and `i_live_out(_, _)` is one table that any changed
  fact invalidates whole.

So passes use cfg.pl: pure, no asserted state, and no driver-level
version bookkeeping. The "versioned facts at pass boundaries" exception in
PLAN's rules is not needed by M5. cfg_tabled.pl stays as the declarative
specification the functional code is checked against in the Nix check.

**A Trealla tabling bug.** In `12f4cbd`, a `\+` or if-then-else written
inline after a tabled call, in a tabled clause, gives wrong answers. It
reported temps live into the block that defines them. The same negation
moved into a helper predicate is right:

```prolog
:- table li/2, lo/2.
li(B,T) :- g(B,T).
li(B,T) :- lo(B,T), \+ k(B,T).     % [b2-x,b1-x,b0-x]: b1 kills x, wrong
lo(B,T) :- li(S,T), p(S,B).
g(b2,x). k(b1,x). p(b2,b1). p(b1,b0).
```

With `li(B,T) :- lo(B,T), notk(B,T).` and `notk(B,T) :- \+ k(B,T).` the
answer is `[b2-x]`. cfg_tabled.pl uses the helper form. This matters to
anyone who writes tabled analyses with negation, as the handoff proposed.

## Host: SWI-Prolog

The measurements above are on Trealla. After M5 the default host became
SWI-Prolog 9.2.9 (PLAN decision 3), with `src/swi/` adapting it to the
Trealla dialect and `bin/nanofil` choosing the host. Output is identical
on both hosts: the gen1 assembly, the IR of every `tests/c` file, and the
corpus outcomes. Wall-clock times, Trealla against SWI:

| run | Trealla | SWI |
| --- | --- | --- |
| difftest `memory.ssa` (interpreter) | 15.7 s, 3.5 GB | 0.6 s, 35 MB |
| difftest gen1 (200 functions) | 16.0 s | 1.7 s |
| compile gen1 | 1.9 s | 0.4 s |
| pptest | 25 s | 5.6 s |
| corpus (parallel) | 60 s | 18 s |
| bench-cfg on big2.c | 2.1 s | 0.4 s |
| whole Nix check | about 215 s | 81 s, with a 12 s Trealla step |

Most of the interpreter's time went to CLP(Z) propagation on values that
were already integers. The interpreter now computes known values with
`is/2` and branches on them with if-then-else, keeping constraints for
unknown values, and `prepare/2` indexes functions and blocks once per
module. Results are identical; difftest got 2 to 4 times faster on SWI
(gen1 with -O: 3.2 s to 0.8 s, about 0.3 s of it startup) and 13 times
on Trealla (`memory.ssa`: 15.7 s to 1.2 s). `NANOFIL_PROFILE=N` runs any
nanofil command under SWI's profiler and prints the top N predicates.

### Compiler profiling after the interpreter fast path

The next pass targets compiler work, without changing the IR or emitted
code. On swa with SWI 9.2.9, medians of five separate invocations against
the preceding revision
([e669408ad01c](https://github.com/mbrock/filnix/commit/e669408ad01c)):

| command / input | before | after |
| --- | --- | --- |
| `check tests/fixtures/calls.ssa` (mostly startup) | 0.20 s | 0.10 s |
| `cc tests/c/prog/hello.c` (system headers) | 0.71 s | 0.58 s |
| `cc` c-testsuite/00200.c (1557 blocks) | 1.08 s | 0.76 s |
| `cc` bigfn.py 1 300 | 0.38 s | 0.28 s |
| `-O cc` bigfn.py 1 300 | 0.38 s | 0.29 s |
| `cc` bigfn.py 1 3000 | 2.24 s | 1.63 s |
| `-O cc` bigfn.py 1 3000 | 3.32 s | 1.79 s |
| `compile` gen.py 1 200 | 0.33 s | 0.25 s |

Each pair produced byte-identical output. Input generation and Prolog
profiling are outside these wall-clock measurements; startup, target
profile discovery and printing are included. Peak RSS did not increase:
for example, hello.c fell from 163 to 146 MiB. These are local machine
measurements, not directly comparable to the earlier orb timings.

The changes follow the profiles:

- **Startup:** compile-only commands were loading the interpreter and
  CLP(Z), although neither runs. SWI now autoloads the interpreter on
  first use; Trealla still loads it normally. The IR module's unused
  CLP(Z) import is gone. Symbolic runs still use the same solver.
- **Preprocessing:** `located_splice/4` was a leading cost on hello.c.
  It now shares one `File:Line` term per physical line instead of
  constructing one per character; splices and token locations are
  unchanged. No header or target-profile cache was added.
- **Backend:** `nth0` scans for pollchecks took 26% of profiled
  compilation of 00200.c. The Fil-C backend indexes block positions and
  phis once, then looks up both ends of each edge. It still tests layout
  order, including self-edges, not lexical label order, and emits the
  same checks and phi copies.
- **Promotion:** on bigfn.py 1 3000, collecting each slot's store blocks
  took 51% of the profiled pass and escape-event classification another
  15%. Both now group their input once by slot/allocation; assembly uses
  the existing phi assoc rather than searching its original list.
  Stable event order preserves the first escape reason. No promotion
  eligibility, liveness or dominance rule changed. Profiling just
  `promote_module/2` fell from 1.58 to 0.55 CPU seconds; assoc lookups
  fell from 2.31 million to 0.30 million.

The full Nix check, forced to build locally on swa both times, passed
in 31 seconds versus 38 before, including the unchanged Trealla checks.
Separate validation compared 92 complete assembly/IR outputs against the
old compiler: the existing C and IR fixtures, three extra 1000-statement
seeds (2, 3, 17), and a case with a self-edge, non-lexical block order,
an unreachable phi predecessor and an unused allocation, all with and
without `-O`. All were byte-identical. Full preprocessing token terms
also matched for LF/CRLF splices and multiline comments, including their
locations. No permanent tests were added for these representation-only
changes; the existing semantic and GC-stress suites still apply.

To repeat the compile profiles, generate the inputs with `tests/bigfn.py`
or `tests/gen.py`, then run, for example:

```sh
NANOFIL_PROFILE=25 bin/nanofil -O cc big.c >/dev/null
# Measure separately without the profiler:
/usr/bin/time -f '%e s, %M KiB peak RSS' bin/nanofil -O cc big.c >/dev/null
```

### Removing the address-chain scaling cliff

The staging Fil-C compiler already contains
[the frame-coloring fix](https://github.com/mbrock/fil-c/commit/92c381beeb23a2584afb9b134cf91b180b54f7da):
at `-O0`, always-live allocas made a dense interference graph, and trying
colors by repeatedly scanning neighbors made coloring cubic. That fix
represents the dense relation implicitly. Nanofil does not have frame
coloring yet, but the lesson applies to its existing analyses too.

`escape:address_temps/2` used to rescan every constant-offset definition
until a fixed point. A chain of N pointer additions resolved one more
temporary per round: N whole-function scans even if the definitions were
already in dependency order. At 500/1000/2000/4000 links, it used
1.80/7.09/28.18/112.36 million Prolog inferences. That is quadratic work,
not just a large constant.

It now indexes outgoing dependencies by source temp and processes only
the newly resolved sources. Every edge is visited once, with logarithmic
assoc operations. Breadth-first layers preserve the old result when
definitions compete: earliest resolved layer wins, then original
instruction order. Already-resolved temps never change, and unrooted
cycles stay unresolved. This changes neither the escape policy nor
promotion eligibility; it makes this part of M5 scale before adding more
alias and copy analysis.

Complete `-O compile` wall time on SWI 9.2.9, swa, medians of three runs
against [248807c](https://github.com/mbrock/filnix/commit/248807c48618d2550c5e3f8093ee8b9d438cae41):

| pointer additions | before | worklist |
| --- | --- | --- |
| 1000 | 0.92 s | 0.13 s |
| 2000 | 3.45 s | 0.17 s |
| 4000 | 14.01 s | 0.24 s |

The 4000-link address analysis alone went from 5.14 s to 0.028 s;
16000 links now take 0.118 s. Assembly is byte-identical at each measured
compile size. Peak process memory at 4000 links is still about 39 MiB.

Validation compared the complete address maps and escape classifications
on 2086 functions: existing IR fixtures, 2000 seeded generated graphs,
20 shuffled 100-link chains and a directed conflict/cycle case. All
matched the old analysis exactly. A deliberately broken copy that omitted
the instruction-order tie-break differed on the first case, so the
comparison detects that mistake. Trealla also produces the same assembly
for the 1000-link compile. The full Nix check retains the semantic and
GC-stress coverage.

Reproduce the compiler scaling input without a separate generator:

```sh
python3 - 4000 > chain.ssa <<'PY'
import sys
n = int(sys.argv[1])
print('export function w $chain() {\n@start')
print(f'    %0 =p alloc8 {n + 1}')
for i in range(1, n + 1):
    print(f'    %{i} =p add %{i - 1}, 1')
print(f'    storeb 42, %{n}\n    %result =w loadub %{n}\n    ret %result\n}}')
PY
/usr/bin/time -f '%e s, %M KiB' bin/nanofil -O compile chain.ssa > chain.s
```

## Not done

- Copy elimination, alias analysis and loops (the rest of PLAN's M5).
  Promote leaves `copy` instructions where loads were.
- The symbolic before/after equivalence query on small functions. The
  validation here is on concrete runs only.
- Keeping non-escaping arrays on the stack (`ALoc` allocs that promote
  cannot turn into temps). That needs a backend change, so that such
  objects live in the stack frame and are checked against their exact
  size, as clang does at `-O1` (see the `oobp` gap in m4.md).
