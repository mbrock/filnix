# M7: reusing access-check evidence

This is M7's first deliverable ([PLAN.md](../PLAN.md#m7-safety-obligations-and-alternative-evidence)):
one narrowly specified alternative to repeated runtime checking. A heap
access check's proof may cover later scalar accesses through the same
pointer, in the same block (round 1) or along CFG edges (round 2), as
long as nothing on any path in between can change what the check
established. Everything else keeps its adjacent check. The
pass is off by default (`--checks=reference`); `--checks=reuse` or
`NANOFIL_CHECKS=reuse` selects it, and the reference path stays the
differential reference.

## The obligation

A raw scalar access `raw_load(T, Off)` or `raw_store(W, Off, V, A)` at a
proof A requires, at the moment it executes:

| Fact | Means |
| --- | --- |
| identity | A's capability is the capability of the pointer P the source access used |
| range | `[P+Off, P+Off+Size)` lies within that object's current bounds |
| rights | write rights for a store (the object is not read-only); read for a load |
| alignment | `P+Off` is aligned as the access requires (1 for every scalar) |
| lifetime | the object is not freed; free empties its bounds, so this is part of range |

Before M7 one proof discharged one access: `check(Lo, Hi, Rights, Align)`
on P, immediately followed by the raw access that reads its result. The
reference path still produces exactly that.

## Evidence

A proof `tmp(Q)` defined by `let(tmp(Q), a, check(Lo, Hi, R, Al), [P])`
in block B establishes those facts for P's value (address and
capability) and the object's state when the check ran, for every access
the check covers (`ir:covered_access/6`). The facts stay true until one
of these happens:

| Invalidator | Why |
| --- | --- |
| any call (`call`, `raw_call` and its `check_function`, external, `free`), `setjmp`, `va_arg` | may free the object, or return twice |
| `alloc`, `local_alloc` | `filc_allocate` may exit and run deferred signal handlers |
| a pointer store (`raw_store_pointer`) | ensure-aux may exit |
| a getter (`let(_, p, copy, [global(_)])`), `va_args` | conservatively |
| a redefinition of Q, or of P (hand-written IR may redefine a temp) | the proof no longer names the same value |
| a poll edge, or an edge from a block later in block order | see [Across edges](#across-edges-round-2) |
| a phi whose destination is Q or P | a redefinition, on the edge |

The instructions that preserve evidence are a closed list
(`ir:evidence_preserving/1`): pure `let`s (integer and float arithmetic,
comparisons, extensions, conversions, `ptoi`, non-symbol `copy`),
`flight`, `loc`, heap checks, `check_local` with its access, scalar
`raw_load` and `raw_store`, and raw pointer loads with one of the closed
heap or local load effect lists. None calls a helper
or reaches a safepoint. A scalar store cannot change any object's
bounds, rights or lifetime: upper and flags sit in the header below the
lower, outside every capability's range. A pointer load reads aux and
box words only (`pointer_load_effect//4`). Atomics, fences and volatile
accesses, if they are ever added, must stay off the list.

Merge: see [Across edges](#across-edges-round-2) (in round 1 the facts
at block entry were none). Transfer: a heap check adds
its proof once its first access has run; a preserving instruction keeps
every fact except those naming the temporary it defines; anything else
empties the set. No fact exists without a check that ran at the original
access's place.

## Checked IR contract

No new term. `ir:checked_insts/5`'s acceptance rule changed:

1. Every check is still immediately followed by a first use it covers.
   Checks are never moved or widened beyond their first access, which is
   what keeps trap timing.
2. A heap check's proof may also be read by later **scalar** raw accesses
   that it covers, where the validator's own dataflow (below) shows the
   evidence live: on every path from the check, only preserving
   instructions and plain edges, and neither Q nor P redefined.
3. Proofs still never reach phis, parameters, call arguments, results or
   memory. Local and function
   proofs keep immediate single use; a pointer access never reads a
   reused proof.

## Interpreter contract

Unchanged. A raw access evaluates its proof's captured value and checks
the access against the capability's **current** region state; a
violation is `unchecked(Why)`, not a trap. Stale evidence after a modeled
`free` and too narrow or read-only evidence therefore show up as
`unchecked`, which refines nothing. Evidence about the wrong object is
safe, so it shows up only as a changed outcome. Effects the interpreter
abstracts (polls, allocation exits, ensure-aux, concurrent free) are
covered by the validator's invalidator list and by native GC tests.

## Emitter contract

`fused_blocks/5` keeps `fused(Check, Access)` for each check and its
first use. A later scalar raw access at proof Q becomes `reused(Access)`,
Access at the check's operand P: emission loads P's address from its
rooted slot and performs the access without a check. Its liveness view
reads P, so P stays live, and its slot unshared, until its last reused
access. The emitter forgets a proof once Q or P is redefined, including
by a fused access or call, because it reloads P where the interpreter
reads Q's captured value; it throws on a
reused access at a nonzero offset, which pizlonation never produces. It
does not repeat the validator's invalidator analysis.

## The pass

`check_reuse:reuse_checks/2` runs after pizlonation. It walks each block
forward (entry facts per [Across edges](#across-edges-round-2)) with the facts `avail(P, Q, Lo, Hi, Rights, Align)` and deletes a
heap check whose first use is a scalar raw access when an available proof
of the same operand P **subsumes the deleted check itself** (range,
rights, alignment), not just its access, and when the deleted proof has
one definition and one reader in the function (round 2; round 1 asked
only that nothing later in the block read it); the access then reads
that proof. It never widens a check or adds one. Its transfer function
(`transparent/1`) is stated separately from the validator's
`evidence_preserving/1`. Context sites follow the instructions, and
`alias(Q, tmp(Q1), none, Os)` records which proof replaced a deleted one.

`check_reuse:reuse_refines/2` is the independent identity check the
driver applies after the pass: the output is the input less deleted
heap checks, each of whose single access now reads either an earlier
proof in its block or a function-wide singly defined proof, of the same
operand, whose check subsumes the deleted one; and the deleted proof had
one definition and one reader.
`valid_module/1` then checks the safety rule. A rewiring to another
object's proof is safe, so only this check rejects it.

## Observation contract

The same outcomes as the reference checked module on every interpreted
run, traps and their reasons included, and the same block count. A
deleted check would have succeeded: its proof's check succeeded on the
same capability and address with at least its range and rights, and
nothing between could change the object's bounds, rights or lifetime.
Deterministic executions are unchanged. A free by another thread, racing
without synchronization with the later access, may lose its trap; Fil-C
already tolerates that race between any check and its access
([pizlonation.md](pizlonation.md)), the memory cannot be reclaimed while
P is rooted, and no trap is added or moved earlier.

## Evidence

The reference path's 1032 snapshot outputs are byte-identical to the
preceding compiler's. With reuse, the Nix check runs difftest (unchecked
vs reused interpretation, and native) on the Fil-C fixtures, `tests/c`
and `big1.c` with and without `-O`; the native ABI, GC, setjmp,
pointer-effect and exception fixtures and the programs under
`FUGC_SCRIBBLE=1 FUGC_VERIFY=1`; the corpus; and the GC fixtures with
`--registers=local`. Hello, zlib and Lua are built with `--checks=reuse`
too and must match filcc.

`tests/filc/reuse.ir` has one function per mistake: a call (free) between

## Review

Oracle reviewed the design before implementation and found it safe. It
required three changes, all made: subsumption against the deleted check
rather than its access (a hand-written wider or write check would
otherwise lose its trap), forgetting a fact whose proof name is
redefined, and the emitter's own redefinition guard. It recommended
keeping `reuse_refines/2` as the wrong-object check, which interpreter
tests alone rarely discriminate.

Oracle then reviewed the implementation and found no blockers. It found
two gaps, both fixed with tests: `reuse_refines/2` accepted a rewiring
when the deleted proof's name was read again later (reachable only from
hand-written checked IR, since pizlonation names proofs freshly), and the
emitter's guard ignored definitions made by a fused first access. On its
advice the pointer-load entry is tied to the closed load effect lists.

For round 2, Oracle reviewed the design (four spec findings, folded into
the section below) and then the result. The result review found no
unsound case and two gaps, both fixed: the emitter's proof index counted
definitions once per check, quadratic on the default path too (a
3000-statement function spent 54 s in it; it now sorts the names once),
and no test exercised the emitter's guard that Q has one definition
(now in `reuse_edges`, and it fails with the guard removed).

## Across edges (round 2)

Round 2 lets evidence flow forward along CFG edges. The facts, the
intra-block transfer and the invalidators are unchanged. Only how a
block's entry facts are formed changes. Oracle reviewed this design
before implementation and found it sound; its four spec findings are
folded in below (marked *review*).

### Facts and lattice

The facts are the same as within a block: `live(Q, P, Lo, Hi, Rights, Align)`
(validator) and `avail(P, Q, Lo, Hi, Rights, Align)` (pass). A fact is a
ground term, and two facts are equal only when they are identical. The
set of facts is ordered by inclusion; smaller sets are more conservative.

### Edges

| Edge | Facts it carries |
| --- | --- |
| `goto(L)` or a `branch` arm `L` | the source block's exit facts |
| `goto(poll(L))` or a `branch` arm `poll(L)` | none |
| from a block not yet processed | none |

A **poll** may run deferred signal handlers, which may call `free`, and
it is a collector handshake. Spatial facts could in principle survive a
poll with a renewed temporal check, as FilPizlonator does, but nanofil's
facts are not split into spatial and temporal parts. So a poll kills
every fact. Pizlonation polls every edge to a block at or before its
source, so every back edge carries nothing and no fact is ever carried
around a loop.

### Merge and order

Blocks are processed once, in the order of the function's block list.
A block's entry facts are the **intersection** over every incoming
**edge**, from every predecessor including unreachable ones, of the facts
that edge carries. Edges are not deduplicated per predecessor:
`branch(V, poll(L), L)` contributes a polled and a plain edge, and the
polled one empties the intersection (*review*). A block with no
incoming edge starts with none; the intersection of no sets is empty,
not everything (*review*). The phis' destinations then kill the facts
that name them, matching P through its `tmp/1` wrapper (*review*). No
iteration is needed: an edge from a block not yet processed carries
nothing, which can only lose facts. By induction on the order, every
computed fact holds on every path. In pizlonated IR every
not-yet-processed predecessor reaches the block through a polled edge,
so this single pass loses nothing.

### Acceptance

The validator (`ir:stage_func/4`, `checked_block/5`) computes its own
entry sets this way from its own `evidence_preserving/1`, independently
of the pass. A scalar raw access in any block may read a live proof that
covers it. Its facts need no uniqueness: redefinitions are killed on
each path.

The pass computes `avail` with its own `transparent/1` and its own edge
rule. Facts cross an edge only when Q has exactly one definition and P
at most one, counting parameters, phis and every instruction form
(`ir:temp_defs/3`), the same condition the emitter needs (*review*). It
deletes a check only when its proof has one definition and one reader
in the whole function; this replaces round 1's block-local rule.

`reuse_refines/2` becomes function-wide: a rewired access must read a
uniquely defined heap check of the same operand that subsumes the
deleted check, and the deleted proof must have had no other reader. Its
availability on every path remains the validator's question.

### Emission

A reused access in another block reloads P. To be correct it needs P to
hold the value that was checked, so the emitter accepts a cross-block
reuse only when Q and P each have at most one definition in the
function (a parameter counts as one). With strict SSA, a reachable use
of Q is dominated by Q's check, and P's single definition dominates that
check, so the reload yields the checked value. Liveness reads P at the
reused access, so P stays live, rooted and unshared across the edges.

The emitter's own guard (`single_proofs/3`) counts definitions the
same way; a cross-block reuse that fails it falls through to the
unchecked-access error, never to a reload of a different value.

### Tests

`reuse_edges` (unit) accepts reuse across a plain edge and through a
diamond, and rejects, in the validator:

- **Branch-only evidence:** q proves 8 bytes on one arm and 4 on the
  other (hand-written, so q dominates the join); the 8-byte read after
  the join is rejected. A check only on one arm does not even dominate.
- **Free on one path**, with the freeing block before and after the
  join in block order.
- **Loop-carried staleness:** a preheader check, a back edge after a free.
- A forward poll edge, `branch(V, poll(L), L)`, and a phi redefining P.

The pass keeps the join's check after a free on one path and in a loop,
deletes it in a diamond, and all three modules (unchecked, checked,
reused) give the same outcomes; it carries nothing over a poll edge and
rewires nothing across an edge when P has two definitions. The emitter
refuses that case; refines rejects a deleted proof read in another
block. `tests/filc/reuse.ir` adds `diamond` and `loop_free` (difftest,
native); `reuse-gc.ir`'s `survive2` reuses p two blocks after its check
while a new pointer would take p's slot, under forced GC.

Planted cross-edge mistakes (unit, `difftest reuse.ir` and `run-c
reuse-gc` with reuse on):

| Planted mistake | Caught by |
| --- | --- |
| validator: union at merges | unit |
| validator: poll edges carry facts | unit |
| validator: ignore edges from later blocks | unit |
| validator: one edge per predecessor | unit |
| validator: phis keep facts | unit |
| pass: union at merges | unit, difftest (validator rejects) |
| pass: poll edges carry facts | unit |
| pass: ignore edges from later blocks | unit, difftest |
| pass: no single-definition filter | unit |
| refines: ignore the deleted proof's other readers | unit |
| emitter: P's definitions not counted | unit |
| emitter: Q's definitions not counted | unit (`reuse_edges`) |
| emitter: liveness does not read P (round 1 mistake, now across edges) | run-c (`survive2` 7501500 became 6003000) |

A pass whose phis keep facts is not separately observable: a phi that
redefines P gives P a second definition, so the single-definition
filter already drops the fact. The phi kill stays as the stated rule.

Static yield, the same 256 files (c-testsuite, `tests/c`,
`tests/c/prog`), emitted heap checks:

| --- | --- | --- | --- |

## Runtime effect (October 2026)

Measured at [`bf0e86d`](https://github.com/mbrock/filnix/commit/bf0e86da0f88)
on swa (Ryzen 9 7950X3D, not a VM). Each program was built by nanofil in
four modes through `nanofil-cc`, as the Nix checks build them, plus a
filcc `-O2` reference. Every nanofil binary's output was first checked
byte for byte against the reference on 4 MB of text and of random data,
including bzip2 and lz4 with reuse, which their Nix checks did not then build.
Then 7 trials after one warm-up, modes shuffled within each trial, pinned
to one core, `perf stat` user instructions and task-clock; medians.

| Workload | off → reuse, time | instructions | `-O` → `-O` reuse, time | instructions |
| --- | ---: | ---: | ---: | ---: |
| zlib `-6` text | −1.2% | −2.0% | +0.1% | 0.0% |
| zlib `-d` text | **−4.6%** | −7.2% | −3.9% | 0.0% |
| bzip2 `-9` text | **−6.4%** | −10.5% | −0.3% | 0.0% |
| bzip2 `-d` text | **−4.7%** | −7.1% | +0.7% | 0.0% |
| lz4 `-1` random | +0.3% | −5.0% | −0.6% | 0.0% |
| lz4 `-9` text | −0.9% | −3.3% | −0.8% | 0.0% |
| lz4 `-d` text | −1.0% | −4.2% | +0.8% | 0.0% |
| Lua integer loop | +1.5% | −1.8% | +0.3% | 0.0% |
| Lua table reads | −3.0% | −1.2% | −1.1% | 0.0% |
| Lua strings and sort | −0.5% | −0.5% | −0.9% | −0.2% |

With `-O`, reuse changes executed instructions by at most 0.2%, yet
times still move by up to 3.9% with separated trial ranges (zlib
`-d`): that is code layout, and it sets the noise floor. Only the three
bold rows, each with a 7–10% instruction drop, are clearly above it.
So reuse helps unoptimized code by up to about 6% and does nothing
measurable after `-O`, where nearly every access has its own flight
pointer and no earlier proof of the same SSA pointer.

For scale, filcc's `-O2` was 5–28× faster than nanofil without `-O`,
and 2–7× faster than nanofil `-O` (e.g. bzip2 `-9`: 0.29 s, 3.01 s,
1.08 s). The gap is general code quality, not checks.

## Related pointers (round 3, proposed)

Not implemented; this is the contract for perf.md item 6c-1. With `-O`
each field access has its own flight from the struct pointer, so the
same-SSA-pointer rule finds almost nothing (the runtime-effect table
above: 0.0% of instructions). Round 3 relates a check's pointer to an
earlier proof's pointer when both are constant offsets from one root,
and changes nothing else: the evidence facts, invalidators, edges,
merge and the validator's acceptance rule stay as in rounds 1 and 2.

### Relation

`base(X) = R + K` when `tmp(X)` has exactly one definition in the
function and it is `flight(tmp(X), add, [address(B), const(K0)],
lower(B))`, `sub` with `-K0`, or `copy` with `[address(B)]` and K0 = 0,
with the same B as address and lower donor, and B a temporary with one
definition; then `base(X) = base(B) + K0`. Any other pointer P has
`base(P) = P + 0`. P and P1 are **related with distance D** when
`base(P) = R + K`, `base(P1) = R + K1`, R is the same singly defined
temporary (or P == P1, D = 0), and `D = K − K1`. Then P and P1 have
R's capability (exactly, by `lower(B)` at every step), and P's address
is P1's plus D in unsigned 64-bit arithmetic, which is how `flight`
computes addresses. The walk from P to R carries a visited set and
stops at a cycle (*review*: an unreachable block may hold a
self-referential flight, which the validator accepts and on which the
prototype did not terminate).

Why it holds at the deleted check S (*review*; a single static
definition can run many times, so "single definition" alone is not the
argument): the input is validated before the pass, so every reachable
use is dominated by its single definition. If R's definition ran again
after P's chain was last computed and before S, some path from entry to
S would avoid P's definition, contradicting its dominance of S; the
same holds for each intermediate flight. On P1's side, Q1's fact
reaches S only along plain forward edges, and a rerun of R between
Q1's check and S would sit in a block whose entry evidence contains Q1,
which by the validator's round-2 induction is impossible since R's
block dominates Q1's. So at S both carry R's current capability and
their addresses differ by D, at reachable points only.

### The pass

A heap check `check(Lo, Hi, Rights, Align)` of P whose first use is a
scalar access at offset Off may be deleted when an available fact
`avail(P1, Q1, Lo1, Hi1, Rights1, Align1)` has P1 related to P with
distance D and subsumes `check(Lo + D, Hi + D, Rights, Align)`, and the
deleted proof has one definition and one reader (round 2). The access
is rewritten to read Q1 at offset `Off + D`. Subsumption is against
the deleted check shifted by D, not against its access, as before.

### Acceptance

Unchanged. The rewritten access reads Q1 at `Off + D`, which the
validator accepts only if Q1's live check covers `[Off + D, Off + D +
Size)` with its rights and alignment (`covered_access/6`). So the
validator alone establishes that the access stays inside Q1's checked
range, whatever the pass did. `reuse_refines/2` gains the relation:
the rewired access must read a proof whose pointer is related to the
deleted check's pointer with exactly the distance by which the offset
changed, and that proof's check must subsume the shifted deleted
check. That is the identity side (same object, same address), which
the validator does not see; the shifted subsumption is also what keeps
the trap of a hand-written check wider than its access. The relation
code is shared by the pass and `reuse_refines/2` (*review*), so a bug
in it defeats both; unit tests therefore hand `reuse_refines/2` modules
rewired by a wrong distance and a wrong root, and the planted relation
bugs must be caught by difftest values. The provenance record
`alias(Q, tmp(Q1), none, Os)` gains the distance, so explanations do not
claim Q's address equals Q1's.

### Interpreter

Unchanged. A raw access at `Q1 + (Off + D)` evaluates Q1's captured
pointer plus the offset against the capability's current state, so a
wrong distance shows up as a changed value or `unchecked`, and stale
evidence as `unchecked`.

### Emission

`fused_insts/5` stops throwing on a reused access at a nonzero offset
when the offset fits a signed 32-bit immediate (else it still throws).
`reused(Access)` loads P1's address from its rooted slot, adds the
offset (`add $Off, %rax`), then emits the access at offset 0. The
liveness view reads P1, so P1 stays live and rooted until the last
access that reuses it; the emitter's redefinition guard and
single-definition rule for P1 (round 2) apply unchanged. P itself may
then be dead, which is fine: nothing reads it.

### Observation contract

Unchanged from rounds 1 and 2. A deleted check would have succeeded:
an earlier check of the same capability already succeeded on a range
containing the shifted one, with at least its rights and alignment,
and nothing in between could free the object, change its bounds or
rights, or reach a safepoint. No check moves, widens or is added, so
every trap happens at the same access with the same text. Racing free
is the same tolerated race as before.

### Tests and plants

- Unit: a field read after another field's check is rewired at the
  right offset; rejected when the two flights have different lower
  donors, different roots, a root or flight with two definitions, a
  distance that takes the access outside the proof's range (validator),
  a read proof for a store, and across a call or poll.
- `tests/filc/reuse.ir`: fields at offsets 0, 4 and 8 of one object,
  holding distinct values (so a dropped `add` or an ignored K changes
  the output), a free between, and an out-of-bounds field after an
  in-bounds one, which must still trap at the second access. A later
  field's check first keeps the earlier field's check: pizlonated
  checks have Lo = 0, so a negative distance never deletes in emitted
  code (*review*); a hand-written unit case with Lo1 < 0 exercises a
  real negative-distance reuse in the interpreter.
- Termination: unreachable self-referential and two-cycle flights.
- Shapes: chained flights (`(R+4)+4` against `R+8`), `sub` and `copy`
  flights, a parameter root, a loop-header phi root with fields read
  on both sides of the back edge, a wrapping constant (`2^64−8`
  against `−8`, which must only fail to match), and a related field
  read across a plain edge (rounds 2 and 3 together), natively.
- `reuse-gc.ir`: a reused related access is the only reader keeping P1
  live while a new pointer would take its slot, under forced GC.
- Plants: relation ignores the lower donor; relation ignores K
  (distance 0 always); pass compares the unshifted check; refines
  accepts any distance; emitter drops the `add`. Each must be caught by
  unit, difftest `reuse.ir` or `run-c reuse-gc`.
- Gate: the bench in `O-reuse`, and the ten Nix checks, which build
  every program with `--checks=reuse` too.

### Review

Oracle reviewed this contract and the prototype (`/tmp`, not
committed) and found no case in reachable, validated IR where an access
runs unchecked, a trap moves or changes text, the wrong address is
accessed or rooting breaks. It confirmed the emission (`add $Off,
%rax` after reloading P1, flags dead, no safepoint before the access,
liveness reading P1, the checkers knowing `add` with an immediate). Its
findings are folded in above, marked *review*: the soundness argument,
cycle termination, the shared relation code, provenance, negative
distance and the extra tests.

### Measured yield (prototype)

0–3.4% of instructions under `-O --checks=reuse` (perf.md item 6c), and
static heap checks over c-testsuite, `tests/c` and `tests/c/prog` with
`-O` go from 711 (round 2) to 643, against 770 with no reuse. It
changes nothing by default unless `--checks=reuse` becomes the `-O`
default, which is a separate decision.

## Limits

- Forward only: no motion, and no evidence around a loop, because every
  back edge polls and a poll kills every fact. Splitting spatial from
  temporal facts would be needed to keep bounds across a poll.
- Across an edge, only proofs and pointers with a single definition.
- Scalar consumers only; pointer accesses always keep their check.
- Same SSA pointer only (until round 3, proposed above): a different
  flight to the same object or a constant offset from P is not related
  to P's proof.
- Read evidence never covers a write: no rights upgrade.
- Local (`check_local`) and function proofs are not reused.
- Polls, `alloc` and helper exits are trusted to the invalidator list
  and native tests; the interpreter models only explicit free.
