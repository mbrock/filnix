# M7: reusing access-check evidence

This is M7's first deliverable ([PLAN.md](../PLAN.md#m7-safety-obligations-and-alternative-evidence)):
one narrowly specified alternative to repeated runtime checking. A heap
access check's proof may cover later scalar accesses through the same
pointer, in the same block (round 1) or along CFG edges (round 2), as
long as nothing on any path in between can change what the check
established. Everything else keeps its adjacent check. The
pass is off by default (`--checks=reference`); `--checks=reuse` or
`NANOFIL_CHECKS=reuse` selects it, and the reference path stays the
differential reference.

## The obligation

A raw scalar access `raw_load(T, Off)` or `raw_store(W, Off, V, A)` at a
proof A requires, at the moment it executes:

| Fact | Means |
| --- | --- |
| identity | A's capability is the capability of the pointer P the source access used |
| range | `[P+Off, P+Off+Size)` lies within that object's current bounds |
| rights | write rights for a store (the object is not read-only); read for a load |
| alignment | `P+Off` is aligned as the access requires (1 for every scalar) |
| lifetime | the object is not freed; free empties its bounds, so this is part of range |

Before M7 one proof discharged one access: `check(Lo, Hi, Rights, Align)`
on P, immediately followed by the raw access that reads its result. The
reference path still produces exactly that.

## Evidence

A proof `tmp(Q)` defined by `let(tmp(Q), a, check(Lo, Hi, R, Al), [P])`
in block B establishes those facts for P's value (address and
capability) and the object's state when the check ran, for every access
the check covers (`ir:covered_access/6`). The facts stay true until one
of these happens:

| Invalidator | Why |
| --- | --- |
| any call (`call`, `raw_call` and its `check_function`, external, `free`), `setjmp`, `va_arg` | may free the object, or return twice |
| `alloc`, `local_alloc` | `filc_allocate` may exit and run deferred signal handlers |
| a pointer store (`raw_store_pointer`) | ensure-aux may exit |
| a getter (`let(_, p, copy, [global(_)])`), `va_args` | conservatively |
| a redefinition of Q, or of P (hand-written IR may redefine a temp) | the proof no longer names the same value |
| a poll edge, or an edge from a block later in block order | see [Across edges](#across-edges-round-2) |
| a phi whose destination is Q or P | a redefinition, on the edge |

The instructions that preserve evidence are a closed list
(`ir:evidence_preserving/1`): pure `let`s (integer and float arithmetic,
comparisons, extensions, conversions, `ptoi`, non-symbol `copy`),
`flight`, `loc`, heap checks, `check_local` with its access, scalar
`raw_load` and `raw_store`, and raw pointer loads with one of the closed
heap or local load effect lists. None calls a helper
or reaches a safepoint. A scalar store cannot change any object's
bounds, rights or lifetime: upper and flags sit in the header below the
lower, outside every capability's range. A pointer load reads aux and
box words only (`pointer_load_effect//4`). Atomics, fences and volatile
accesses, if they are ever added, must stay off the list.

Merge: see [Across edges](#across-edges-round-2) (in round 1 the facts
at block entry were none). Transfer: a heap check adds
its proof once its first access has run; a preserving instruction keeps
every fact except those naming the temporary it defines; anything else
empties the set. No fact exists without a check that ran at the original
access's place.

## Checked IR contract

No new term. `ir:checked_insts/5`'s acceptance rule changed:

1. Every check is still immediately followed by a first use it covers.
   Checks are never moved or widened beyond their first access, which is
   what keeps trap timing.
2. A heap check's proof may also be read by later **scalar** raw accesses
   that it covers, where the validator's own dataflow (below) shows the
   evidence live: on every path from the check, only preserving
   instructions and plain edges, and neither Q nor P redefined.
3. Proofs still never reach phis, parameters, call arguments, results or
   memory. Local and function
   proofs keep immediate single use; a pointer access never reads a
   reused proof.

## Interpreter contract

Unchanged. A raw access evaluates its proof's captured value and checks
the access against the capability's **current** region state; a
violation is `unchecked(Why)`, not a trap. Stale evidence after a modeled
`free` and too narrow or read-only evidence therefore show up as
`unchecked`, which refines nothing. Evidence about the wrong object is
safe, so it shows up only as a changed outcome. Effects the interpreter
abstracts (polls, allocation exits, ensure-aux, concurrent free) are
covered by the validator's invalidator list and by native GC tests.

## Emitter contract

`fused_blocks/5` keeps `fused(Check, Access)` for each check and its
first use. A later scalar raw access at proof Q becomes `reused(Access)`,
Access at the check's operand P: emission loads P's address from its
rooted slot and performs the access without a check. Its liveness view
reads P, so P stays live, and its slot unshared, until its last reused
access. The emitter forgets a proof once Q or P is redefined, including
by a fused access or call, because it reloads P where the interpreter
reads Q's captured value. Since round 3 a reused access at a nonzero
offset reloads P and adds the offset; beyond 32 bits it throws. It
does not repeat the validator's invalidator analysis.

## The pass

`check_reuse:reuse_checks/2` runs after pizlonation. It walks each block
forward (entry facts per [Across edges](#across-edges-round-2)) with the facts `avail(P, Q, Lo, Hi, Rights, Align)` and deletes a
heap check whose first use is a scalar raw access when an available proof
of the same operand P **subsumes the deleted check itself** (range,
rights, alignment), not just its access, and when the deleted proof has
one definition and one reader in the function (round 2; round 1 asked
only that nothing later in the block read it); the access then reads
that proof. It never widens a check or adds one. Its transfer function
(`transparent/1`) is stated separately from the validator's
`evidence_preserving/1`. Context sites follow the instructions, and
`alias(Q, tmp(Q1), none, Os)` records which proof replaced a deleted one.

`check_reuse:reuse_refines/2` is the independent identity check the
driver applies after the pass: the output is the input less deleted
heap checks, each of whose single access now reads either an earlier
proof in its block or a function-wide singly defined proof, of the same
operand, whose check subsumes the deleted one; and the deleted proof had
one definition and one reader.
`valid_module/1` then checks the safety rule. A rewiring to another
object's proof is safe, so only this check rejects it.

## Observation contract

The same outcomes as the reference checked module on every interpreted
run, traps and their reasons included, and the same block count. A
deleted check would have succeeded: its proof's check succeeded on the
same capability and address with at least its range and rights, and
nothing between could change the object's bounds, rights or lifetime.
Deterministic executions are unchanged. A free by another thread, racing
without synchronization with the later access, may lose its trap; Fil-C
already tolerates that race between any check and its access
([pizlonation.md](pizlonation.md)), the memory cannot be reclaimed while
P is rooted, and no trap is added or moved earlier.

## Review

Oracle reviewed the design before implementation and found it safe. It
required three changes, all made: subsumption against the deleted check
rather than its access (a hand-written wider or write check would
otherwise lose its trap), forgetting a fact whose proof name is
redefined, and the emitter's own redefinition guard. It recommended
keeping `reuse_refines/2` as the wrong-object check, which interpreter
tests alone rarely discriminate.

Oracle then reviewed the implementation and found no blockers. It found
two gaps, both fixed with tests: `reuse_refines/2` accepted a rewiring
when the deleted proof's name was read again later (reachable only from
hand-written checked IR, since pizlonation names proofs freshly), and the
emitter's guard ignored definitions made by a fused first access. On its
advice the pointer-load entry is tied to the closed load effect lists.

For round 2, Oracle reviewed the design (four spec findings, folded into
the section below) and then the result. The result review found no
unsound case and two gaps, both fixed: the emitter's proof index counted
definitions once per check, quadratic on the default path too (a
3000-statement function spent 54 s in it; it now sorts the names once),
and no test exercised the emitter's guard that Q has one definition
(now in `reuse_edges`, and it fails with the guard removed).

## Across edges (round 2)

Round 2 lets evidence flow forward along CFG edges. The facts, the
intra-block transfer and the invalidators are unchanged. Only how a
block's entry facts are formed changes. Oracle reviewed this design
before implementation and found it sound; its four spec findings are
folded in below (marked *review*).

### Facts and lattice

The facts are the same as within a block: `live(Q, P, Lo, Hi, Rights, Align)`
(validator) and `avail(P, Q, Lo, Hi, Rights, Align)` (pass). A fact is a
ground term, and two facts are equal only when they are identical. The
set of facts is ordered by inclusion; smaller sets are more conservative.

### Edges

| Edge | Facts it carries |
| --- | --- |
| `goto(L)` or a `branch` arm `L` | the source block's exit facts |
| `goto(poll(L))` or a `branch` arm `poll(L)` | none |
| from a block not yet processed | none |

A **poll** may run deferred signal handlers, which may call `free`, and
it is a collector handshake. Spatial facts could in principle survive a
poll with a renewed temporal check, as FilPizlonator does, but nanofil's
facts are not split into spatial and temporal parts. So a poll kills
every fact. Pizlonation polls every edge to a block at or before its
source, so every back edge carries nothing and no fact is ever carried
around a loop.

### Merge and order

Blocks are processed once, in the order of the function's block list.
A block's entry facts are the **intersection** over every incoming
**edge**, from every predecessor including unreachable ones, of the facts
that edge carries. Edges are not deduplicated per predecessor:
`branch(V, poll(L), L)` contributes a polled and a plain edge, and the
polled one empties the intersection (*review*). A block with no
incoming edge starts with none; the intersection of no sets is empty,
not everything (*review*). The phis' destinations then kill the facts
that name them, matching P through its `tmp/1` wrapper (*review*). No
iteration is needed: an edge from a block not yet processed carries
nothing, which can only lose facts. By induction on the order, every
computed fact holds on every path. In pizlonated IR every
not-yet-processed predecessor reaches the block through a polled edge,
so this single pass loses nothing.

### Acceptance

The validator (`ir:stage_func/4`, `checked_block/5`) computes its own
entry sets this way from its own `evidence_preserving/1`, independently
of the pass. A scalar raw access in any block may read a live proof that
covers it. Its facts need no uniqueness: redefinitions are killed on
each path.

The pass computes `avail` with its own `transparent/1` and its own edge
rule. Facts cross an edge only when Q has exactly one definition and P
at most one, counting parameters, phis and every instruction form
(`ir:temp_defs/3`), the same condition the emitter needs (*review*). It
deletes a check only when its proof has one definition and one reader
in the whole function; this replaces round 1's block-local rule.

`reuse_refines/2` becomes function-wide: a rewired access must read a
uniquely defined heap check of the same operand that subsumes the
deleted check, and the deleted proof must have had no other reader. Its
availability on every path remains the validator's question.

### Emission

A reused access in another block reloads P. To be correct it needs P to
hold the value that was checked, so the emitter accepts a cross-block
reuse only when Q and P each have at most one definition in the
function (a parameter counts as one). With strict SSA, a reachable use
of Q is dominated by Q's check, and P's single definition dominates that
check, so the reload yields the checked value. Liveness reads P at the
reused access, so P stays live, rooted and unshared across the edges.

The emitter's own guard (`single_proofs/3`) counts definitions the
same way; a cross-block reuse that fails it falls through to the
unchecked-access error, never to a reload of a different value.

### Tests

`reuse_edges` (unit) accepts reuse across a plain edge and through a
diamond, and rejects, in the validator:

- **Branch-only evidence:** q proves 8 bytes on one arm and 4 on the
  other (hand-written, so q dominates the join); the 8-byte read after
  the join is rejected. A check only on one arm does not even dominate.
- **Free on one path**, with the freeing block before and after the
  join in block order.
- **Loop-carried staleness:** a preheader check, a back edge after a free.
- A forward poll edge, `branch(V, poll(L), L)`, and a phi redefining P.

The pass keeps the join's check after a free on one path and in a loop,
deletes it in a diamond, and all three modules (unchecked, checked,
reused) give the same outcomes; it carries nothing over a poll edge and
rewires nothing across an edge when P has two definitions. The emitter
refuses that case; refines rejects a deleted proof read in another
block. `tests/filc/reuse.ir` adds `diamond` and `loop_free` (difftest,
native); `reuse-gc.ir`'s `survive2` reuses p two blocks after its check
while a new pointer would take p's slot, under forced GC.

Planted cross-edge mistakes (unit, `difftest reuse.ir` and `run-c
reuse-gc` with reuse on):

| Planted mistake | Caught by |
| --- | --- |
| validator: union at merges | unit |
| validator: poll edges carry facts | unit |
| validator: ignore edges from later blocks | unit |
| validator: one edge per predecessor | unit |
| validator: phis keep facts | unit |
| pass: union at merges | unit, difftest (validator rejects) |
| pass: poll edges carry facts | unit |
| pass: ignore edges from later blocks | unit, difftest |
| pass: no single-definition filter | unit |
| refines: ignore the deleted proof's other readers | unit |
| emitter: P's definitions not counted | unit |
| emitter: Q's definitions not counted | unit (`reuse_edges`) |
| emitter: liveness does not read P (round 1 mistake, now across edges) | run-c (`survive2` 7501500 became 6003000) |

A pass whose phis keep facts is not separately observable: a phi that
redefines P gives P a second definition, so the single-definition
filter already drops the fact. The phi kill stays as the stated rule.

`tests/c/prog`), emitted heap checks:

## Runtime effect (October 2026)

Measured at [`bf0e86d`](https://github.com/mbrock/filnix/commit/bf0e86da0f88)
on swa (Ryzen 9 7950X3D, not a VM). Each program was built by nanofil in
four modes through `nanofil-cc`, as the Nix checks build them, plus a
filcc `-O2` reference. Every nanofil binary's output was first checked
byte for byte against the reference on 4 MB of text and of random data,
including bzip2 and lz4 with reuse, which their Nix checks did not then build.
Then 7 trials after one warm-up, modes shuffled within each trial, pinned
to one core, `perf stat` user instructions and task-clock; medians.

| Workload | off → reuse, time | instructions | `-O` → `-O` reuse, time | instructions |
| --- | ---: | ---: | ---: | ---: |
| zlib `-6` text | −1.2% | −2.0% | +0.1% | 0.0% |
| zlib `-d` text | **−4.6%** | −7.2% | −3.9% | 0.0% |
| bzip2 `-9` text | **−6.4%** | −10.5% | −0.3% | 0.0% |
| bzip2 `-d` text | **−4.7%** | −7.1% | +0.7% | 0.0% |
| lz4 `-1` random | +0.3% | −5.0% | −0.6% | 0.0% |
| lz4 `-9` text | −0.9% | −3.3% | −0.8% | 0.0% |
| lz4 `-d` text | −1.0% | −4.2% | +0.8% | 0.0% |
| Lua integer loop | +1.5% | −1.8% | +0.3% | 0.0% |
| Lua table reads | −3.0% | −1.2% | −1.1% | 0.0% |
| Lua strings and sort | −0.5% | −0.5% | −0.9% | −0.2% |

With `-O`, reuse changes executed instructions by at most 0.2%, yet
times still move by up to 3.9% with separated trial ranges (zlib
`-d`): that is code layout, and it sets the noise floor. Only the three
bold rows, each with a 7–10% instruction drop, are clearly above it.
So reuse helps unoptimized code by up to about 6% and does nothing
measurable after `-O`, where nearly every access has its own flight
pointer and no earlier proof of the same SSA pointer.

For scale, filcc's `-O2` was 5–28× faster than nanofil without `-O`,
and 2–7× faster than nanofil `-O` (e.g. bzip2 `-9`: 0.29 s, 3.01 s,
1.08 s). The gap is general code quality, not checks.

## Related pointers (round 3)

Implemented (perf.md item 6c-1) from the reviewed contract below;
[Implementation](#implementation-round-3) records what differs. With `-O`
each field access has its own flight from the struct pointer, so the
same-SSA-pointer rule finds almost nothing (the runtime-effect table
above: 0.0% of instructions). Round 3 relates a check's pointer to an
earlier proof's pointer when both are constant offsets from one root,
and changes nothing else: the evidence facts, invalidators, edges,
merge and the validator's acceptance rule stay as in rounds 1 and 2.

### Relation

`base(X) = R + K` when `tmp(X)` has exactly one definition in the
function and it is `flight(tmp(X), add, [address(B), const(K0)],
lower(B))`, `sub` with `-K0`, or `copy` with `[address(B)]` and K0 = 0,
with the same B as address and lower donor, and B a temporary with one
definition; then `base(X) = base(B) + K0`. Any other pointer P has
`base(P) = P + 0`. P and P1 are **related with distance D** when
`base(P) = R + K`, `base(P1) = R + K1`, R is the same singly defined
temporary (or P == P1, D = 0), and `D = K − K1`. Then P and P1 have
R's capability (exactly, by `lower(B)` at every step), and P's address
is P1's plus D in unsigned 64-bit arithmetic, which is how `flight`
computes addresses. The walk from P to R carries a visited set and
stops at a cycle (*review*: an unreachable block may hold a
self-referential flight, which the validator accepts and on which the
prototype did not terminate).

Why it holds at the deleted check S (*review*; a single static
definition can run many times, so "single definition" alone is not the
argument): the input is validated before the pass, so every reachable
use is dominated by its single definition. If R's definition ran again
after P's chain was last computed and before S, some path from entry to
S would avoid P's definition, contradicting its dominance of S; the
same holds for each intermediate flight. On P1's side, Q1's fact
reaches S only along plain forward edges, and a rerun of R between
Q1's check and S would sit in a block whose entry evidence contains Q1,
which by the validator's round-2 induction is impossible since R's
block dominates Q1's. So at S both carry R's current capability and
their addresses differ by D, at reachable points only.

### The pass

A heap check `check(Lo, Hi, Rights, Align)` of P whose first use is a
scalar access at offset Off may be deleted when an available fact
`avail(P1, Q1, Lo1, Hi1, Rights1, Align1)` has P1 related to P with
distance D and subsumes `check(Lo + D, Hi + D, Rights, Align)`, and the
deleted proof has one definition and one reader (round 2). The access
is rewritten to read Q1 at offset `Off + D`. Subsumption is against
the deleted check shifted by D, not against its access, as before.

### Acceptance

Unchanged. The rewritten access reads Q1 at `Off + D`, which the
validator accepts only if Q1's live check covers `[Off + D, Off + D +
Size)` with its rights and alignment (`covered_access/6`). So the
validator alone establishes that the access stays inside Q1's checked
range, whatever the pass did. `reuse_refines/2` gains the relation:
the rewired access must read a proof whose pointer is related to the
deleted check's pointer with exactly the distance by which the offset
changed, and that proof's check must subsume the shifted deleted
check. That is the identity side (same object, same address), which
the validator does not see; the shifted subsumption is also what keeps
the trap of a hand-written check wider than its access. The relation
code is shared by the pass and `reuse_refines/2` (*review*), so a bug
in it defeats both; unit tests therefore hand `reuse_refines/2` modules
rewired by a wrong distance and a wrong root, and the planted relation
bugs must be caught by difftest values. The provenance record
`alias(Q, tmp(Q1), none, Os)` must not claim Q's address equals Q1's
when the distance is not 0.

### Interpreter

Unchanged. A raw access at `Q1 + (Off + D)` evaluates Q1's captured
pointer plus the offset against the capability's current state, so a
wrong distance shows up as a changed value or `unchecked`, and stale
evidence as `unchecked`.

### Emission

`fused_insts/5` stops throwing on a reused access at a nonzero offset
when the offset fits a signed 32-bit immediate (else it still throws).
`reused(Access)` loads P1's address from its rooted slot, adds the
offset (`add $Off, %rax`), then emits the access at offset 0. The
liveness view reads P1, so P1 stays live and rooted until the last
access that reuses it; the emitter's redefinition guard and
single-definition rule for P1 (round 2) apply unchanged. P itself may
then be dead, which is fine: nothing reads it.

### Observation contract

Unchanged from rounds 1 and 2. A deleted check would have succeeded:
an earlier check of the same capability already succeeded on a range
containing the shifted one, with at least its rights and alignment,
and nothing in between could free the object, change its bounds or
rights, or reach a safepoint. No check moves, widens or is added, so
every trap happens at the same access with the same text. Racing free
is the same tolerated race as before.

### Tests and plants

- Unit: a field read after another field's check is rewired at the
  right offset; rejected when the two flights have different lower
  donors, different roots, a root or flight with two definitions, a
  distance that takes the access outside the proof's range (validator),
  a read proof for a store, and across a call or poll.
- `tests/filc/reuse.ir`: fields at offsets 0, 4 and 8 of one object,
  holding distinct values (so a dropped `add` or an ignored K changes
  the output), a free between, and an out-of-bounds field after an
  in-bounds one, which must still trap at the second access. A later
  field's check first keeps the earlier field's check: pizlonated
  checks have Lo = 0, so a negative distance never deletes in emitted
  code (*review*); a hand-written unit case with Lo1 < 0 exercises a
  real negative-distance reuse in the interpreter.
- Termination: unreachable self-referential and two-cycle flights.
- Shapes: chained flights (`(R+4)+4` against `R+8`), `sub` and `copy`
  flights, a parameter root, a loop-header phi root with fields read
  on both sides of the back edge, a wrapping constant (`2^64−8`
  against `−8`, which must only fail to match), and a related field
  read across a plain edge (rounds 2 and 3 together), natively.
- `reuse-gc.ir`: a reused related access is the only reader keeping P1
  live while a new pointer would take its slot, under forced GC.
- Plants: relation ignores the lower donor; relation ignores K
  (distance 0 always); pass compares the unshifted check; refines
  accepts any distance; emitter drops the `add`. Each must be caught by
  unit, difftest `reuse.ir` or `run-c reuse-gc`.
- Gate: the bench in `O-reuse`, and the ten Nix checks, which build
  every program with `--checks=reuse` too.

### Review

Oracle reviewed this contract and the prototype (`/tmp`, not
committed) and found no case in reachable, validated IR where an access
runs unchecked, a trap moves or changes text, the wrong address is
accessed or rooting breaks. It confirmed the emission (`add $Off,
%rax` after reloading P1, flags dead, no safepoint before the access,
liveness reading P1, the checkers knowing `add` with an immediate). Its
findings are folded in above, marked *review*: the soundness argument,
cycle termination, the shared relation code, provenance, negative
distance and the extra tests.

### Implementation (round 3)

`check_reuse.pl`: `names_info/3` records each single-definition flight
from a singly defined base with the same address and lower donor;

provenance's `alias/4` without changing its grammar, so a nonzero
rewiring leaves Q as an eliminated value with no replacement.

rewiring always has distance 0: what round 3 finds there is the same
field reached by two flights (a reload of `p->c`). Nonzero offsets come

runs natively.

## Spatial evidence and renewal (round 4)

Rounds 1–3 treat a check's evidence as one fact that every safepoint
kills, so nothing survives a call, and nothing survives a loop's back
edge, which always polls. Checks are 18–39% of `-O`'s instructions
(perf.md, "Where we are now"), and bzip2 `-9` runs 539M of them against
filcc's 230M. This round splits the fact in two. The **spatial** part
(bounds and alignment) lasts as long as the object does. The
**temporal** part (not freed, and for a store not read-only) is renewed
at the access by a flag test. That test stands exactly where the full
check stood, so no check moves.

### Measured first

Method (scratch, not kept): the gate's workloads built with `-O`
(at `2f960d1` plus the emission fix `6bbc117`), a symbol at every block
label, callgrind's entry count per block, joined to a per-block
analysis of the same IR after pizlonation and `--checks=reuse`. For
every check that reuse leaves, it asks which rule would cover it:

- **d (this contract):** a heap check of the same root (round 3's
  relation: single-definition, constant-offset flights with the same
  lower donor), whose bounds and alignment subsume this check's, either
  earlier in the block or in a block that dominates it. Rights are
  ignored, since the renewal tests them. Functions with setjmp are
  excluded.
- **p:** a loop's steady state with rounds 1–3's kills, but the back
  edge's poll carrying facts. This needs a peeled first iteration, or a
  loop copy entered when the poll's slow path runs.
- **q:** as p, but with spatial facts that only a redefinition kills.
  This also needs peeling.
- **index:** what d leaves inside loops when the root is a flight with
  a variable offset (`block[i]`).

### The facts

| Fact | Holds when |
| --- | --- |
| spatial `span(Q1, P1, Lo, Hi, Align)` | heap check Q1 of P1's current value succeeded: the capability is non-null, P1+[Lo, Hi) was inside the object's bounds, and P1+Lo was Align-aligned |
| temporal `live(Q, P, Lo, Hi, Rights, Align)` | rounds 1–3's fact: in addition, the object has not been freed since, and Rights held |

**Lifetime lemma** (runtime, at the pin): an object's lower, upper and
read-only flag are written only when it is created (`filc_runtime.c`
2760, 2846, 2895, 8597) and by `free_impl` (3172–3194), which sets
`upper = lower` and the FREE flag. Nothing else writes upper or
read-only. `mprotect` changes no flags (10156). `munmap` of a whole
mapping frees the object (9955). Whole or partial, it remaps the range
anonymous read-write (`filc_unmap`, 9930–9953), so it faults nothing,
in the reference or here. The other flag
writes are FREE and WEAK_KEY (3640, `filc_runtime_inlines.h` 742). A
GC cycle never frees a rooted object, and P1 stays rooted in its frame
slot. So a span stays true for the same object until it is freed. The
FREE flag is set exactly when it is freed, whether by this thread at a
call, by a handler at a poll, or by another thread.

### The term

One new op, approved separately as a grammar change:

| Op | Class | Args | Meaning |
| --- | --- | --- | --- |
| `renew(Lo, Hi, Rights, Align)` | `a` | `[tmp(Q1)]` | checked stage: trap as `check(Lo, Hi, Rights, Align)` would if Q1's object is freed, or if Rights is `write` and it is read-only; otherwise a proof with Q1's value |

Like a check, it is followed immediately by its first access, which
reads the renew's own result `tmp(Q)` at offset 0, as a pizlonated
check's does. This slice allows **distance 0 only**: the deleted
check's pointer P and Q1's pointer P1 have the same address and lower
donor (round 3's relation with K = 0), so `%rax:%rcx` loaded from P1 is
exactly P (*review*: with a nonzero distance the fail call would report
P1, not P, and the term has no place for the distance).

### Acceptance (validator, independent of the pass)

`let(tmp(Q), a, renew(Lo, Hi, Rights, Align), [tmp(Q1)])` is accepted
iff all of these hold:

1. Q1 has exactly one definition, a heap `check(Lo1, Hi1, _, Al1)` of
   P1. Rights do not matter.
2. P1 has at most one definition, counting parameters, phis and every
   instruction form (`temp_defs/3`).
3. The function has no `setjmp`.
4. `Lo1 ≤ Lo < Hi ≤ Hi1`, `Al1 mod Align = 0` and
   `(Lo − Lo1) mod Align = 0`. Size `Hi − Lo` is positive, as the
   emitter requires (*review*).
5. The next instruction is an access it covers (`covered_access/6`),
   heap storage effects, as for `check`.

Strict SSA's existing check (`definitions_dominate`) already requires
Q1's single definition to dominate the renew; within a block, at an
earlier index. That is the whole availability rule: no dataflow and no
kill list.

`renew` is on `evidence_preserving/1` (a flag load and a branch to a
non-returning fail block). After its access it adds
`live(Q, tmp(P1), Lo, Hi, Rights, Align)`, so later scalar accesses may
reuse Q under rounds 1–3 (*review*).

*Why dominance suffices.* Let C be Q1's check and Y the renew, with C
dominating Y. Suppose some path from the last execution of C to Y
redefined P1. P1's single definition D dominates C, so a path from
entry to the first D avoids C. Join it to the segment from that later D
to Y, which also avoids C. The result is a path from entry to Y that
avoids C, which contradicts dominance. So at Y, P1 and Q1 hold the
values that C checked. Loops change nothing: each iteration's
re-execution of D is followed by C again before Y. `cfg_idoms` is an
iterative fixpoint, so irreducible CFGs are covered. `setjmp`'s second
return adds edges the CFG does not show, so functions with setjmp are
left out; inlining refuses setjmp in callee and caller, and an unwind
leaves the frame.

### Interpreter

`renew` runs the same `access_res/7` as `check` on Q1's captured value
`ptr(A, Cap)` with its own range, rights and alignment (*review*):

- a freed region traps `out_of_bounds`, the reference check's reason,
  since free empties the bounds;
- a write to `ro(_)` traps `readonly`;
- any other failure is `unchecked(span)`: the span the validator relied
  on was false, a validator or pass mistake, never a program trap;
- otherwise it yields `ptr(A, Cap)`.

So every lost span, bounds or alignment, shows as `unchecked` where the
reference traps or succeeds, and difftest catches it.

### Emission

`fused(renew(Lo, Hi, Rights, Align), Access)`:

    flight load of P1           ; address into %rax, lower into %rcx, from rooted slots
    test $Mask, -2(%rcx)        ; Mask = 4 (FREE), or 6 (FREE|READONLY) for a write
    jnz  <the fail label of k(Hi−Lo, Write, Align)>
    <Access, as after a check>

`-2(%rcx)` is the low flags byte of aux, the byte `write_check//2`
already tests. This is FilPizlonator's own `NotFree`/`CanWrite`
renewal (FilPizlonator.cpp 4048–4086). The renewal needs no null test,
because the capability is non-null and unchanged, and no bounds or
alignment test, because those are invariant. On failure it calls
`filc_optimized_access_check_fail` with `%rax:%rcx` = P and the
deleted check's origin. That function derives its message from the
object's state: null, then FREE, then bounds, then read-only
(4431–4467), so a freed object prints "free object" and a live
read-only one "read-only", as the full check would.

Bookkeeping (*review*): `single_proofs/3` maps a renew's Q to P1 as it
maps a check's, so a later reuse of Q reloads P1; the emitter refuses a
renew whose Q1 or P1 has two definitions; `inst_check_kind/2` gets a
`fused(renew(...), _)` clause so its fail label is emitted;
`live_inst` reads P1 at the renew, so P1 stays live and rooted across
the calls in between. `--registers=temps` homes only `w` and `l`
scalars, so P1's address and lower are in rooted frame slots there.

Pointer consumers may follow a renew: it leaves `%rax:%rcx` as a check
does, and a pointer store is then check-equivalent, ensure-aux, store,
as in the reference.

### The pass

For each heap check that rounds 1–3 keep, the pass (`check_reuse.pl`)
replaces it with `renew` when an earlier heap check of a pointer
related at distance 0, in the same block or in a dominating block,
subsumes its bounds and alignment, Q1 and P1 have a single definition,
and the function has no setjmp. Its `avail` fact after the access is
keyed by P1. `renew_refines/2` accepts exactly that rewrite: the same
position, the same range and rights, and Q1 a single-definition heap
check of a pointer related at distance 0. The pass is opt-in, as
`--checks=renew` (`NANOFIL_CHECKS=renew`), which runs rounds 1–3 first.

### Observation contract, and the back-edge poll

Every remaining full check stays where it was, and each renew stands at
the index of the check it replaces, with the same origin and pointer.
In every object state, the renew traps exactly when that check would,
and for the same reason. A free, by a call, by a signal handler run at
a poll, or by another thread before the access in happens-before order,
makes both trap, with "free object". A read-only object makes both trap
on a write. Otherwise both succeed, because the bounds and alignment
have not changed. Block counts are unchanged. A free by another thread
that races with the renew may lose its trap, as with every check and
its access today; `free_impl` writes upper before it sets FREE, so in
that unsynchronized window a renew can pass where a full check would
fail (*review*). That is the same tolerated race.

A **back-edge poll** kills temporal facts and no spatial ones. The
handler it may run can free the object, which the next iteration's
renew observes. It cannot move the bounds. So in a loop over a
loop-invariant pointer whose check runs before the loop, each
iteration's first access of an object is a renew, and later accesses in
that iteration reuse its proof under rounds 1–3. Spatial facts first
established inside the loop do not reach the header, because the
preheader edge does not carry them. Reaching them needs p or q's
peeling, which is not part of this slice.

### Tests and plants (planned; as built, see Implementation)

- **Validator rejects:** a renew whose Q1 is defined twice, or whose P1
  is defined twice (also through a phi); a renew in a setjmp function;
  a renew covering more than Q1's range or at a weaker alignment; Size

  a renew not followed by its access.
- **Interpreter:** a free between the check and the renew (on another
  path, after a call, and in a loop) traps `out_of_bounds` like the
  reference. A write renew of a read-only object traps `readonly`. A
  renew forged without a span, and one at a stricter alignment than
  Q1's, show `unchecked(span)`.
- **Native:** `reuse.ir` cases for free-then-renew in a loop, a
  read-then-write `p->x++` (rights upgrade), Q1 in an irreducible loop,
  and a renew fused with a pointer store across ensure-aux. `reuse-gc`

  `FUGC_SCRIBBLE`/`FUGC_VERIFY`. The message text and origin must
  match the reference on the free and read-only traps, compared as

- **Plants:** ignore Q1's definition count; ignore P1's phi

### Implementation (round 4)

`--checks=renew` (`NANOFIL_CHECKS=renew`) runs rounds 1–3, then
`renew_checks/2`, then `renew_refines/2` against round 3's output, then
`valid_module/1`. It was opt-in when it landed (the snapshot gate
reported every output identical to `7ebcae8`) and is now the `-O`
default (below).

- `ir.pl`: the `renew` row, `kind_arity`, its class `[a]`, and
  `evidence_preserving`. `renew_sources/3` keeps, per function, the
  heap checks whose proof and pointer have one definition each, and
  none when the function has a setjmp. The checked-stage clause
  requires coverage, Size > 0 and the next instruction's covered
  access, then adds `live(Q, P1, …)`.
- `interp.pl`: `renew` runs `access_res/7` on Q1's value; a failure is
  `out_of_bounds` for a freed object, `readonly` for a write to `ro(_)`,
  and `unchecked(span)` otherwise.
- `filc_amd64.pl`: `single_proofs/3` maps a renew's Q to P1 (only when
  Q1's check is itself single), `renewed_inst/8` refuses anything else,
  a cas or an offset, and `inst(fused(renew(…), _))` emits the flight
  load of P1, `testb $4` or `$6, -2(%rcx)` and `jnz` to the check's fail
  label, then the access. `inst_check_kind/2` knows the renew.
- `check_reuse.pl`: for each remaining heap check followed by a scalar
  or ordinary pointer access, the pass takes the shallowest dominating
  source of the same root at distance 0 that covers it. Subsumption and
  dominance are transitive, so that source is never itself renewed.

The validator and pass previously rescanned every fact at every
definition, which was quadratic. Evidence is now indexed by the names it
mentions (`ir.pl` `ev/3`, `check_reuse.pl` `st/3`), and a definition
kills only the facts indexed under its name. Reuse-mode output on 560
corpus files, with and without `-O`, is byte-identical to `7ebcae8`'s.

**Reverted on time.** Defaults are judged on time, not instructions. On
a quiet swa (Zen 4), the gate's geomean was 2.00 with renewal against
1.98 with reference checks, and bzip2 `-d` ran 24% slower (2.83 against

resyncs went from 0.03M to 7.1M. These are memory-dependence
mispredictions in the frame-to-frame phi copy blocks, and they vanish
with speculative store bypass disabled. Renewal keeps P1 live, which grew
the frame from 1296 to 1712 bytes and changed those copies; the flag
test itself accounts for about a third of the cost (perf.md). So `-O`
selects `--checks=reference` again, and `--checks=renew` stays
selectable. Renewal can come back once no gate workload is slower with
it.

To find the sites that cause the resyncs, `NANOFIL_RENEW_SITES=Fn:From-To`
keeps only function Fn's renewals numbered From to To − 1, in the
pass's block order, and leaves every other check in place (`Fn` alone
keeps all of Fn's). Any subset of renewals is valid checked IR, so the
selector needs no rule of its own; it is for bisecting, not a mode.

validator's lower bound and offset alignment, a wrong-distance
rewiring, and the pass's pointer index. It also asked for the trap
comparison to cover the whole stderr. A renew's in-block proof now maps
through Q1, so a twice-defined renew result is no longer refused. Not
covered then, both since covered (next section): Q1 in an irreducible
loop, and a renew fused with a pointer store under GC stress.

## Range guards (round 5): contract, reviewed

Round 4 renews a check only when an earlier full check of the same
pointer dominates it. Inside a loop, the check of `a[i]`, or of a field
of a state pointer that nothing checked before the loop, still runs in
full on every iteration. This round tests, once and without trapping,
whether the object covers every byte the loop's accesses through one
pointer can reach. Each access then runs as a renewal when that test
passed, and as its unchanged full check when it did not. No check
moves, and nothing traps earlier.

### Measured first

Method (scratch, not kept): the gate's programs built with the `-O`
default at `a4351bc` (renewal on), a symbol at every block label,
callgrind's per-block counts, joined to a classification of every full
check left after renewal. Every class below needs a loop-invariant
root pointer, meaning a single definition outside the check's innermost
natural loop.

- **inv:** constant offset from the root, with no dominating check
  before the loop (such as `s->lookahead` in `deflate_slow`).
- **narrow:** the offset is a zero- or sign-extended byte or short,
  scaled and shifted by constants (`ftab[c]`).
- **mask c, mask v:** the offset is bounded by `and` or `urem` with a
  constant (c) or with an invariant name (v, such as zlib's `& wmask`).
- **iv:** the offset is affine in a basic induction variable, with a
  dominating exit test against an invariant (`ptr[i]` in `mainQSort3`).

Executed full checks, millions, after renewal:

| zlib `-6` | 166 | 75 | 47.8 | 1.9 | 0 | 49.7 | 0.1 | 24.2 | 24.3 |
| zlib `-d` | 17 | 0.2 | 0.2 | 0 | 0 | 0.2 | 0 | 0 | 0 |

What is not guardable:
- Offsets loaded in the loop (`block[ptr[i]]`).
- Roots loaded in the loop (`s->window` reloaded after a store), which a
  middle-end load hoist would make invariant.
- Pointer phis (`p++`, Lua's `pc`).
- Induction variables without a bound test (`while (a[i])`).
- Checks outside any loop.

Bounded induction (the `block[i]` case) is 33M of bzip2 `-9`'s 286M and
nothing in zlib. So the guard is the mechanism, in two slices:

1. **Slice A, constant spans:** inv, narrow and constant masks. The
   guard's span is constants relative to the root, and no names or
   induction rule are needed. It covers about 150M of the 220M
   guardable.
2. **Slice B, symbolic spans:** linear forms over invariant names, for
   iv and for symbolic masks (`ext(uw)(and(x, m))` lies in [0, V] when
   V is `ext(uw)(m)`, a guard argument). Contracted below and
   implemented after slice A is measured.

Expected cost:
- A full read check is 8 instructions after its flight load (null,
  lower and upper tests), and a write check adds the flag test.
- The guarded renewal's fast path is 4: a test of G, a branch to an
  out-of-line full check, the flag test and its branch.
- So a passing guard saves about 4 instructions per read and 6 per
  write. For slice A that is roughly 3% of zlib `-6`, 2.5% of bzip2 `-9`,
  2% of bzip2 `-d` and 2% of lz4 `-9`, if every guard passes.
- Versioning the loop (a copy whose accesses are plain renews) would
  save about twice that. It can be accepted just as locally (see
  Review), and is left for later.

### The fact

`span(G, P0, Lo, Hi)`: if G = 1, then when G's span test ran, P0's
capability was non-null and its object's bounds contained every address
in [addr(P0) + Lo, addr(P0) + Hi), computed modulo 2⁶⁴. By round 4's
lifetime lemma, an object's bounds change only when it is freed, which
empties them and sets FREE. So the fact holds for the same object until
it is freed, and every access that uses it still tests FREE and
READONLY itself.

### The terms

Two new ops, a grammar change that needs separate approval:

| Op | Class | Args | Meaning |
| --- | --- | --- | --- |
| `span_test(Lo, Hi)` | `w` | `[P0, V1, …, Vn]` | 1 when P0's capability is an object's (not null, a function, an external or none), and its bounds contain [addr(P0)+Lo, addr(P0)+Hi) with Lo < Hi; otherwise 0. Never traps, reaches no safepoint, reads no flags. In slice A, Lo and Hi are integers and there are no Vs. In slice B, they are `lin(C, [K1, …, Kn])`: C + ΣKi·Vi over the l-class Vs. |
| `renew_if(Lo, Hi, Rights, Align)` | `a` | `[P, G]` | checked stage: exactly `check(Lo, Hi, Rights, Align)` of P. When G = 1, only its temporal part (FREE, plus READONLY for a write) and its alignment are tested. |

Like `check`, `renew_if` is followed immediately by its first access,
which reads its result at offset 0. Both ops are on
`evidence_preserving/1`. After its access, `renew_if` adds
`live(Q, P, Lo, Hi, Rights, Align)`, so rounds 1–3 can reuse Q. The
emitter's `single_proofs` and `fused_insts` map Q to P, as they do for
a check. Without this, a guard at the end of `idom(H)` would end the
round-2 facts that enter H over the plain preheader edge.

### Acceptance (validator, independent of the pass)

`let(tmp(Q), a, renew_if(Lo, Hi, Rights, Align), [P, tmp(G)])` is
accepted iff all of these hold:

1. G has one definition, a `span_test(GLo, GHi)` of `[P0 | Vs]`, and
   strict SSA makes it dominate the access.
2. Every name the derivation passes through has exactly one definition
   by `temp_defs/3`: P0, each V, the flights from P0 to P, every offset
   temp, and in slice B the induction variable, its increments and the
   exit test's condition. `definitions_dominate` alone accepts a name
   defined twice when one definition dominates the use. Reading "the"
   definition of such a name would be unsound.
3. The function has no setjmp.
4. P is P0 plus an offset, through flights `add` and `sub` whose lower
   donors chain to P0 (round 3's relation, with non-constant offsets).
   A `sub` flight negates its term's interval. The offset's interval is
   [OLo, OHi], by the rules below. Each end is compared separately:
   GLo ≤ OLo + Lo and OHi + Hi ≤ GHi. In slice B the coefficient vectors
   must be equal and the constants are then compared.
5. The next instruction is an access it covers, with heap effects, as
   for `check`.

**Interval rules.** An interval bounds the *signed* value of a temp in
its own width. A constant is first reduced to signed in that width (the
IR stores w values unsigned). A rule rejects when its conditions fail.

- `const(c)`: [c, c], c taken signed in its width.
- `ext(ub)`, `ext(uh)` of anything, and `raw_load(ub/uh)`: [0, 255] and
  [0, 65535]. For `sb` and `sh`: [−128, 127] and [−32768, 32767].
- `and` with `const(m)`, 0 ≤ m < 2^(width−1): [0, m]. `urem` by
  `const(m)`, 0 < m ≤ 2^(width−1): [0, m−1].
- `ext(sw)` of a w interval: the same interval. `ext(uw)` only of an
  interval within [0, 2³¹).
- `shl` by `const(k)`, 0 ≤ k < width, and `mul` by `const(c)`: scale
  both ends, swapping them for c < 0. `add` of two intervals, and `sub`
  of a constant, add the ends.
- **In class w**, every end of a result must lie in [−2³¹, 2³¹) for
  every value its names can take: a guard V that is `ext(sw)` of a w
  name ranges over [−2³¹, 2³¹), any other over the full 64-bit range.
  This rules out `a[i + k]` with a w add that wraps. **In class l** no
  fit condition is needed. The program's value is congruent modulo 2⁶⁴
  to the exact form, and the guard bounds the exact form with overflow
  detection (Emission).
- **Slice B, names:** a guard V, or a w name x such that some V is
  `ext(sw)` of x: [V, V].
- **Slice B, basic induction variable** i. i is a phi in block H. Each
  of its operands from a reachable predecessor is either Init, the same
  name everywhere (a V, x as above, or a constant), or a single-
  definition `add(i, const(1))` of i's class, whose definition is
  dominated by T. Some block E ends in `branch(tmp(c), T, F)`, read from
  the jump term, with `edge_label(F) ≠ T`. Here c has one definition,
  `cmp(slt, K)` of [i, N] with K i's class and N of the same forms as
  Init. T's only reachable predecessor is E, and T dominates the access.
  Then i is in [Init, N − 1] at the access.
  - Why: H dominates the cmp, because the cmp uses i. The cmp's block
    dominates E, and T dominates both the access and every increment.
    So every increment of i followed a passing test i < N ≤ max, and
    cannot wrap. And the latest test before the access saw the current
    i.
  - This needs only dominance and single definitions, so irreducible
    loops, multiple latches and multiple exits change nothing. When
    Init ≥ N, the access never runs.

At the access, G, P0 and every name above hold the values the guard
used, by round 4's dominance argument. Any path from the guard to a
redefinition and on to the access would yield a path from entry to the
access that avoids the guard.

### Interpreter

`span_test` is 0 for a `none`, `fn(_)` or `ext(_)` capability, and
otherwise compares the object's current bounds with the span computed
over unbounded integers, modulo 2⁶⁴ as native code computes addresses.
`renew_if` with G = 0 is `check`. With G = 1 it runs the full
`access_res/7`:
- a freed object traps `out_of_bounds`;
- a write to `ro(_)` traps `readonly`;
- a misaligned address traps `misaligned`, as the check would, because
  the fast path tests alignment itself;
- any other failure is `unchecked(span)`, meaning the guard or the
  interval rules were wrong.

### Emission

`span_test`:
- P0's flight load into `%rax:%rcx`; G = 0 if `%rcx` is null.
- GLo and GHi as signed 64-bit values, with `imul` and `add` overflow
  (`jo`) sending G to 0. In slice A they are immediates.
- L = `%rax` + GLo and H = `%rax` + GHi, modulo 2⁶⁴.
- G = 1 iff lower ≤ L < H ≤ upper (`-16(%rcx)`), compared unsigned.

This reads only what a full check reads. Special objects and the free
singleton have upper = lower, so their guard fails.

`renew_if`:

    flight load of P                       ; once, for both paths
    cmpl $0, G ; je .Lfull_<blk>_<i>
    testb $Mask, -2(%rcx) ; jnz <fail k(Size, Write, Align)>
    [alignment test as in access_check//2, when Align > 1]
    .Laccess_<blk>_<i>: <Access>
    …
    .Lfull_<blk>_<i>:                      ; out of line
    <access_check//2 of P, to the same fail label> ; jmp .Laccess_<blk>_<i>

Both paths fail to the same label, with `%rax:%rcx` = P and the same
origin, so the report is the check's. Labels are per block and index
(`local_label/5`), and `inst_check_kind` knows the op. Liveness reads P
and G, and G is a w temporary, homed across calls.

### The pass

For each natural loop with header H (`natural_loops` skips irreducible
cycles), in a function without setjmp, the pass takes each full check
left after rounds 1–4 that is followed by a scalar or ordinary pointer
access, and whose root P0 and every derivation name meet the rules
above and are defined outside the loop:
- It groups these checks by root, and in slice B by coefficient vector.
- For each group it emits one `span_test` at the end of `idom(H)`, over
  the group's least Lo and greatest Hi. Every name used in the loop and
  defined outside it dominates H, and so the end of `idom(H)`. A branch
  ending `idom(H)` reads its condition after the guard, and the guard
  writes only G.
- Each check in the group becomes a `renew_if` on that guard.

`guard_refines/2` accepts exactly this rewrite: new `span_test` lets at
block ends, and checks replaced in place by `renew_if` with the same
range, rights and alignment. It is selectable as `--checks=guard`
(rounds 1–4, then guards), off by default until measured.

### Observation contract

- The guard never traps, reaches no safepoint, and writes nothing but G.
  A failing or unused guard changes cost, not outcome.
- Every `renew_if` stands at its check's index with the same origin,
  range, rights and alignment. With G = 0 it is that check. With G = 1
  the bounds part is proven, and the fast path tests everything else the
  check tests: FREE, READONLY for a write, and alignment. So it traps
  exactly when the check would, with the same reason.
- Calls and back-edge polls may free the object. FREE is then set, and
  the next access traps "free object" as the reference does.
- A free racing another thread between guard and access may pass
  unnoticed, the same tolerated race as round 4. `free_impl` writes
  upper before it sets FREE. FUGC never writes upper, and P0 keeps the
  object mapped while the guard reads it.

### Tests and plants (planned)

- **Validator rejects:**
  - a span missing either end by one byte;
  - another root, or another lower donor;
  - a guard that does not dominate the access;
  - a twice-defined offset name, V, P0, i, i+1 or c;
  - a latch increment not dominated by T (it skips the test);
  - `branch(c, T, T)`, and an exit taken on the true edge;
  - `ult`, step 2, and Init not among the guard's forms;
  - a w `add` that can wrap (`a[i + k]`);
  - `and` with 0x80000000 in w, `urem` by 3·10⁹ in w, and `shl` by the
    width or more;
  - a symbolic mask in slice A;
  - setjmp.
- **Interpreter:**
  - a forged guard gives `unchecked(span)`;
  - G = 0 behaves exactly as the check;
  - G = 1 traps `out_of_bounds` after a free, `misaligned` on a
    misaligned address, and `readonly` on a write to `ro(_)`.
- **Native** (trap text compared as bytes):
  - guards that pass and fail (one element short);
  - with G = 1: a free inside the loop, a misaligned `int *`, a write to
    a const table;
  - guards on `malloc(0)`, a freed object and a special object;
  - zero-trip loops, and Init > N;
  - byte-indexed tables of 256 and 255 entries;
  - an `idom(H)` ending in a branch, and an H with two entries;
  - G kept across calls under `--registers=temps`;
  - two `renew_if`s in one block, and reuse of a `renew_if`'s Q;
  - GC stress with renewed pointer stores.
- **Plants:**
  - the guard drops `jo`, or compares upper signed, or `H < upper`;
  - the slow path skips the flight load or the alignment test;
  - the fast path skips FREE;
  - liveness drops G;
  - `span_test` is missing from `evidence_preserving`;
  - a `sub` flight is not negated;
  - the narrow rule treats `sb` as unsigned;
  - the IV rule ignores where the increment is dominated, or takes
    predecessors from the CFG's ordsets;
  - the interpreter maps misaligned to `unchecked`;
  - `guard_refines` accepts a moved check.
- **Gate:** snapshot identical; the Nix checks with a guard variant;
  instructions before and after on bench/run.py; compile time on
  sqlite3.c.

### Review

Oracle reviewed this contract before any implementation. It found
three blockers in the first draft, all now fixed in the text above:
- the IV rule let a latch increment that never passed the exit test
  wrap i (now: every increment is dominated by T);
- it read definitions of names that may have several, and took the exit
  edge from the CFG's ordsets, where `branch(c, T, T)` looks like a
  single edge (now: single definitions throughout, and the edge is read
  from the jump term);
- it stated its fit conditions for 64 bits while w adds wrap at 32 and
  w constants are stored unsigned (now: signed intervals per width, and
  an exact, overflow-checked guard, which makes l-class arithmetic need
  no fit condition).

Its should-fix items are folded in: misalignment keeps its trap under
G = 1, odd capabilities give 0, both ops preserve evidence, the flight
load is shared with an out-of-line slow path, and the arithmetic is
stated exactly. It also proposed the cheaper slice A.

It confirmed that the guard's reads are safe against free, special
objects and FUGC. It confirmed the dominance argument and the guard's
placement at the end of `idom(H)`, including several entries and a
branch there.

For later: versioning can be accepted just as locally. In the copy, an
access may be a plain renew when it is dominated by a block T whose
only predecessor E ends in `branch(G, T, F)` with F ≠ T.
`guard_refines` would then also check that the copy is a label-renamed
duplicate.

Not verified: vfork, `dlclose` and thread-exit header paths (as in round
4), and how often guards pass at run time.

### Survey: guards, hoisting, versioning, peeling, cheap wins

Before choosing new ops, every full check that the `-O` default
(renewal on) leaves was counted once on the gate. The method is the one
described under "Measured first". The extra rules are these:

- **Hoist:** the root is a pointer loaded in the loop, from an address
  whose root is invariant. The loop has no call and no pointer store,
  and the load executes on every iteration before any exit (or after a
  side-effect-free header test, with loop rotation). Otherwise the
  hoisted load's check would move.
- **Peel:** a constant-offset check of an invariant root whose block
  dominates every latch. Peeling one iteration lets the loop's copy renew
  it with today's ops. Counted net of loop entries.
- **Distance > 0:** a dominating check of the same root at another
  constant offset whose span covers this one.
- **Fields:** a dominating check of the same root that does not cover
  this one.

Executed full checks removable (millions), and the instructions saved
as a share of the run. A guarded access saves 4 (read) or 6 (write)
instructions. A versioned or peeled access, which becomes a plain
renew, saves 6 or 8.

| Workload | full | guard A | guard B adds | hoist | peel | dist > 0 | fields | guard A+B instr | versioning A+B instr | peel instr |
| --- | --: | --: | --: | --: | --: | --: | --: | --: | --: | --: |
| zlib `-6` | 166 | 49.7 | 24.3 | 0 | 0.7 | 0 | 57.5 (47.3 in A/B) | 4.4% | 6.5% | 0.1% |
| bzip2 `-9` | 286 | 49.9 | 33.0 | 0 | 22.5 | 0 | 34.4 (34.0) | 3.6% | 5.3% | 1.4% |
| bzip2 `-d` | 83 | 18.0 | 7.8 | 3.9* | 7.1 | 0 | 22.1 (13.1) | 2.9% | 4.3% | 1.1% |
| lz4 `-9` | 138 | 37.1 | 15.4 | 0 | 0 | 0 | 5.2 | 3.0% | 4.4% | 0 |
| Lua int | 62 | 14.0 | 0 | 0 | 0 | 0 | 28.0 (6.0) | 2.7% | 3.9% | 0 |
| Lua tab, str | 54–74 | 2–4 | 0–1 | 0–0.1 | 0–1.1 | 0 | 24–26 | 0.5% | 0.7% | 0–0.2% |

\* Only with type-based aliasing (scalar stores in the loop) and loop
rotation.

- **Hoisting removes almost nothing under the trap rule.** The large
  "root loaded in the loop" sites either sit in loops with calls or
  pointer stores (bzip2's `copy_input_until_stop`, `handle_compress`),
  or their load is conditional inside the loop (zlib's `deflate_slow`
  `L342`, the hash insert behind `if`). Hoisting such a load would run
  its check on paths that never ran it.
- **Distance > 0 renewal finds nothing.** Pizlonated checks start at
  offset 0, so a dominating check of another field never covers this
  one.
- **Write evidence covering a later read is already used**, and what
  remains of distance-0 coverage is 0.2–2.3M.
- **Fields of an already-checked struct are mostly in the guard
  classes.** Covering them is span_test's job, not a cheaper rule.
- **Peeling** uses today's ops and validator only (a middle-end loop
  copy), and reaches 1.1–1.4% on bzip2 and nothing elsewhere.

Instruction counts are only a proxy here. On swa, renewal is 10% fewer
instructions but 24% slower on bzip2 `-d` (perf.md, `BZ2_decompress`'s
layout), while on this orb it is 4% faster than reference checks on the
same workload.

## Limits

- No motion. Rounds 1–3 carry no evidence around a loop, because every
  back edge polls and a poll kills every fact. Round 4 keeps only
  bounds and alignment across polls and calls, and still tests the
  flags at every access that a full check guarded; spatial facts first
  established inside a loop do not reach its header.
- Across an edge, only proofs and pointers with a single definition.
- Rounds 1–3 reuse for scalar consumers only; pointer accesses keep
  their check, or (round 4) its renewal.
- Same SSA pointer, or (round 3) a constant-offset flight from the
  same root with the same lower donor: a variable index (`a[i]`,
  `a[i+1]`) or a pointer reloaded from memory is not related.
- Read evidence never covers a write under rounds 1–3; a round-4
  renew of a write tests the read-only flag itself.
- Local (`check_local`) and function proofs are not reused.
- Polls, `alloc` and helper exits are trusted to the invalidator list
  and native tests; the interpreter models only explicit free.
- Renewal needs distance 0, single-definition Q1 and P1, and no
  setjmp in the function; a variable index (`block[i]`) in a loop is
  not covered (the "index" column above), which is the next contract.
